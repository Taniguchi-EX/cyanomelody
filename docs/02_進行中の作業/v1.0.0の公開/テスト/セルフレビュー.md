# セルフレビュー

## 仕様との突き合わせ
- 作業概要の範囲（README・LICENSE、NSIS のインストーラ、自動アップデートと3つの選択肢のダイアログ、GitHub Actions）をすべて用意した。
- アップデートのダイアログは、途中で頼まれた文言（「新たなバージョンが公開されました。アプリをアップデートしますか？」、はい／いいえ／このバージョンをスキップ）にした。OS のダイアログでは3つのボタンを自由に出せないので、アプリの中のダイアログにした。

## 見つけて直した問題
- リポジトリの一番上に .gitignore がなく、`.sec` を含むファイルが Git に入るおそれがあった。`*.sec*` を加えた。署名の秘密鍵は、念のためリポジトリの外に置いた。
- README のスクリーンショットで、右の欄のファイルのパスに Windows のユーザー名が出ていた。見本のデータをユーザーのフォルダの外（`E:\tmp\見本`）に置いて撮り直した。
- GitHub Actions のビルドで、package.json に `tauri` のスクリプトがないため、tauri-action が CLI を見つけられないおそれがあった。`tauriScript: npx tauri` を指定した。
- package.json の版を変えたので、package-lock.json の版もそろえた（`npm ci` が食い違いで失敗しないように）。
- Cargo.toml の license が空だったので、MIT にした。

## 不具合の確認
- 開発用のビルド（画面テスト）では新しい版を探さないので、テストにダイアログが出ない。
- オフラインや、まだ Release がないとき（latest.json がない）は、何も出さない。
- スキップした版と同じ版なら出さず、違う版なら出す。
- 「はい」の後に失敗したら、ダイアログを閉じてエラーを出す（再起動しない）。

## 確かめられていないこと
- アップデートのダイアログと、実際の更新の流れ（ダウンロード・インストール・再起動）は、新しい版（v1.0.1 以降）を公開するまで試せない。次の版を出すときに確かめる。
