# Linux対応

状態：作業概要（仮判断で作成）。実装は、開発する PC の WSL に Linux 向けのビルドに要るものを入れることの確認をユーザーに取ってから始める。

ユーザーの離席中に、全体ロードマップの「Linux対応」を、仮判断で作業概要にしたもの。

## 目的
Linux（友人の PC など）でも cyanomelody を使えるようにする。

## 範囲（仮判断）
- 対象：Ubuntu 22.04 以降（x86_64）。配布は AppImage と .deb（Tauri の bundler）。GitHub Actions の release で、Windows と一緒に作る。
- 自動アップデート：Linux でも Tauri の updater で行う（AppImage）。.deb は自動では更新しない（README に書く）。
- 機能の違いを埋める所（コードで調べたもの）
  - ごみ箱への移動（ファイルの削除）：今使っている `trash` クレートは Linux（freedesktop のごみ箱）にも対応している。ネットワークのフォルダなど、移せないときの扱いは今と同じ。
  - エクスプローラーで見せる（`revealItemInDir`）：Tauri の opener プラグインは Linux ではファイルマネージャを開く。選んだ状態にできない環境では、フォルダを開くだけになる。
  - パスの区切り：相対パスは `/` で持っているので、そのまま。大文字・小文字を区別するファイルシステムでも、スキャンの対象の拡張子は今どおり区別しない。
  - データの置き場所：`~/.local/share/dev.cyanomelody.app`（Tauri の app_data_dir）。
  - 画面：WebKitGTK で表示する。フォントは Noto Sans CJK を優先し、なければ OS の既定。
- 開発：開発する PC の WSL（Ubuntu）で、Linux 向けのビルドと単体テスト（cargo test）を流す。画面テスト（WebView2 にリモートデバッグでつなぐ Playwright）は Linux では使えないので、Linux では流さない（主な動きを手で確かめ、確かめたことを記録する）。

## やらないこと
- ARM 版、Flatpak・Snap での配布。
- Linux での画面テストの自動化。
