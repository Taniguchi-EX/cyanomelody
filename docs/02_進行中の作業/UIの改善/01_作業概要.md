# UIの改善

## 目的

実際の使い方（ユースケース）に沿って画面を見直し、分かりやすく、少ない操作で使えるようにする。
ユーザーの指示により、10周行う。

## 方針

- 文章で説明したり、専用のボタンを足したりするのは極力避ける。最小限のグラフィカルな要素（記号、色、配置、表示・非表示）で意図が伝わるようにする。
- 今の絞り込みとファイルの選択（チェック、右の欄の表示）を、一括で解除できるボタンを用意する。

## 進め方（1周ごと）

1. ユースケースを1つ想定する。
2. そのユースケースで必要な操作を列挙する。
3. 今の画面を、次の観点でレビューする。
   - 分かりにくい部分、自明な表示、無駄な説明がないか
   - 操作の回数を減らせないか
   - 要素の配置場所や表示の条件は正しいか
4. 見つかった問題を直す。
5. 単体テストとすべての画面テストを実行する（画面の変更で必要ならテストを直す）。
6. 各周の内容を`02_ロードマップ.md`に記録し、コミットする。

## 想定するユースケース（指示の例と、それに加えるもの）

1. TRPGのシナリオに使う効果音を吟味しつつプレイリストとしてまとめる（別名、シナリオに特化したエフェクト、シーンごとのプレイリストをフォルダのように使う）
2. 音楽再生アプリとして使う（「任天堂曲」のようなタグの組み合わせのプレイリスト、ランダムセレクトで毎回違う曲）
3. 一般公開するコンテンツ用に、ライセンスの緩い効果音を探す
4. シナリオごとのプレイリストを見て、過去にどのファイルをどう使ったか振り返る
5. 新しく入手した素材集を取り込み、タグ・出典・ライセンスを付けて整理する
6. 重複したファイルや、移動して見つからなくなったファイルを片付ける
7. 素材集の中から、似た音を聞き比べて選ぶ（試聴を続けて行う）
8. 大量のファイル（数万件）の中から、条件を重ねて目的の音を探す
9. エフェクトを調整しながら、狙った音を作って書き出す
10. 友人にプレイリストを書き出して渡す

## やらないこと

- 新しい機能の追加（ユースケースの操作に必要な小さな変更は除く）
- データベースの構造の変更

## 仮決定した事項

- ユーザーの指示（進め方と観点が示されている）に従い、作業概要とロードマップのレビューは待たずに進める。
- 一括解除のボタンは、ツールバーの「絞り込みを解除」を置き換える形にする（解除する対象を、絞り込み・チェック・右の欄の表示に広げる）。1周目で扱う。
