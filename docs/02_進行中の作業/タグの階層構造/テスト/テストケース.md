# テストケース

## 単体テスト（Rust）

`tags.rs`
- 階層の順（親の次にその子孫）と深さ。件数は子孫を含み、同じファイルは1回だけ数える
- 移動：前・後ろ・子の最後・最上位の最後。子孫も一緒に移る
- 自分自身や子孫の中への移動、存在しないタグの移動・存在しないタグへの移動はエラーで、並びは変わらない
- 新しいタグは最上位の最後に入る（既存のテストの並びの想定も、作った順に直した）
- 削除で子がその位置に繰り上がる
- 統合で統合元の子が統合先の子の最後に移る。子孫のタグへの統合はエラー
- 使われていないタグの一括削除は、子孫にファイルが付いたタグを残す

`files.rs`
- ファイルに付いたタグは、タグの一覧の順に並ぶ（並べ替えると変わる）
- 親のタグで絞り込むと子孫のタグのファイルも出る。親と別のタグの組み合わせはAND

`db.rs`
- migration 4で、既存のタグが最上位に名前の順（大文字・小文字を区別しない）で並ぶ

## 画面テスト（Playwright、`app/e2e/tag-tree.mjs`）

- G01：準備。作ったタグは作った順に並ぶ
- G02：取っ手で行の真ん中に落とすと、その子の最後に入る
- G03：ドラッグ中は落とす位置が表示される（前は上の線、後ろは下の線、子は枠）。一覧の外で離すと何も起きない
- G04：上の端に落とすと前、下の端に落とすと後ろ（同じ親の兄弟）に入る
- G05：自分自身や子孫の中には落とせない（表示が出ず、離しても変わらない。移すタグと子孫は薄く表示される）。「（タグなし）」の行にも落とせない
- G06：件数は子孫を含み、親のタグで絞り込むと子孫のタグのファイルも出る。親と子を選ぶとAND
- G07：取っ手を押しただけでは絞り込まない
- G08：一覧の下の空いた所に落とすと、最上位の最後に入る（子孫も一緒に移る）
- G09：たたむと子が隠れ、再読み込み後もたたんだまま。たたんだタグに落とすと、たたんだまま子に入る
- G10：ファイルに付いたタグは、タグの一覧の順に並び、並べ替えると変わる
- G11：管理画面も同じ順番と階層で表示する
- G12：子孫のタグへの統合はできない
- G13：子のあるタグを削除すると、子はその位置に繰り上がる。確認のメッセージにそのことが書いてある
- G14：確認ダイアログで「キャンセル」を選ぶと削除しない
