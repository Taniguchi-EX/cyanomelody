# セルフレビュー

テストの前に、実装を作業概要と突き合わせ、コードを見直した。

## 作業概要との突き合わせ

作業概要の仕様の項目ごとに確かめ、すべて実装されていた。
- 親子関係と兄弟の中での順番。新しいタグは最上位の最後。既存のタグは最上位に名前の順
- 左の欄の取っ手（右端）でのドラッグアンドドロップ。名前の部分のクリックは絞り込み
- 落とす位置（上の端は前、下の端は後ろ、真ん中は子の最後）と、その表示（線・枠）
- 自分自身や子孫の中には落とせない（表示を出さず、落としても何もしない）。「（タグなし）」の行にも落とせない
- 子孫も一緒に移る。一覧の下の空いた所に落とすと最上位の最後
- たたんでいるタグの真ん中に落とすと、たたんだまま子の最後に入る
- 並べ替えても絞り込みの条件は変わらない
- 左の欄と管理画面の階層表示、開く・たたむの印、開閉の状態の記憶（最初はすべて開いている）
- 件数は子孫を含めた数。絞り込みは子孫を含める（複数のタグはAND）
- ファイルに付いたタグは、一覧の各行・右の欄とも、タグの一覧の順に並ぶ
- 名前変更で位置は変わらない。統合で統合元の子は統合先の子の最後へ。統合先が統合元の子孫ならエラー
- 削除で子は繰り上がる。確認のメッセージにも書く
- 使われていないタグの一括削除は、子孫にもファイルが付いていないタグだけ

## 見つけて直した問題

1. 子のないタグの行で、字下げの左にある開閉の印の場所（空白）を押しても、絞り込みにならなかった。
   - 子のないタグでは、その場所のクリックを行のクリック（絞り込み）として扱うようにした。
2. タグの削除の確認で「付いているファイル N件」と出していたが、件数が子孫の分を含むようになったため、そのタグ自身の件数と食い違う。
   - 件数は出さず、「付いているファイルから外れます」とした。

## 実装中に直した点（画面の確認で見つけたもの）

- 取っ手の記号（⋮⋮）が詰まって小さく見えた。「≡」に変えた（作業概要の記述も直した）。

## 確かめて問題がなかった点

- ドラッグはpointerイベントで自作した（試作結果を参照）。取っ手でつかんでから4px動かすまではドラッグにしないので、取っ手を押しただけでは何も起きない。
- 処理中（busy）は取っ手をつかめない。
- 移動の処理（Rust）でも、自分自身や子孫の中への移動はエラーにしている（画面で防いだうえで、二重に確かめる）。
- データの変更（migration 4）は列の追加と順番の設定だけで、既存のタグとファイルの対応は変えない（単体テストで確認）。
- 階層の順に並べる処理は、親子が輪になったデータ（本来は起きない）でも止まらずに、最上位として出す。
- たたんだ状態の記憶には、削除したタグのidが残ることがあるが、表示には影響しない。

## テストで見つけて直した問題
