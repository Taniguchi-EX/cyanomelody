# 録音した音（段階4の検討）

状態：案（ユーザーの確認待ち）。

その場で作る単発の音は、種類が限られ、音も物足りない（段階3）。そこで、単発の音のボタンに、利用者が録音した音を割り当てられるようにする（ユーザーの指示）。

## REC ボタン
- ライブの画面に REC ボタンを置く。押すたびに、REC モードの入と切が替わる（入のときは、ボタンを押し込まれた見た目にし、赤くする）。
- 置く場所：左下の BPM のボタンの左隣（BPM のボタンを少し狭くする）。
- REC モードの間は、録る音を「曲」と「マイク」から選ぶ切り替えを出す（REC ボタンの近く。選んだ方は覚えておく）。

## 録る
- REC モードの間、単発の音のボタンを押している間だけ録音する。離すと、録った音をそのボタンに割り当てる（前の音は置き換わる）。
- 録るときの BPM（BPM のボタンの今の値）も一緒に覚える。
- 録っている間は、ボタンを赤く光らせ、録った長さ（「1.2秒」）を出す。
- 長さは最大8秒。8秒を超えたら、そこで録るのを止める（指を離していなくても）。
- 録る音
  - 曲：今聞こえている曲の音（ライブのエフェクトをかけていれば、かけた後の音）。単発の音は入れない。
  - マイク：端末のマイクの音。初めて使うときに、端末がマイクの許可を求める。許可しなければ、マイクは選べないと出す。
    - スピーカーで曲を鳴らしていると、マイクに曲の音も入る（イヤホンを使えば入らない）。
- REC モードの間に押しても、録った音や今の音は鳴らさない（録るだけ）。
- 録った音は、アプリを閉じても残す（アプリのデータのフォルダに保存する）。

## 鳴らす（REC モードでないとき）
- 録った音があるボタンは、触れた瞬間に録った音を頭から鳴らし、離しても最後まで鳴らす。
- 同じボタンを続けて押すと、前に鳴らしていた音を止めて（ごく短く小さくして）、頭から鳴らし直す。別のボタンの音とは重ねて鳴らせる。
- 速さは、今の BPM に合わせる：録ったときの BPM と今の BPM の比で、速さを変える（音の高さは変えない）。
  - 例：BPM 120 で録った音を、BPM 150 で鳴らすと、1.25倍の速さ（短く）になる。
  - 比は 0.5〜2倍までにする（それを超えると、音がひどく崩れるため。超えたら 0.5 か 2 倍で鳴らす）。
- 録った音がないボタンは、今の音（その場で作る Kick・Snare など）を鳴らす。
- 押したままの連打（段階3のロール）はやめる（録った音・今の音とも、押した瞬間に1回だけ鳴らす）。
- ボタンの名前：録った音があれば、名前の下に「REC」と小さく出す（どれが録った音か分かるように）。

## 消す
- REC モードの間、録った音があるボタンの隅に「✕」を出す。押すと、録った音を消して、今の音に戻す（確かめは出さない。すぐ録り直せるため）。

## 仕組み（メモ）
- 曲の音は、ライブの出口（エフェクトの後）から AudioWorklet で取り出して覚える。マイクは getUserMedia で取る。
  - マイクは、Android のアプリにマイクの権限（RECORD_AUDIO）を加え、WebView の許可の求め（onPermissionRequest）に応える必要がある。Tauri（wry）が応えるかを、最初にエミュレータで確かめる。だめなら、ユーザーに相談する。
- 録った音は、WAV にしてアプリのデータのフォルダに保存する（ボタンごとに1つ。録ったときの BPM も一緒に）。
- 速さだけを変えるのは、鳴らす前に、録った音を短い区切りで重ねてつなぎ直す方法（WSOLA）で作り直す。BPM ごとに作った音を覚えておき、BPM を測り直したら作り直す（押した瞬間に重い計算をしないように）。

## やらないこと
- 録った音の頭と終わりを切りそろえる・編集すること。
- 録った音を、ほかの端末と受け渡すこと・書き出すこと。
- ボタンの数を増やすこと（6個のまま）。

## 決まっていないこと
- 上の案のうち、ユーザーが指示していない所（REC ボタンの置き場所、最大8秒、アプリを閉じても残す、消し方、連打をやめること、速さの比の上限）。
