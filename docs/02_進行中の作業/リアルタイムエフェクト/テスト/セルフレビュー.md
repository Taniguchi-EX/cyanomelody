# セルフレビュー（段階1）

## 見つけて直したこと
- 指を XY パッドに置いたまま、別のエフェクトに切り替えると、新しいエフェクトに指の位置が渡らず、作ったときの値（ローパスなら 350Hz）のまま鳴っていた。最後の指の位置と BPM を覚えておき、切り替えたときに新しいエフェクトを始めるようにした（`liveAudio.ts` の `select`）。
- 画面の部品の中で、描く途中に audio 要素の ref に触れていた（lint の警告）。開いたときの effect の中で、audio 要素を探すようにした。

## 確かめたこと（問題なし）
- Windows の動きは変えていない：曲の URL はアセットのプロトコルのまま（`mediaSrc` は Android だけ `cm-media`）。audio 要素の crossOrigin も Android の画面だけ。
- `cm-media` は、SAF のファイルと `effects-cache` の中のファイルだけを返す（それ以外のパスは 403。単体テストで確かめた）。
- 曲の音を AudioContext に通すのは、ライブの画面を初めて開いたときだけ。開かなければ、普段の再生は今までと同じ道を通る。
- AudioContext に通した後も、アプリの音量のつまみ（audio 要素の volume）は効く（エミュレータで、1 → 0.5 → 0.1 で出口の大きさが 0.119 → 0.059 → 0.012）。
- ライブの画面を閉じるときは、エフェクトを外す（指を置いたまま戻る操作をしても、エフェクトが残らない）。
- エフェクトを切り替えるとき・指を置く／離すときは、10ミリ秒で滑らかにつなぐ（急に切り替えると「プツッ」と鳴る）。
- 単発の音は、エフェクトを通さず、曲の音に重ねる。
- 確かめ用の口（`window.__cmLiveAudio`）は、出口の音を測るだけで、ほかの動きを変えない。

## 残すこと（後の段階で）
- 実機での遅れの評価と、開発者ツールをつながずにロック中に鳴り続けるかは、段階2の終わりに実機でまとめて確かめる。
- 画面の名前と切り替えのボタンの絵（今は「🎛」、読み上げの名前は「ライブの画面」）は、まだ決めていない。

# セルフレビュー（段階2：エフェクト）

## 見つけて直したこと
- Gate・SideChain：指を置いた瞬間の最初の拍で、深さ（縦の位置）が前の値のまま使われていた（深さは move で決めていて、拍の予定は start で組むため）。start でも深さを決めるようにした。
- BitCrush：一番粗い所を 2ビットにしていたが、小さな音（試験の曲は 0.119）が丸めで 0 になり、無音になった。一番粗い所を 4ビットにした。
- TypeScript の設定（erasableSyntaxOnly）で、コンストラクタの引数でフィールドを作る書き方が使えなかったので、ふつうのフィールドにした。

## 確かめたこと（問題なし）
- 指を置いたまま別のエフェクトに切り替えたとき、前のエフェクトの拍の予定（BeatClock）・揺れ（Wobble の LFO）・繰り返しは、外すときに止める（stop の後に dispose）。
- ライブの画面を閉じるとき（指を置いたままでも）、release でエフェクトを止める。拍の予定のタイマーも止まる。
- Echo の残りの響きは、エフェクトを選び直すと消える（出口を閉じる）。ふたたび指を置くと、遅れへ送る音とエフェクトの中の素通しを開け直す。
- AudioWorklet の処理（processors.js）は、読み込むまで XY パッドを押せないようにした（エフェクトを作るのは読み込んだ後）。
- 作っておくのは、選んでいるエフェクト1つだけ（ほかのエフェクトの処理は動かさない）。
- 入力がモノラル（1チャンネル）でも、AudioWorklet の処理は両方のチャンネルに同じ音を出す。

# セルフレビュー（段階3：単発の音）

## 見つけて直したこと
- 連打は、拍の予定を少し先（0.15秒）まで組むので、短く押しただけでも、2回目（Snare・Hat なら約0.12秒後）が先に予定されて鳴っていた。音ごとに出口を分け、離したときに、まだ鳴り始めていない分の出口を外すようにした。
- 6個の大きさがそろっていなかった（Clap が小さく、Impact が大きすぎた）。音ごとの大きさを直した。

## 確かめたこと（問題なし）
- 指ごとに、離したときの処理を覚えておく（同じボタンを2本の指で押しても、それぞれ止まる）。指がボタンの外に出ても、ボタンが指を捕まえておくので、離したときに止まる。
- ライブの画面を閉じたとき（押したままでも）、連打と Riser を止める。
- Riser を離したときは、上がっている途中の大きさのまま止めてから消す（cancelAndHoldAtTime。値が最初に戻って「プツッ」と鳴らないように）。音の部品は 0.1秒後に止め、0.3秒後に外す。
- 長押しで、端末のメニューが出ないようにした。
- BeatClock を別のファイルに移しただけで、エフェクトの動きは変えていない。

# セルフレビュー（段階4：録音した音）

## 見つけて直したこと
- マイクを開く処理が、画面の描き直しのたびに閉じて開き直し、いつまでも録れなかった（覚えておく値を変える関数が、描き直しのたびに作り直されるため）。マイクを使えないときの処理を useEffectEvent にして、開き直さないようにした。
- マイクを開いている途中で閉じた（REC モードを切った）とき、開き終わったマイクが開いたままになるおそれがあった。開くたびに番号を付け、途中で閉じられていたら、開き終わったときに閉じるようにした。
- 速さを変えた音を、BPM ごとにすべて覚えていた（8秒の音は1つ数MBあり、BPM を測り直すたびに増える）。録った音ごとに、最後に作った速さの分だけ覚えるようにした。
- BPM のボタンが REC のボタンの分だけ狭くなり、「曲に合わせてタップ」が2行に折り返していた。文字を小さくして1行に収めた。

## 確かめたこと（問題なし）
- 録っている途中で8秒に達すると、録音の処理が自分で止めて音を返す。その後に指を離しても、何も起きない。
- 録っている途中でライブの画面を閉じると、録音を止め、そこまでの音を割り当てる。
- REC モードの間は、単発の音のボタンを押しても鳴らさない（録るだけ）。マイクを開き終わるまでは、押しても録らない。
- 録音の処理の出口は無音（大きさ 0 でスピーカーにつなぐのは、処理を動かすためだけ）。
- 録った音は、新しく録ると別の物になるので、前の音のために作った速さの音は、使われなくなって消える。
- 同じボタンの前の音を止めるのは、録った音だけ（その場で作る音は短いので、今までどおり重ねる）。
- 押したままの連打をやめたので、単発の音では BeatClock を使わなくなった（エフェクトでは使う）。
- Windows の動きは変えていない（ライブの画面は Android だけ）。アプリの権限に、マイク（RECORD_AUDIO・MODIFY_AUDIO_SETTINGS）を加えた。

# セルフレビュー（段階4の後の見た目の直し）
- 単発の音のボタンの名前と「REC」の印を消し、鳴らす音の波形を出すようにした（ユーザーの指示）。録っていないボタンが空にならないよう、その場で作る音も、開いたときに音を出さずに作って（OfflineAudioContext）、薄い色で波形を出す。
- 波形は大きさを全体の最大でそろえるので、ほぼ無音の録音（エミュレータのマイク）でも、目いっぱいの高さに見えていた。そろえる基準を 0.05 より小さくしないようにして、小さな音は小さいまま描く。
- 波形の形は、録った音ごとに覚えておく（描き直しのたびに、数十万の点を読まない）。
- BPM のボタンの「曲に合わせてタップ」を消した（ユーザーの指示）。測っている途中の「あと3回」は残す。
