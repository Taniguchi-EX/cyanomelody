# リアルタイムエフェクト

状態：作業概要の検討中（段階1：画面の大枠）。

## 目的
鳴らしている曲に、指の操作でその場でエフェクトをかけたり、ドラムなどの単発の音を重ねたりして遊べる画面を作る（Android 版）。今のエフェクト（エフェクトセット）は、鳴らす前に音を作っておくもので、その場では変えられない。
エフェクトは、音楽ゲーム「SOUND VOLTEX」の FX（押している間だけかかるエフェクト）とつまみのフィルターを参考に、近いものを作る（名前・絵・音などはまねない。効き方を参考にするだけ）。

## 進め方（段階）
1. 画面の大枠を決めて作る（この作業概要）。エフェクトと単発の音は仮の中身で置く。
2. エフェクトを1つずつ決めて作る（`01-01_エフェクト.md` で検討する）。
3. 単発の音を決めて作る（`01-02_単発の音.md` で検討する）。

## 画面

### 入り方
- 全画面の再生の右上に、切り替えのボタンを置く。押すと、この画面（以下「ライブの画面」）を開く。
- ライブの画面の「←」と、端末の戻る操作で、全画面の再生に戻る。
- Android だけ。Windows には作らない。

### 並び（縦向き）
```
┌──────────┬──────────┐
│ ← 曲名            ⏸ │  見出しの行：戻る・曲名・再生と一時停止
├──────────┬──────────┤
│ ┌──┐┌──┐ │[Retg][Gate]│  右上：エフェクトを選ぶボタン（2列）
│ │①││②│ │[Echo][Wobl]│        選んでいるものを目立たせる
│ └──┘└──┘ │[Flng][Phas]│
│ ┌──┐┌──┐ │[Bit ][Ptch]│
│ │③││④│ │[Stop][SdCh]│
│ └──┘└──┘ │┌────────┐│  右下：XY パッド
│ ┌──┐┌──┐ ││        ││        指を置いている間だけ、選んだエフェクトがかかる
│ │⑤││⑥│ ││   ●    ││        横・縦の位置で効き方を変える
│ └──┘└──┘ ││        ││
├──────────┤│        ││
│ BPM 128  │└────────┘│
│ （タップ）│          │  左下：BPM のボタン
└──────────┴──────────┘
```
- 左半分：単発の音のボタン（2列×3段の6個）。押すと、その音を1回鳴らす。曲の音に重ねて鳴らす（曲のエフェクトはかけない）。
- 右半分の上：エフェクトを選ぶボタン（2列）。押すと選ぶ（同時に選べるのは1つ）。並べるエフェクトは段階2で決める。
- 右半分の下：XY パッド。
  - 指を置いている間だけ、選んでいるエフェクトをかけ、離すと外す（SOUND VOLTEX の FX の長押しと同じ）。
  - 横と縦の位置で、エフェクトの効き方（細かさ・強さなど）を変える。何をどう変えるかは、エフェクトごとに段階2で決める。指を置いたまま動かすと、その場で変わる。
  - 指の位置に印を出す。
- 左下：BPM のボタン（下の「BPM」）。
- 再生エリア（小）は出さない（見出しの行で一時停止できる）。

### BPM
- 曲に合わせて何回か押すと、押した間隔から BPM を出して、ボタンに出す（「BPM 128」）。
- 4回目から出す。直近の8回までの間隔の平均を使う。前に押してから2秒より空いたら、数え直す。
- 出した BPM は、次に測り直すまで覚えておく（アプリを閉じても覚えておく）。曲ごとには覚えない。
- BPM は、テンポに合わせて動くエフェクト（細かく繰り返す・音を切るなど）と、単発の音（連打など）に使う。どれに使うかは段階2・3で決める。
- 一度も測っていないときは 120 とする。

### 曲との関係
- かけるのは、今鳴らしている曲の音だけ。ファイルや、エフェクトセットの設定は変えない。
- エフェクトセットがかかる曲では、エフェクトセットをかけた音に、さらにかける。
- ライブの画面を閉じても、曲は鳴り続ける。指を離せばエフェクトは外れるので、閉じたときには何もかかっていない。

## 仕組み（案）
- ブラウザの音声処理（Web Audio）を使う。再生に使っている audio 要素の音を AudioContext に通し、エフェクトの部品（フィルター・遅延など。繰り返しなどは AudioWorklet で自前で作る）を通してから鳴らす。単発の音も同じ AudioContext で鳴らす。
- 確かめないと分からないこと（段階1の最初に、実機で確かめる）
  - audio 要素の音を AudioContext に通せるか。曲は別の場所（端末のファイルを読むための専用のアドレス）から読んでいるので、ブラウザの決まり（CORS）で音が消される（無音になる）おそれがある。消されるときは、曲を読み込んで（fetch）Web Audio で直接鳴らすなど、別の方法を考える。
  - AudioContext に通した後も、画面をロックしたときやアプリを裏に回したときに鳴り続けるか（今はロック中も鳴る）。
  - 指を置いてから音が変わるまでの遅れが、遊ぶのに困らない程度か。

## やらないこと
- Windows 版のライブの画面。
- かけた音の録音・書き出し。
- 曲ごとの BPM の記録。曲からの BPM の自動検出。
- 単発の音を利用者が入れ替えること（段階3で、要るかどうか改めて決める）。

## 決まっていないこと
- ライブの画面の名前（見出しに出す名前）と、切り替えのボタンの絵。
- 並べるエフェクトと、XY パッドの横・縦の割り当て（段階2）。
- 単発の音の中身（段階3）。
