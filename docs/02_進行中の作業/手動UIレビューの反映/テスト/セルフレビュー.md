# セルフレビュー

## 1回目の指摘

### 仕様との食い違い
- 作業概要では、右の欄の出典・ライセンスのボタンも「＋」としていたが、設定済みのものを置き換える操作なので「設定」のままにした（「＋」は足す意味に見えるため）。タグは足す操作なので「＋」にした。作業概要の書き方を直した。

### 不具合・境界値
- フォルダ・ファイルを選ぶダイアログを開けなかったとき、エラーが画面に出ず、何も起きないように見えた。下の欄にエラーを出すようにした。
- 欄の幅を広げたあとでウィンドウを狭くすると、中央の欄がつぶれていた（左・右の幅が固定のため）。左・右の欄の列を「最小の幅〜覚えた幅」にし、左・右の欄が最小まで縮んでから中央が縮むようにした。
- WAV の INFO のタイトルは末尾に NUL 文字が付いていて、空白の除去だけでは残った（単体テストで見つけた）。NUL も取り除くようにした。
- トラック名は読み終わるまで出さない。別のファイルに移ったときに、前のファイルのトラック名が出ないよう、読んだファイルのパスと組にして持つ。
- 右の欄のタグの入力欄の候補は、既に付いているタグを除いた。付いているタグ名を入れても「＋」は押せない。
- 右の欄で何も選んでいないときは何も出さない（空の欄）。

### 既存の機能への影響
- タグの入力欄で新しいタグを作れなくなったため、画面テストの補助関数 `addTag` は、まだないタグを管理画面で作ってから付けるようにした。
- 一括操作の欄の出典・ライセンス・タグは、今までどおり新しい名前で作れる（`CreditField` の `bulk` で分ける）。
- 一覧の色の印の書式 `hash` を、右の欄のハッシュ値から外した（これが縦に細長くなる原因だった）。
- `Collapsible` は、左の欄の「選んでいる数」に加えて、右の欄の「件数」も出せるようにした（`count`）。左の欄の表示は変わらない。

### 書き方
- 境界の部品は `Splitter` にまとめ、左右の欄で同じものを使う。幅を覚える処理は `storage.ts` の `useStoredNumber` にまとめ、ドラッグを終えたときだけ保存する。
- トラック名を読む処理は Rust の `metadata.rs` に分けた（エフェクトのデコードとは目的が違うため）。

## 2回目の指摘

### 仕様との食い違い
- なし。記号（＋・✎・🗑・🧹）と、行にマウスを乗せたときだけ出すことは、作業概要どおり。

### 不具合・境界値
- 0件でグレーアウトした行は、行全体を薄くしていたため、行の「✎」「🗑」まで押せないように見えた。使われていないタグ（0件）を消したり名前を変えたりするのはよくある操作なので、薄くするのを名前・件数などだけにし、記号と取っ手は薄くしないようにした。
- グレーアウトした行（タグ・出典・ライセンス）には `aria-disabled` を付けていたが、ARIAでは中の要素まで「押せない」扱いになり、行の「✎」「🗑」も押せないものとして扱われていた（画面テストで見つけた）。これらの行には付けず、グレーアウトは書式（class）だけで示すようにした。「（タグなし）」などの、ボタンを持たない行はそのまま。
- 出典・ライセンスの行は、名前と件数が離れて並んでいた（件数が行の中ほどに出る）。名前が残りの幅を使うようにし、件数・記号を右に寄せた（タグの行と同じ並び）。
- 名前の入力欄は、外を押すとやめる。統合の確認ダイアログが出るとウィンドウからフォーカスが外れて入力欄が閉じるが、確認の結果どおりに変える（キャンセルなら何も変えない）。キャンセルしたときに入力した名前は残らないが、入れ直せば済むため、このままにした。
- 作れなかった・変えられなかったとき（同じ名前など）は、入力欄・フォームを残し、直して続けられるようにした。
- 名前を変えずにEnterを押したときは、何もせず入力欄を閉じる（変えていないのに「変えました」と出さない）。
- 「✎」「🗑」は、行の絞り込み・中央で開く処理に届かないようにした（入力欄を押したときも同じ）。
- 出典・ライセンスのフォームは重ねて表示するので、フォームを開いている間に同じものが削除されることはない（管理画面にあった「編集中のものが削除されたら作成に戻す」処理は要らなくなった）。

### 既存の機能への影響
- 「使われていないタグを削除」は見出しの「🧹」に移した。プレイリストで使われているタグを消さないなどの決まりは変えていない。
- 中央の編集画面での、プレイリストの名前の変更・削除・子のプレイリストの作成はそのまま。
- 行の記号はキーボードのTabでは届かない（マウスを乗せる前は隠しているため）。左の欄の行はもともとキーボードで選べないため、今回は合わせない。

### 書き方
- 行の「✎」「🗑」は `RowActions`、その場の名前の入力欄は `NameInput` にまとめ、タグ・プレイリスト・出典・ライセンスで同じものを使う（`TreeParts.tsx`）。
- 管理画面（`TagManager`）を消し、出典・ライセンスの管理画面は、フォームだけの `CreditForm` にした。使わなくなった書式（管理画面の表など）も消した。

## 3回目の指摘

### 仕様との食い違い
- なし。作業概要に書いた形（再生の欄、詳細画面、項目を押したときの右の欄、右の欄のタグ・プレイリスト・出典・ライセンス、左の欄の一番上の絞り込み）で作った。

### 不具合・境界値
- 右の欄のタグの入力欄で「候補から選んだ」ことは、ブラウザが入力を候補で置き換えたとき（入力の種類が `insertReplacementText`）で見分ける。打ち込んでいる途中で名前が一致しただけでは付けない（「雨」を打って「雨音」にしたいときに、「雨」が先に付いてしまわないように）。画面テストではこの入力を起こして確かめたが、実際に候補を選んだときの動きは手動でも確かめてほしい。
- 右の欄で既に付いているタグ名（大文字・小文字の違いを含む）を入れてEnterを押しても、何もせず入力欄を空にする（同じタグを付け直す処理を呼ばない）。
- 項目のファイルはファイルの一覧（絞り込んだ結果）にないことがあるので、ファイルの一覧とは別に1件だけ読む。タグを付けたなどでデータを読み直すたびに、これも読み直す。別の項目に移ったときに前の項目のファイルが出ないよう、読んだファイルのidと押した項目のファイルのidが一致するときだけ出す。
- 項目を押した直後は、項目のファイルを読み終えるまで右の欄に何も出さない。最初は読み終えるまで「ファイルでない項目」の形（名前の欄と内容だけ）を出していたため、読み終えて形が変わったときに、入力し始めた名前が消えていた（画面テストで見つけた）。
- 項目のファイルがライブラリから外されているとき（ファイルの項目なのにファイルがない）は、タグの組み合わせなどと同じく「プレイリスト上での名前」と内容だけを出す。
- 「プレイリスト上での名前」の欄は、別の項目を押すと欄の外に出たことになり、そこで保存する（入力したまま別の項目に移っても消えない）。
- プレイリストを開いたとき・閉じたときは、右の欄の項目の表示を消す。
- 再生の欄の時間は、長さが分からない間（読み込み中）は「0:00」と出す（NaN を出さない）。
- 右の欄のプレイリストのプルダウンは、処理中は押せないようにした（続けて選んで二重に加えないため）。一括操作の欄のプルダウンも同じ部品なので、処理中は押せなくなった。

### 既存の機能への影響
- 1回目の「右の欄では新しいタグを作れない」は、今回の指摘で取り消した（Enterで最上位に作って付ける）。出典・ライセンスは、今までどおり右の欄では作れない（プルダウンは既にあるものだけ）。
- 一括操作の欄の入力（タグ・出典・ライセンス・プレイリスト）は変えていない。
- 試聴（一覧の行の再生ボタン）は、今までどおり再生の欄には出さない。
- 左の欄のプレイリストの行から、再生・名前の変更・削除のボタンをなくしたので、2回目で付けた「✎」「🗑」もなくなった（タグ・出典・ライセンスの行には残る）。

### 書き方
- 再生の欄は `PlayerBar` を作り直した（何も再生していないときも出し、`data-playing` で再生中かを示す）。
- 「プレイリスト上での名前」の欄と、ファイルでない項目の詳細は `ItemDetail.tsx` にまとめた。項目の元の名前を求める処理は `playlistItem.ts` に移し、詳細画面と右の欄で使う。
- 詳細画面の名前の変更は、左の欄のタグと同じ `NameInput` を使う。

## 4回目の指摘

### 仕様との食い違い
- なし。

### 不具合・境界値
- 音量は、バーを動かしている間は音量だけを変え、動かし終えたとき（マウスを離した・キーを離した）に保存する。再生の欄は再生中に何度も描き直すので、描き直すたびに保存しないようにした。
- 音量は、アプリを開いたときに覚えていた値を `audio` 要素に入れる。試聴とプレイリストの再生は同じ `audio` 要素なので、どちらにも効く。
- タグの行へのドラッグで、0件でグレーアウトしたタグにも落とせる（使われていないタグに付けるのは普通の操作のため）。「（タグなし）」の行は落とす先として探さない（`data-tree` を持たない）。
- タグへのドラッグで、既に付いているファイルがあっても、そのまま（付け直しのエラーにはならない。一括操作の欄でタグを付けるときと同じ処理）。
- 一覧の見出しの行は、文字を消したあとも、右端のチェックボックスの位置が変わらないように右寄せにした。

### 既存の機能への影響
- 「使われていないタグを削除」は、画面のボタンだけでなく、Rust のコマンド（`delete_unused_tags`）と、それだけが使っていた `tags_in_use` も消した。単体テストは、この機能のための2件を消し、プレイリストのテストの中の1行（プレイリストで使われているタグは消さないことの確認）を消した（84件→82件）。
- 件数を一番下の行に移したので、中央のツールバーは、チェックしているときだけ出る。
- 試聴中の再生の欄の表示は新しく足したもので、試聴の操作（行のボタンで始める・止める）は変えていない。

### 書き方
- ファイルの行のドラッグ（`useFileDrag`）は、落とす先を「プレイリスト」と「タグ」の2種類にし、どちらに落としたかを渡す。
- 試聴中のファイルは、id だけでなくファイルそのもの（`previewFile`）を持つようにし、再生の欄で名前を出す。

## 5回目の指摘

### 仕様との食い違い
- なし。あいまいだった3点（一括操作の欄をなくして消える操作、「このプレイリストを作る」が何を指すか、右の欄のプレイリストのチップの「✕」）は、実装の前にユーザーに確認した。

### 不具合・境界値
- 一括操作の欄のために使っていた「チェックしたファイルの内訳」の処理（`summarize_files`）には、ライブラリから消えたファイルをチェックから外す役目もあった。内訳は要らなくなったので消したが、この役目は残す必要があるため、ライブラリにあるidだけを返す小さなコマンド（`existing_file_ids`）に置き換えた。
- すべての条件を外す「✕」のチップは、検索の文字も外す（チップには出ないが、絞り込みの条件のため）。チェックと右の欄の表示は外さない（検索の欄の右の「✕」との違い）。
- 「全てチェック」は、表示中がすべてチェック済みのときは押せないようにした（押しても何も変わらないため）。
- 出典・ライセンスへのドラッグは、0件でグレーアウトした行にも落とせる（まだ使っていない出典を設定するのは普通の操作のため）。
- 右の欄のプレイリストのチップの「✕」は、そのプレイリストに同じファイルの項目が複数あれば、すべて外す。外した項目のプレイリスト上での名前やエフェクトの設定も消える。確認は出さない（詳細画面の項目の「✕」と同じ）。

### 既存の機能への影響
- まとめて外す操作（タグ・出典・ライセンス）と、見つからないファイルのまとめての「ひも付け直す」「ライブラリから外す」はなくなった（ユーザーに確認済み）。
- 「🔊」（ライブラリの外のファイルと同じ音声を探す）は、画面と Rust のコマンド（`hash_file`）を消した。ハッシュ値の計算そのもの（スキャン後の計算、重複、同じ音声を探す、ひも付け直し）は変わらない。
- 子のプレイリストは、左の欄で作ってから取っ手で親の中に落として作る（今までもできた操作）。
- 一覧の見出しの行をなくしたが、Ctrl+A での「表示中をすべてチェック」は残した。

### 書き方
- 使わなくなった部品・処理を消した：`BulkBar`、`audio.ts`（拡張子の一覧）、`CreditField` の一括操作用の分かれ道、`PlaylistPicker` の「追加」ボタン、`useChecks` の内訳、Rust の `summarize_files`・`FileSummary`、使われなくなった書式。
- ファイルの行のドラッグ（`useFileDrag`）の落とす先に、出典・ライセンスを足した。行には、ほかの木と同じく `data-tree`・`data-node-id` を付ける。
