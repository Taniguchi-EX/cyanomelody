# セルフレビュー

## 1回目の指摘

### 仕様との食い違い
- 作業概要では、右の欄の出典・ライセンスのボタンも「＋」としていたが、設定済みのものを置き換える操作なので「設定」のままにした（「＋」は足す意味に見えるため）。タグは足す操作なので「＋」にした。作業概要の書き方を直した。

### 不具合・境界値
- フォルダ・ファイルを選ぶダイアログを開けなかったとき、エラーが画面に出ず、何も起きないように見えた。下の欄にエラーを出すようにした。
- 欄の幅を広げたあとでウィンドウを狭くすると、中央の欄がつぶれていた（左・右の幅が固定のため）。左・右の欄の列を「最小の幅〜覚えた幅」にし、左・右の欄が最小まで縮んでから中央が縮むようにした。
- WAV の INFO のタイトルは末尾に NUL 文字が付いていて、空白の除去だけでは残った（単体テストで見つけた）。NUL も取り除くようにした。
- トラック名は読み終わるまで出さない。別のファイルに移ったときに、前のファイルのトラック名が出ないよう、読んだファイルのパスと組にして持つ。
- 右の欄のタグの入力欄の候補は、既に付いているタグを除いた。付いているタグ名を入れても「＋」は押せない。
- 右の欄で何も選んでいないときは何も出さない（空の欄）。

### 既存の機能への影響
- タグの入力欄で新しいタグを作れなくなったため、画面テストの補助関数 `addTag` は、まだないタグを管理画面で作ってから付けるようにした。
- 一括操作の欄の出典・ライセンス・タグは、今までどおり新しい名前で作れる（`CreditField` の `bulk` で分ける）。
- 一覧の色の印の書式 `hash` を、右の欄のハッシュ値から外した（これが縦に細長くなる原因だった）。
- `Collapsible` は、左の欄の「選んでいる数」に加えて、右の欄の「件数」も出せるようにした（`count`）。左の欄の表示は変わらない。

### 書き方
- 境界の部品は `Splitter` にまとめ、左右の欄で同じものを使う。幅を覚える処理は `storage.ts` の `useStoredNumber` にまとめ、ドラッグを終えたときだけ保存する。
- トラック名を読む処理は Rust の `metadata.rs` に分けた（エフェクトのデコードとは目的が違うため）。

### 不具合・境界値
- 0件でグレーアウトした行は、行全体を薄くしていたため、行の「✎」「🗑」まで押せないように見えた。使われていないタグ（0件）を消したり名前を変えたりするのはよくある操作なので、薄くするのを名前・件数などだけにし、記号と取っ手は薄くしないようにした。

- 出典・ライセンスの行は、名前と件数が離れて並んでいた（件数が行の中ほどに出る）。名前が残りの幅を使うようにし、件数・記号を右に寄せた（タグの行と同じ並び）。
- 名前の入力欄は、外を押すとやめる。統合の確認ダイアログが出るとウィンドウからフォーカスが外れて入力欄が閉じるが、確認の結果どおりに変える（キャンセルなら何も変えない）。キャンセルしたときに入力した名前は残らないが、入れ直せば済むため、このままにした。
- 作れなかった・変えられなかったとき（同じ名前など）は、入力欄・フォームを残し、直して続けられるようにした。
- 名前を変えずにEnterを押したときは、何もせず入力欄を閉じる（変えていないのに「変えました」と出さない）。
- 「✎」「🗑」は、行の絞り込み・中央で開く処理に届かないようにした（入力欄を押したときも同じ）。
- 出典・ライセンスのフォームは重ねて表示するので、フォームを開いている間に同じものが削除されることはない（管理画面にあった「編集中のものが削除されたら作成に戻す」処理は要らなくなった）。

### 既存の機能への影響
- 「使われていないタグを削除」は見出しの「🧹」に移した。プレイリストで使われているタグを消さないなどの決まりは変えていない。
- 中央の編集画面での、プレイリストの名前の変更・削除・子のプレイリストの作成はそのまま。
- 行の記号はキーボードのTabでは届かない（マウスを乗せる前は隠しているため）。左の欄の行はもともとキーボードで選べないため、今回は合わせない。

### 書き方
- 行の「✎」「🗑」は `RowActions`、その場の名前の入力欄は `NameInput` にまとめ、タグ・プレイリスト・出典・ライセンスで同じものを使う（`TreeParts.tsx`）。
- 管理画面（`TagManager`）を消し、出典・ライセンスの管理画面は、フォームだけの `CreditForm` にした。使わなくなった書式（管理画面の表など）も消した。

- 右の欄のプレイリストのプルダウンは、処理中は押せないようにした（続けて選んで二重に加えないため）。一括操作の欄のプルダウンも同じ部品なので、処理中は押せなくなった。

## 6回目の指摘

### 仕様との食い違い
- なし。あいまいだった3点（ライブラリの外のファイルを紐づけるときの扱い、直近で再生したものの並び順、曲名とプレイリスト上での名前の優先）は、実装の前にユーザーに確認した。

### 不具合・境界値
- 直近で再生したものの順番は、時刻ではなく通し番号で持つ。同じ秒に何曲も鳴らしても（プレイリストの「次へ」を続けて押すなど）、鳴らした順に並ぶ。
- 直近で再生したものは、ライブラリにないファイル（記録の直前に外されたなど）は記録しない。ファイルを消すと記録も消える（外部キーの連鎖）。
- 再生を記録したあとは一覧と件数を読み直す（「直近で再生したもの」で絞り込んでいるときに、すぐ反映されるように）。プレイリストの再生でも1曲ごとに読み直すが、条件が同じなので軽い。
- ひも付け直し（今までの「ひも付け直す」と、新しい2つ）では、再生の記録も移す。どちらにも記録があれば新しい方を残す。今までの「ひも付け直す」の移し方は、共通の処理（`merge_into`）にまとめた。
- 「ファイルを紐づける」で、元の場所に戻したファイルそのもの（見つからないファイルと同じファイル）を選んだときは、スキャンで見つかった扱いになるので、ひも付け直すものはない（エラーにしない）。
- 「ファイルを紐づける」で選んだファイルがライブラリの中にあっても、見つからない印が付いたままの記録しかないとき（スキャンしていない）は、そのフォルダをスキャンしてから探す。
- ライブラリのフォルダの外にあるファイル・フォルダを登録するときは、今までのフォルダの追加と同じ決まり（登録済みのフォルダを含むフォルダは登録できない）に従い、登録できなければエラーを出す。
- 「指定フォルダから自動で探す」は、ライブラリにあって計算済みのファイルを先に調べ、なければフォルダの中のファイルを64件ずつ計算して、見つかった時点でやめる（大きなフォルダで、全部を計算してから比べない）。計算している間は「処理中…」になり、ほかの操作は待つ。
- 曲名はデータベースにないので、再生の欄に出すときにファイルから読む。読み終わるまでは拡張子を除いたファイル名を出し、別の曲に移ったときに前の曲の曲名が出ないよう、読んだファイルのパスと組にして持つ（右の欄のトラック名と同じ）。
- 「その他」の「リンク切れしているもの」は、見つからないファイルがないときも行を出し、0件でグレーアウトする（以前の「⚠」は、そのときボタンごと出さなかった）。

### 既存の機能への影響
- 左の欄の一番上の「⚠」「⧉」は「その他」の欄に移した。条件のチップにも出るようになった（以前は、この2つはチップに出なかった）。
- 「その他」の件数を求めるため、件数の問い合わせが3回増えた（同じ条件は覚えておく仕組みの中で行う）。
- 欄の見出しの「＋」は、欄を開く関数を受け取れるようにした（`Collapsible` の `actions` に関数を渡せる）。出典・ライセンスの「＋」はフォームを開くので、そのまま。

### 書き方
- リンク切れのファイルのひも付けは、Rust の `linking.rs` に分けた（ライブラリに取り込む処理と、フォルダから探す処理）。直近で再生したものは `recent.rs`。
- 「その他」の項目の一覧（条件の名前・件数の名前・記号）は `otherFilters.ts` にまとめ、左の欄と条件のチップで使う。

## 7回目の指摘

### 仕様との食い違い
- なし。作業概要に書いた形（ユーザーに確認済み）で作った。途中で受けた「▶／⏸を中央に」も作業概要に足した。

### 不具合・境界値
- 一覧の再生の順番は、再生を始めたときの一覧から作る（見つからないファイルを除く）。絞り込みを変えても、鳴っている順番は変わらない。
- 一覧の再生で「🎲」（1曲だけ）を押すと、表示中の一覧から1件を選んで鳴らす。表示中に鳴らせるファイルがないときは、そのことを出して鳴らさない（再生の欄の「▶」「🔀」「🎲」は押せない）。
- 一覧の行の「▶」は、鳴らしているファイルの行なら止める。プレイリストの再生で同じファイルが鳴っているときも、その行の「■」で止まる（どちらの再生でも、鳴らしている行を示すため）。
- 再生中の項目のハイライトは、再生しているプレイリストと、開いているプレイリストが同じときだけ出す。曲には「どの項目から出たか」を持たせ、子のプレイリストを中まで展開しても、外側（開いているプレイリスト）の項目になるようにした（展開するたびに外側の項目で書き換える）。項目1つだけの再生でも、その項目を示す。
- 項目のハイライトの左端の線は、ドラッグ中の落とす位置の線（上・下）と同じ所に引くので、ドラッグ中は落とす位置の線を優先する。
- 曲のリストは、データを読み直すたびに読み直す（タグを付け替えたなど）。別の項目に移ったときに前の項目の曲が出ないよう、読んだ項目の id と組にして持つ。
- 右の欄のパスは、見つからないファイルのときはリンクにしない（開いても見つからないため）。
- 曲名がないときの名前（拡張子を除いたファイル名）を、再生の欄と右の欄で同じにするため、求め方を `paths.ts` の `stem` にまとめた。

### 既存の機能への影響
- 一覧の再生は、プレイリストの再生と同じ仕組み（再生の順番）で鳴らすので、試聴でも「直近で再生したもの」に1曲ごとに記録される（今までと同じ）。エフェクトの管理画面の試聴は、今までどおり1件だけ鳴らす。
- 再生の順番の各曲に「どの項目から出たか」を足した（Rust の `PlayEntry.item_id`）。書き出しなどほかの使い方は変わらない。
- プレイリストの詳細画面の「タグの組み合わせを加える」（その場でタグを選ぶ欄）をなくしたので、組み合わせは左の欄でタグを選んでから加える。

### 書き方
- 項目に入る曲をすべて並べる処理（`item_files`）は、再生の展開（`expand_item`）とは別の関数にした（再生方法を当てはめず、乱数も使わないため）。

## 8回目の指摘

### 仕様との食い違い
- なし。あいまいだった3点（まとめての操作の種類、「新しいfxを作る」で作ったエフェクトセットをその行に付けるか、既にあるエフェクトセットを直す入口）は、実装の前にユーザーに確認した。

### 不具合・境界値
- 詳細画面の項目の行をつかんでドラッグすると、ページの文字が選ばれて青くなっていた（画面テストのスクリーンショットで見つけた）。ファイルの一覧の行と同じく、項目の行では文字を選ばないようにした。
- 項目の行のドラッグは、並べ替えの取っ手・プルダウン・ボタン・チェックボックスの上では始めない（取っ手は今までどおり並べ替え、それ以外はそれぞれの操作）。
- 項目をつかんで左の欄に落としたときは、項目に入る曲を Rust に問い合わせてから操作する（タグの組み合わせ・プレイリストの項目は、再生方法にかかわらず中の曲すべて）。同じ曲が複数の項目に入っていても1回だけ操作する。
- 「新しいfxを作る」「このfxを編集」は、プルダウンの値を変えずに管理画面を開く（プルダウンは今のエフェクトセットのまま）。管理画面は、試聴する曲を調べてから開く。
- 「新しいfxを作る」をチェックした行で選んだときは、作ったエフェクトセットをチェックした行すべてに付ける（fx をまとめて設定するのと同じ決まり）。
- 試聴は、管理画面を開いた元の項目の曲で行う（今までは右の欄のファイル）。項目に鳴らせる曲がない（見つからないファイルだけなど）ときは、試聴のボタンを押せない。
- 検索の欄の「✕」（すべて解除）をなくしたので、右の欄の表示を消す操作はなくなった（別のファイルを押すと移る）。フォルダを登録したときに絞り込みなどをすべて外す処理（`clearAll`）は残している。

### 既存の機能への影響
- エフェクトセットの管理画面は、左の欄からは開けなくなった（項目の fx のプルダウンからだけ）。ファイルの一覧で選んだファイルで試聴することもなくなった。
- 「エフェクトのまとまり」の言葉を、画面・下の行・確認のダイアログ・ドキュメントで「エフェクトセット」にした。データベースの名前（effect_chains）は変えていない。
- ファイルの一覧の行のドラッグの部品（`useFileDrag`）を、プレイリストの項目の行でも使う。落としたときに渡すのは、ファイルの一覧ではファイルの id、詳細画面では項目の id。

### 書き方
- ファイルを左の欄に落としたときの処理を `dropFiles` にまとめ、ファイルの一覧と、プレイリストの項目（`dropItems`：曲に展開してから `dropFiles`）で使う。
