# サービスの検討

2026-11-05 に調べた結果。料金や条件は変わることがあるので、再開するときに確かめ直す。

## 仕組み
1. アプリの中で、曲の音声から指紋（Chromaprint の形式）を作る。
2. AcoustID に、指紋と曲の長さ（秒）を送って問い合わせる（`https://api.acoustid.org/v2/lookup`。パラメータは client・duration・fingerprint と、返してほしい情報の meta）。曲の候補（MusicBrainz の曲の id、曲名、アーティスト、アルバム）と、一致の点数が返る。
3. 必要なら、MusicBrainz にその曲の id で問い合わせて、ジャンルなどを取る。

## 候補のサービス
- AcoustID（＋MusicBrainz）：本命。
  - 料金：非営利なら無料（オープンソース向けの枠は検索の回数も無制限）。営利で使うときは月50ユーロからの有料の枠。
  - 制限：1秒に3回まで（5,000曲なら、問い合わせだけで約30分）。
  - キー：アプリを登録して、アプリ用のキー（client）をもらう。使う人ごとのキーは要らない（要るのは指紋を投稿するときだけ）。
  - データのライセンス：CC BY-SA 3.0（MusicBrainz との対応だけ CC0）。取得した情報をタグにする分には問題になりにくいが、データをまとめて配り直すときは表示の条件がある。
- MusicBrainz：曲の詳しい情報。
  - API キーは要らない。アプリの名前と連絡先を入れた User-Agent を付けて、1秒に1回までに抑える（超えると断られる）。
  - データのライセンス：基本のデータは CC0。それ以外の一部は CC BY-NC-SA 3.0。非営利なら無料。
- ACRCloud：14日間の無料の試用。その後は使った分だけ料金がかかる（料金はログインしないと見られない）。数千曲には有料になる。
- AudD：最初の300回は無料。その後は1000回あたり2〜5ドル（ほかに月額の案内もあり、情報が食い違う）。数千曲には有料になる。
- Shazam：公式に使える API がないので、候補から外した。

## 指紋の作り方
- Rust の `rusty-chromaprint`（MIT ライセンス）で作れる。音声の読み込みは、今も使っている symphonia でできる（ほかのソフトを同梱しなくてよい）。
- ただし「移植の途中」とされているので、作った指紋で AcoustID が曲を見つけられるかを試作で確かめる。だめなら、公式の `fpcalc.exe`（Chromaprint。LGPL 2.1）を同梱する。

## 向き不向き
- 見つかるのは市販・配信の音楽。谷口さんのライブラリはほとんどが MP3 の音楽（約5,200曲）なので、よく当たる見込み。
- 効果音や自作の音は、まず見つからない。
