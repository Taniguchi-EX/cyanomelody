# 初期概要検討

## アプリの概要

効果音などの音声素材を管理するアプリ。ローカルにある音声ファイルにタグを付けて管理する。
使うのは本人と、限られた友人数名。

メインとなる音声管理機能のほか、補助的に以下の機能も実装する。
- タグ自体の管理
- 出典とライセンスの管理
- ハッシュ値による検索と重複チェック
- エフェクトセットの作成と書き出し（ノーマライズもエフェクトの一種として扱う）

## 動作環境

- 対応OS：Windows11 / Linux / Android。まずはWindowsだけに対応し、LinuxとAndroidは後の作業で対応する。
- 配布：インストーラやAPKのファイルを友人に直接手渡しする。
- 規模：1端末あたり最大で数万ファイル
- 対応する形式：MP3、WAV、FLAC、OGG、M4A

## アーキテクチャや実装方式

- Tauri 2で作る。内部処理はRust、画面表示はReact。
- タグやハッシュ値などのメタデータは、アプリのデータ領域にSQLiteで保存する。
- ライブラリは端末ごとに独立して扱う。端末間での共有や同期はしない。

## 基本方針

### 元のファイルを変更しない
- タグはアプリのメタデータにだけ持つ。ファイル内のタグ情報（ID3など）には書き込まない。
- エフェクトを掛けた結果は、別のファイルとして書き出す。

### ファイルの登録と追従
- ライブラリにするフォルダを登録し、スキャンしてファイルを取り込む。
- ファイルが移動・名前変更・削除され、ひも付けが切れたファイルには印を付けて分かるようにする。
- 自動では追いかけない。ユーザーがハッシュ値での検索を明示的に実行し、移動先などを見つけ直す。

### ハッシュ値
- ファイル内のタグ情報を除いた、音声データの部分だけを対象に計算する。
- そのため、ファイル名やファイル内のタグ情報を書き換えても、ハッシュ値は変わらない。

### エフェクト
- 複数のエフェクトを組み合わせ、一つのエフェクトセットとして扱う。
- エフェクトセットを掛けた結果は、別のファイルとして書き出す。

## 開発の順番

以下の順に、機能ごとに別の作業として作る。画面は動作に必要な最低限とし、後の作業で改善する。

1. 音声のタグ管理機能（ライブラリの登録・スキャンを含む）
2. タグ自体の管理機能
3. ハッシュ値を使った機能（重複チェック、ハッシュ値での検索、ひも付けが切れたファイルの見つけ直し）

各作業の内容と順番は、`02_ロードマップ.md`の全体ロードマップで管理する。
確認が必要な技術は、各作業のロードマップに試作のフェーズを設けて、本実装の前に確かめる。
