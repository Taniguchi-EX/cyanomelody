# 全体ロードマップ

今のところやりたいことの一覧と順番。やりたいことが増えたり変わったりしたら、その都度書き換える。
各作業の詳しいロードマップは、それぞれの作業フォルダの`02_ロードマップ.md`に書く。
作業が完了したらチェックを入れ、「03_完了した作業」での連番を書き添える。

## 最初の版（Windowsのみ）
- [x] 1. 初期概要検討（001_初期概要検討）
  - アプリ全体の方針を決め、`01_現在の機能/00_全体/`に反映する。
- [x] 2. 音声のタグ管理（002_音声のタグ管理）
  - 試作：Tauri 2・React・SQLiteの構成を作り、数万ファイルのフォルダをスキャンする時間を測る。
  - 本実装：ライブラリにするフォルダの登録とスキャン、音声ファイルへのタグの付け外し、タグでの絞り込み、試聴。
  - ひも付けが切れたファイル（スキャンで見つからなくなったファイル）に印を付ける。
- [x] 3. タグ自体の管理（003_タグ自体の管理）
  - タグの作成・名前変更・削除。タグの分類（階層など）はこの作業の概要検討で決める。
- [x] 4. ハッシュ値を使った機能（004_ハッシュ値を使った機能）
  - 試作：各形式（MP3、WAV、FLAC、OGG、M4A）から、タグ情報を除いた音声データの部分を取り出す。数万ファイルでハッシュ値を計算する時間を測る。
  - 本実装：ハッシュ値の計算と保存、重複チェック、ハッシュ値での検索、ひも付けが切れたファイルの見つけ直し。

## 2つ目の版（この順に行う）
- [x] 6. タグの階層構造（006_タグの階層構造）
  - 試作：WebView2（Tauri）の中でのドラッグアンドドロップ。
  - 本実装：タグの親子と順番、左の欄でのドラッグアンドドロップ、左の欄の階層表示、子孫を含めた絞り込み。
- [x] 7. ファイルの一括操作（007_ファイルの一括操作）
  - 一覧の各行のチェックボックス（絞り込みを変えても外れない）、チェックしたファイルへの一括操作、チェックしたファイルだけの表示。
- [x] 8. 絞り込み条件のグレーアウト（008_絞り込み条件のグレーアウト）
  - 試作：数万ファイルで、すべての項目の「選んだときの件数」を求める時間を測る。
  - 本実装：選ぶと0件になるタグ・出典・ライセンスの項目のグレーアウトと、件数の表示。

- [x] 10. リファクタリング（010_リファクタリング）

## 4つ目の版（この順に行う）
- [x] 11. プレイリストの項目の別名（011_プレイリストの項目の別名）
  - プレイリストの各項目に、ファイル名などとは別の名前を付ける。そのプレイリスト（親・参照からの再生を含む）でだけ有効。
- [x] 12. エフェクト（012_エフェクト）
  - 試作：エフェクトの処理の方法（Rust側か画面側か）、5形式の読み込み、速度と音程を別々に変える処理、鳴り始めるまでの時間。
  - 本実装：エフェクトのまとまりの管理、プレイリストの項目への結び付け、エフェクトをかけた再生。
- [x] 13. プレイリストの出力（013_プレイリストの出力）
  - プレイリストを再生したときの選曲を、エフェクトをかけた状態で、階層をフォルダにして書き出す。
