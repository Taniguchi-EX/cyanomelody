# 現在の機能の文書の整理

## 目的
`01_現在の機能` の文書を、次の3つの観点で見直して直す。
- 重複した記載：同じことを複数の文書に書いていて、片方だけ直すと食い違うもの
- 内容の正しさ：コードと合わないもの
- 詳しすぎる記載：仕様ではなく作りの細部・計測値など、文書に置かなくてよいもの

## やらないこと
- コードの変更（資料をコードに合わせる。コードの不具合が見つかったら、別の作業にする）
- 文書の構成（フォルダ・ファイルの分け方）の大きな作り直し
- `02_進行中の作業`・`03_完了した作業`・README.md の見直し

## 見直しの結果

### 1. 内容が正しくないもの（コードに合わせて直す）
- ファイルの一括操作.md の「まとめてできない操作」：出典・ライセンスをまとめて外すこと、リンク切れのまとめての「ひも付け直す」「ライブラリから外す」はできない、とある。実際は一括操作の欄でどれもできる（同じ文書の「一括操作の欄」の記述とも矛盾）。→ 節を消す。
- 出典とライセンスの管理.md の「ファイルへの設定」：「まとめて外す操作はない」。→ 一括操作の欄の「（なし）」で外せる、に直す。
- 音声のタグ管理.md の「タグの付け外し」：「まとめて外すのは、チェックの操作の行のタグのチップで行う」。チップは今、右の欄の一括操作の欄にある。→ 直す。
- 開発の手順.md
  - インストーラの場所：msi は作っていない（tauri.conf.json の bundle.targets は nsis だけ）。名前の例が 0.1.0 のまま。→ nsis だけにし、版は「<版>」と書く。
  - 「普段使うアプリはこれ」（target\release）：普段使いはインストールした版。→ 直す。
  - 画面テストの一覧と、変更したもの → 流す画面テストの対応表に、autotag.mjs（ファイルの情報からのタグ付け）と settings.mjs（設定画面）がない。→ 加える。
- 画面の構成.md の「処理の結果の表示」：裏で行う処理に、ファイルの情報からのタグ付け（一括）が入っていない。→ 加える。
- エフェクトの種類と設定.md の表：ノーマライズの目標（−40〜0dBFS）、フェードイン・フェードアウトの長さ（0〜600秒）の範囲が書いていない。→ 加える。

### 3. 詳しすぎる記載（消すか短くする）
- エフェクトの種類と設定.md の「処理の方法」：アルゴリズム（WSOLA・Catmull-Rom・Schroeder型・Linkwitz-Riley の式）と「速さの目安」の計測値。仕様ではなく作りの細部で、計測値は時間がたつと変わる。→ 「Rust 側で symphonia で読み、順にかけて16bitのWAVにする」程度にし、アルゴリズムはコードのコメントに任せる。
- 画面の構成.md の「行の並び」の開閉の印の押せる範囲（縦は行の高さいっぱい、横は字下げを含む…）。→ 「開閉の印は押しやすいよう、行の左端から印までで押せる」程度に短くする。
- 再生.md の「再生の欄」の配置の細部（狭めたときに中央を少しずつ左へずらす、ボタンを下段の右端とそろえる、スピーカーの絵の波の数など）。→ 何がどこにあるかと、狭いときに中央のボタンが隠れないことだけ残す。
- エフェクト.md の管理画面の「試聴のボタンに出す曲の名前が長いときは「…」で省く」と、幅の 1200px。→ 消す。
- 音声のタグ管理.md の文字コードの判定（WAV の INFO・ID3 の ISO-8859-1 の読み直し）。→ 「UTF-8 か Shift_JIS かを判定して読む（日本語の古いファイルのため）」程度に短くし、曲名とタグ付けの2か所の記述を1か所にする。

上の3は、仕様として残したいもの（ふるまいが変わると困るもの）は残す。迷うものは消さずに短くする。

## 前提・未決事項
- 内容の正しさは、文書の中の言い切っている事柄（数値・ボタンの名前・できる/できない）を中心にコードと照らした。文書のすべての文を確かめてはいない。整理の作業の中で、触る節はコードと照らし直す。
- 「詳しすぎる」の線引き：上の3の方針でよいか、レビューで決める。

## 結果
- 上の1〜3をすべて直した。次の2つは、もう参照の形になっていて重複が小さかったので、そのままにした。
  - 一括操作の欄の「リンク切れ」（ファイルの一括操作の側は、項目名と「ハッシュ値を使った機能」への参照だけ）
  - 長さ・リリース年をいつ調べるか（音声のタグ管理の側は「ハッシュ値を使った機能」への参照だけ）
- 開発の手順の「テストの流し方」にあった「普段使うアプリ（リリースビルド）は作業の最後に1回だけビルドする」と「リリースビルドは、普段のアプリを開いたままだと失敗する」も、普段使いがインストールした版になったので消した。
- 「ライブラリから外す」の説明に、プレイリストのそのファイルの項目も消えること（外部キーで消える）を書き足した。

## 進め方
1. この作業概要のレビューを受ける。
2. 1 → 2 → 3 の順に文書を直す（小さな作業なので、ロードマップは作らずこの一覧で進める）。
3. 直した後に、文書どうしの参照（「〜を参照」）が切れていないか確かめる。
4. 作業フォルダを `03_完了した作業` へ移す。
