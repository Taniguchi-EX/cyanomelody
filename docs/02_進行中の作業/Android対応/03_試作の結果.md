# 試作の結果

実施日：2026-11-10。試作のコードは `android-prototype` ブランチ（`app/src-tauri/src/android_proto.rs`、`app/src/AndroidProto.tsx`、`prototypes/android/`）。
実機（Android 17、arm64-v8a）に USB の有線デバッグで入れて確かめた。

## 確かめたことと結果

- 今の Rust のコードを Android 向けにビルドできるか：できる（ごみ箱と自動アップデートだけ、デスクトップ専用にした）
- SAF でフォルダを選べるか：できる（Android の標準のフォルダを選ぶ画面）
- 選んだフォルダの権限が、アプリを起動し直しても残るか：残る。アプリの更新（同じ署名での入れ直し）の後も残る
- フォルダの中の音声ファイルの列挙：できる。サブフォルダ込みで44件を約0.1秒
- ハッシュ値・長さ・曲名・ジャケットの読み取り：できる（下の「ファイルの読み方」の作り替えが要る）。ハッシュ値は Windows で計算したものと同じ（mp3・wav・flac・ogg で確認）。デバッグ版で1件あたり約75ms
- 再生（WebView の audio）：できる（下の「再生」の決まりを守る）
- 今の画面がそのまま開くか：開く（データベースも動く）。ただし狭い画面に合わない（下の「画面」）

## 分かったこと（本実装で守ること）

### ビルド
- Docker の中でビルドできる（`prototypes/android/`：JDK 17・Android SDK と NDK・Rust の Android のターゲット・Node.js のイメージ）。端末で動かすのは、Windows 側の adb から USB でつないだ実機（Docker の中からは USB の端末が見えず、Docker（WSL2）の中では KVM が使えないのでエミュレータも実用的な速さで動かない）。
- Android にないもの（`trash` クレート、自動アップデートのプラグイン）は、`Cargo.toml` の `[target.'cfg(not(any(target_os = "android", target_os = "ios")))'.dependencies]` に移し、コードは `#[cfg(desktop)]` で分ける。ほかのクレート（rusqlite の bundled、symphonia、ttf-parser など）は、そのまま通る。
- Gradle から `npm run tauri` を呼ぶので、`package.json` に `"tauri": "tauri"` のスクリプトが要る。
- APK に署名するデバッグ用の鍵（`~/.android/debug.keystore`）は、Docker のボリュームに残す。ビルドのたびに作り直すと署名が変わり、端末の上で更新できない（消して入れ直すと、選んだフォルダの権限も消える）。
- 16 KB のページサイズに合わせていない、という警告が起動のたびに出る（Android 15 以降の決まり）。本実装では、リンクのときに `-Wl,-z,max-page-size=16384` を渡すか、16 KB に合わせる NDK（r28 以降）を使う。

### SAF（フォルダの選択と読み取り）
- プラグイン `tauri-plugin-android-fs`（`protocol-content` の機能を入れる）で足りる：`Picker::pick_dir`・`persist_uri_permission`・`check_persisted_uri_permission`、`AndroidFs::read_dir`・`open_file_readable`。
- 選んだフォルダとファイルは、パスではなく `FsUri`（content:// の URI。JSON にして保存できる）で表す。ライブラリのフォルダ・ファイルの持ち方を、パスと URI の両方にする必要がある。
- ファイルの読み方：SAF のファイルは、パスから開き直せない（開いたファイルの `/proc/self/fd/番号` から開き直しても「Permission denied」）。そこで、読む処理（ハッシュ値・長さ・曲名・ジャケット）を、パスか「開いたファイル」を受け取れる形（`source::FileSource`）にした。開いたファイルは読むたびに複製（`try_clone`）して頭に戻す（複製は読む位置を共有するので、同時には読まない）。
- プラグインは `tauri::Builder` の組み立てで登録する。`setup` の中で登録すると、プラグインのプロトコル（下の「再生」）が画面に届かない。

### 再生
- `tauri.conf.json` の `plugins` に `"android-fs": { "contentProtocol": { "enable": true } }` を書き、画面では `convertFileSrc(FsUri の JSON, "android-fs-content")` の URL を audio 要素に渡す（範囲指定の読み込みにも対応している）。
- 画面から `fetch` でこの URL を読むことはできなかった（audio 要素での再生には影響しない）。

### 画面
- 今の3列の画面は、狭い画面では左の欄と中央が押し込まれ、右の欄と再生の欄の右側が見えない。作業概要のとおり、1列（欄を切り替える形）にする。
- 画面の上の端が、端末のステータスバー（時刻など）と重なる。上下の余白（セーフエリア）を取る必要がある。
- 端末がダークモードのときは、暗い配色で出る。

## 本実装に向けて
- ライブラリの登録・スキャン・ハッシュ値の計算・ジャケット・エフェクトの処理を、パスと URI の両方で動くようにする（`FileSource` を広げる）。
- 画面を1列にし、セーフエリアを取る。
- 16 KB のページサイズに合わせる。
- 書き込み（エフェクトの書き出し・プレイリストの出力）と同期は、作業概要のとおり後で決める。
