# Android対応

状態：試作を終えた（結果は `03_試作の結果.md`）。本実装の作業概要は、試作の結果をもとに作り直す。

ユーザーの離席中に、全体ロードマップの「Android対応」（試作：Storage Access Frameworkでのフォルダの登録と読み取り、アプリ再起動後もアクセスできるか）を、仮判断で作業概要にしたもの。後の作業「Androidとの同期機能」の前提になる。

## 目的
Android の端末でも、ライブラリのフォルダを登録してタグで整理し、プレイリストで再生できるようにする。

## 範囲（仮判断）
- Tauri 2 のモバイル対応で、同じ画面・同じ Rust の処理を Android 向けにビルドする。
- 最初に試作で確かめる（全体ロードマップのとおり）。
  1. Storage Access Framework（SAF）でフォルダを選び、その中のファイルを列挙・読み取れるか（Rust から読むには、content:// の URI を通す仕組みが要る）。
  2. アプリを起動し直しても、選んだフォルダに読みに行けるか（永続的な権限 `takePersistableUriPermission`）。
  3. ハッシュ値の計算・長さの読み取り・再生（WebView の audio）が、SAF のファイルでできるか。
- 画面：今の3列の画面は狭い画面に合わないので、1列（左の欄・中央・右の欄を切り替えるタブ）にする。再生の欄は下に残す。
- 試作で分かったことをもとに、本実装の作業概要を作り直す。

## やらないこと（最初の段階）
- Google Play での配布（友人に APK を渡す形を想定）。
- エフェクトの書き出し・プレイリストの出力（SAF への書き込みは、試作の後に決める）。
- Android との同期（別の作業）。

## 前提・未決事項
- 開発環境：Android の SDK・NDK は PC に直接入れず、Docker のイメージ（`prototypes/android/`）に入れる（決定）。
- 試す端末：USB の有線デバッグでつないだ実機（決定）。
- 対象の Android の版（仮判断：Android 10 以降）。
