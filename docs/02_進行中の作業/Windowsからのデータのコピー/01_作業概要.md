# Windows からのデータのコピー

状態：作業概要の確認済み（2026-11-10）。試作から始める。

## 目的
Windows で整理したタグ・プレイリストなどと、音声ファイルそのものを、まとめて Android の端末に写して使えるようにする。Windows を正とし、一方向に写す（両方向の同期は、全体ロードマップの「Androidとの同期機能」で後に行う）。

## 決めたこと（ユーザーの回答）
- 渡し方：Windows で書き出したものを、USB・Google ドライブなどで端末に置き、Android で選んで取り込む（Wi-Fi などでの直接の受け渡しはしない）。
- 取り込み方：Windows のとおりに置き換える（Android で変えた分は消える）。
- 一部の項目だけ写すこともできる。
- 音声ファイルも一緒に写せる。
- 置き場所：Android の設定画面の「データ」のタブ。
- 両方向の同期は、後で別の作業として行う（全体ロードマップに残す）。

## 流れ（仮判断）
1. Windows：設定画面の「データ」のエクスポートに「音声ファイルも入れる」を足す。入れるときは、保存先にフォルダを1つ作り、その中にデータの JSON と音声ファイルを置く（下の「書き出すフォルダの形」）。入れないときは、今と同じく JSON だけ。
2. ユーザーが、そのフォルダ（または JSON）を端末に写す（USB でのコピー、Google ドライブなど）。
3. Android：設定画面の「データ」のタブの「Windows からコピー」で、次のどちらかを選ぶ。
   - フォルダを選ぶ…：音声ファイルごと写したフォルダ。中のフォルダをライブラリに登録してスキャンし（端末の中で音声ファイルを写し直さず、置いた場所のまま使う）、データを取り込む。
   - ファイルを選ぶ…：JSON だけ。音声ファイルは、すでに端末にあり、Android でフォルダを登録してある前提。
4. 見込みを出す：書き出した日時とアプリの版、項目ごとの件数、曲がいくつ見つかるか（見分け方の内訳）、置き換えで消えるもの。
5. 写す項目を選ぶ（最初はファイルにあるものをすべて選ぶ）：タグ、プレイリストとエフェクト、出典・ライセンスと設定。
6. 「コピーする」で確かめてから、選んだ項目を置き換えで取り込む。終わったら結果を出し、データを読み直す。

## 書き出すフォルダの形（仮判断）
```
cyanomelody-YYYYMMDD/
  cyanomelody.json        … データ（今のエクスポートと同じ形）
  <ライブラリのフォルダ名>/  … 登録したフォルダごとに1つ。中は相対パスのまま
  <ライブラリのフォルダ名>/
```
- 入れる音声ファイル：書き出す曲（ライブラリを選んだときはすべて、ほかは選んだ項目に関係する曲）のうち、見つからない印のないもの。
- フォルダ名が重なるときは「名前(2)」にする（JSON に、どのフォルダが元のどのフォルダかを書く）。
- 書き出す前に、ファイルの数と合計の大きさを出して確かめる。書き出しは進み具合を出し、やめられるようにする（量が多いと時間がかかるため）。
- zip にはしない（端末で展開すると、場所を2倍使うため）。

## 写す項目（仮判断）
- タグ、プレイリストとエフェクト、出典・ライセンスと設定から選ぶ。
- ライブラリ（フォルダの登録）の項目は使わない。Windows のフォルダの場所は端末では使えないので、フォルダの登録は上の「フォルダを選ぶ」か、Android での登録で行う。
- 画面の設定は、端末で意味のあるもの（音量・再生方法・並び順・一覧の見せ方・戻す／進める秒数など）だけ写し、Windows だけのもの（左右の欄の幅・フォント）は写さない。

## 曲の見分け方（仮判断）
Windows と端末では、フォルダの場所が違うので、今のパスでの見分け方は使えない。上から順に試す。
1. フォルダの中の相対パス：ファイルの各フォルダを、端末で登録したフォルダのうち、相対パスが一番多く一致するフォルダに対応させ、そのフォルダの中で相対パスが同じ曲（大文字・小文字は区別しない）。フォルダごと写した場合は、これでほぼすべて見つかる。
2. ハッシュ値：今と同じ（端末でハッシュ値の計算が終わっている曲だけ）。
3. 名前と大きさ：今と同じ。

見つからなかった曲のタグ付け・出典・ライセンス・プレイリストの項目は写さない。見込みと結果で、見つからなかった数を出す。この見分け方は、今回は Android の取り込みだけに使う。

## やらないこと
- Android からのエクスポート、Android → Windows のコピー、両方向の同期。
- Wi-Fi などでの直接の受け渡し。
- 2回目以降のコピーで、変わった音声ファイルだけを写す（差分）。2回目は、書き出したフォルダを丸ごと写し直すか、JSON だけを写す。

## 2回目以降のコピー（ユーザーの回答）
- 音声ファイルは、置いた場所のままライブラリとして使う（アプリの中の場所へ写し直さない）。
- 前に写したフォルダと同じ場所に上書きしたときは、そのまま再スキャンする。
- 別の場所に写したときは、前に写したフォルダの登録を外すか聞く。
