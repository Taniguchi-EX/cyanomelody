# ファイル内の情報による自動タグ付け

状態：実装検討中（中断。2026-11-05。前段として「一括操作の欄」（作業29）を先に行った）

## 目的
音声ファイルの中の情報（ID3 などのタグ情報。アーティスト・作曲者・アルバム・ジャンル・年など）をもとに、タグを自動で付ける。

## これまでの検討
今のライブラリの曲を調べた結果は `01-01_既存の曲の調査.md` にまとめた。要点は次のとおり。
- 情報が入っているのは、およそ半分の曲（アーティスト・アルバム・ジャンルはそれぞれ約47%、作曲者は約29%、年は約26%）。どれも入っていない曲も約半分ある。
- 日本語の値の多くは Shift_JIS で書かれていて、そのまま読むと化ける。作業23の読み直し（UTF-8 → Shift_JIS）で正しく読める。
- 表記ゆれ（「一之瀬剛」と「一之瀬 剛」など）、複数の名前が1つの値になったもの（「清水依与吏/back number」）、意味のない値（「Unknown」「アーティスト情報なし」など）、アルバム名のディスク番号（「[Disc 2]」）、ばらばらなジャンル名（「サウンドトラック」「Soundtrack」「SCREEN MUSIC(SOUND TRACKS)」など）の整理が要る。
- 今のタグの体系（「作者・グループ」「音楽ジャンル」「関係IP」「アルバム」など）に合わせて付ける。
- 「関係IP」はファイルの中の情報からは分からないが、フォルダの構成（「ゲーム音楽/ポケモン」など）が近い形になっている。
- 全体ロードマップの「音声の指紋による自動タグ付け」とは、この作業を先に行い、情報のない曲だけを指紋で調べる組み合わせがよい。

## 未決事項（再開したときに決める）
1. 対象にする項目：アーティスト、作曲者、アルバム、ジャンル、年のどれにするか。年を使うなら、タグの体系に新しい親（「年」など）を作るか。
2. 付け方：すぐに付けるか、候補の一覧を出して選んでから付けるか（表記ゆれがあるので、確かめてから付けるのがおすすめ）。対象を一括操作の欄（チェックしたファイル）から選べるようにするか。
3. 表記ゆれ・意味のない値・ジャンルの対応の扱い：アプリに決まった規則を持たせるか、別名の表を谷口さんが編集できるようにするか。
4. 今のタグとの対応：同じ名前（大文字・小文字の違いを含む）は今のタグに付ける。ない名前のタグを新しく作るか、確かめてから作るか。どの親の下に作るか。
5. フォルダ名から「関係IP」を付ける機能も入れるか。
