# セルフレビュー

## 仕様と食い違うところ（作業概要と照らした）
- 選ぶ・外す・切り替え、ダブルクリック、抽選（🎲・🔀・同じ曲の2行）、抽選し直すきっかけ、再生中に抽選し直したときの停止：実装した。
- 中央の一覧：見出し、絞り込み、並び順（別々に覚える・プレイリストの順・別名での名前順）、別名の曲名と検索、来た項目のアイコン（説明・押すと編集画面のその行）、単位（曲・ファイル）、チェックはファイルごと：実装した。
- 左の欄の件数（通しの曲数・0曲はグレーアウト）、タグなどの件数は行の数：実装した。
- 再生：選んでいる間はプレイリストとして（項目の fx・別名）、最後まで再生した後の「▶」で抽選し直す、行の「▶」では抽選し直さない、編集画面の「▶ 再生」：実装した。
- 再生の欄の曲名、右の欄・一括操作の欄のチップから編集画面：実装した。
- 編集画面：重ねて出す、閉じる・Esc、名前の変更、項目の「✎」で別名、タグの入力欄で組み合わせ、項目のチェック（外す・fx・再生方法）、書出：実装した。項目の詳細の欄と、項目の曲への一括操作は外した。
- 書出：中央の一覧の行（見えている順）を、通った項目でフォルダに分けて書き出す。選んでいなければ選んでから：実装した。
- 作りの方針（抽選した並びは Rust 側の一時テーブル、別名・fx は写さず今の項目から引く、中身の版で抽選し直すかを1か所で判断、行の形をそろえる、展開の処理で数える、乱数の種、フック）：そのとおりにした。

## 見つけて直したこと
1. 選んでいるプレイリストの行をダブルクリックすると、1回目の押しで選択が外れる（作業概要の「2回目の押しは無視」だけでは防げない）。→ 選んでいる行を押したときは0.3秒待ってから外し、その間にダブルクリックが来たら外さないようにした（仮判断の一覧の3）。
2. 編集画面（重ねて出す画面）が再生の欄まで覆い、開いている間に再生を止められない。→ 再生の欄と一番下の行を重ねて出す画面より上に出し、編集画面の高さを再生の欄に重ならないようにした（仮判断の一覧の2）。
3. 選んでいないプレイリストの編集画面から「▶ 再生」・書出をすると、ライブラリの並び順で一覧を読んでいた。→ 選んだばかりのときは、プレイリストの並び順で読むようにした。
4. 項目の別名の入力欄と、その「✎」のボタンの名前が前方一致で重なり、画面テストで見分けにくい。→ 画面テストでは exact で探す（画面の名前はそのまま）。

## 不具合がないか（確かめたこと）
- 空のとき：まだ抽選していないとき・選択を外した後は、一時テーブルを空にし、抽選した並びで絞り込むと0件になる（`ensure_table`）。0曲のプレイリストは選べないが、編集画面は開ける。
- 消えたもの：削除したファイルの行は、一覧を読むときに audio_files とつなぐので出ない。削除したエフェクトセットは、別名・fx を今の項目から引くので残らない。選んでいるプレイリストの削除・データの取り込みは、読み直しのときの `refresh_draw` で選択を外す。
- 同時の操作：抽選の状態（AppState.draw）は DB の後にロックする（ロックの順をそろえた）。
- 同じ曲が2行：鳴らしている印・右の欄に出す行・↑↓・曲名から移る先は行の番号（key）で見分ける。チェックと一括操作はファイルの id のまま。Shift でのチェックの起点はファイルなので、同じファイルの最初の行を起点にする（困らない）。

## 既存の機能を壊していないか
- ライブラリの一覧は key = ファイルの id なので、今までと同じ動き（tag-management・bulk・facets ほかの画面テストは成功）。
- 項目の再生（編集画面の種類の記号）は今までどおり項目を展開して鳴らす。
- 書出の Rust 側の古い計画（`plan_export`）は使わなくなったので外し、単体テストを抽選した並びのものに書き直した。
- 使わなくなった部品（右の欄の項目の詳細 `ItemDetail.tsx`）と見た目の定義を消した。

## 書き方
- 抽選した並びの Rust の処理は `playlists/draw.rs` にまとめ、単体テストは `draw_tests.rs` に分けた。画面側はフック `usePlaylistSelection` に分けた。
- 行の来た項目の説明の関数は、部品のファイル（FileList.tsx）から `playlistItem.ts` に移した（lint の「部品のファイルは部品だけを出す」に合わせる）。
