# プレイリストの絞り込み化

状態：作業概要は承認済み（ロードマップは未作成）。作業「再生の欄のエフェクトの表示」の後に行う。

## 目的
今の画面には、次の2つの問題がある。
- 左の欄の中で「プレイリスト」だけが絞り込みの条件になっていない。行を押すと、中央が詳細画面に切り替わる。
- ライブラリの一覧とプレイリストの詳細画面の切り替えが分かりにくい。プレイリストを開いている間も左の欄の絞り込みを操作でき、隠れているライブラリの一覧にだけ効く。戻るのは、詳細画面の左上の「＜」だけ。

プレイリストを、ほかの欄と同じ「押すと絞り込む」条件にし、中身の編集は別の画面（編集画面）に分けて、この2つを解く。

## 要件（決まったこと）

### プレイリストの選択と抽選
- 左の欄のプレイリストの行を押すと、そのプレイリストを選ぶ。選ぶと、その時点でプレイリストを1回展開し、再生する曲の並びを決める（以下「抽選」、決まった並びを「抽選した並び」）。
  - 🎲（ランダムセレクト）の項目は、ここで1曲を選ぶ。🔀（シャッフル）の項目は、ここで順番を決める。
  - 展開の中身は今と同じ。タグの組み合わせ・子・参照の中身も含め、親のプレイリストを選んだときは子の中身も含む。見つからないファイルは除く（🎲の候補にも入れない）。
  - 同じ曲が何度出てもよく、出た回数だけ一覧に行を出す。
- プレイリストは1つしか選べない。別のプレイリストを押すと、そちらに切り替わる（抽選する）。同じ行をもう一度押すと外れる。
  - ダブルクリック（編集画面を開く）の2回目の押しは、選択の切り替えに使わない（1回目で選んだまま、編集画面を開く）。
- 抽選し直すのは、次のときだけ。
  - 同じプレイリストを選び直したとき（一度外して、また選んだとき）
  - 一覧を最後まで再生した後に、再生の欄の「▶」でもう一度再生したとき
  - プレイリストを編集したとき（中身は下の「現在の想定」の「抽選し直すきっかけ」）
- 抽選し直さないもの
  - 途中で止めてから再生したとき
  - 最後まで再生した後に、一覧の行の「▶」で再生したとき
- 再生している最中に抽選し直したとき：鳴っている曲が🎲・🔀の項目から来た曲（抽選の結果で変わりうる曲）なら再生を止め、ファイルの項目・順に再生の項目から来た曲ならそのまま鳴らし続ける。
- 見出しの横の「🎲 引き直す」のボタンや、抽選したことを示す表示は、今回は作らない。

### 中央の一覧
- プレイリストを選んでいる間は、中央の一覧に抽選した並びを出す。見出しの「ライブラリ」は、プレイリストの名前にする。
- タグ・出典・ライセンス・その他などの絞り込みは、抽選した並びに対してかける。ほかの条件を選んだままプレイリストを選んだときは、ほかの条件は残す。
- 並び順のプルダウンは使える。「プレイリストの順」（抽選した順）を加える。並び順は、ライブラリとプレイリストで別々に覚え、プレイリストの初期値は「プレイリストの順」。
- 曲名は、ファイルの項目の別名（プレイリスト上での名前）を先に出す。タグの組み合わせなど、複数のファイルが対象になる項目から来た曲は、ファイル名のまま。
  - ファイル名の検索は、別名とファイル名のどちらかに当てはまれば出す。
  - 並び順の「ファイル名順」は、出している名前（別名を含む）で並べる。
- 各行の再生ボタンの右に、どの項目から来た曲かのアイコンを出す。
  - タグの組み合わせの項目：タグのアイコン
  - プレイリストの項目（子・参照）：プレイリストのアイコン。選んだプレイリストの直下の項目を指す。例：A（選んだもの）→ 子B → 子C の中の曲は、Bを指す。Bの中のタグの組み合わせから来た曲も、Bを指す（プレイリストのアイコン）。
  - ファイルの項目として直に入れた曲：アイコンなし
  - マウスを乗せると説明の文を出す（「タグの組み合わせ「雨 ＋ 風」（🎲 1曲）から」「プレイリスト「足音」（🔀 シャッフル）から」）。エフェクトセットの名前は添えない。
  - 押すと、選んでいるプレイリストの編集画面を開き、その項目の行を選んだ状態にする。
- 行そのものに、エフェクトがかかることを示す印は付けない。
- 一番下の行の件数は、行の数（同じ曲が2回出れば2）。
- チェックはファイルごと。同じファイルの行には、そろってチェックが付く。チェックの件数はファイルの数。
- 数え方の違いが分かるよう、プレイリストを選んでいる間は、一番下の行の単位を変える（一覧は「12曲」、チェックは「チェック 3ファイル（表示中 2ファイル）」）。ライブラリの一覧では、今どおり「件」。
- 抽選した後に見つからなくなった曲（スキャンで印が付いた曲）は、行に残し、ライブラリの一覧と同じく取り消し線を引く。再生では飛ばす。

### 左の欄の件数
- プレイリストの行の件数は、そのプレイリストを通しで流したときに鳴る曲の数（🎲の項目は1曲と数える）。ほかの条件を選んでいても変えない。0曲のプレイリストだけグレーアウトする。
- プレイリストを選んでいる間の、タグなどの欄の件数は、抽選した並びの中の行の数。
- 「重複しているファイル」の条件は、今の決まり（ライブラリ全体で同じハッシュ値の曲が2件以上）のまま。同じファイルが2行出ていることは、重複とは別の扱い。
- 「（プレイリストなし）」の行は作らない。

### 再生
- プレイリストを選んでいる間は、プレイリストとして再生する。中央の一覧（絞り込んだ結果を、見えている順に）を鳴らし、各曲に項目のエフェクトセットをかける。
- 行の「▶」・ダブルクリックはその行から、再生の欄の再生方法（一曲だけ・順に連続・ランダム・ランダムセレクト）は一覧の上にかける。今のライブラリの一覧と同じ。
- 編集画面にも再生ボタンを置く。押すと、そのプレイリストを選んだ状態にして（選んでいなければ選んで抽選し）、中央の一覧を頭から再生する。ほかの絞り込みがあれば、それもかかる。
- 編集画面の項目ごとの再生（種類の記号の ▶）は、今のまま残す。

### 再生の欄の曲名を押したとき
- 再生しているプレイリストを選んでいれば、中央の一覧のその行へ移り、右の欄に出す。その曲が今の一覧にないとき（絞り込みで隠れている・抽選し直した）は、そのことを下の行に出す（ライブラリの一覧と同じ扱い）。
- 選んでいなければ、そのプレイリストの編集画面を開き、その項目の行を選ぶ（選び直すと抽選し直しになるため、選び直さない）。

### 編集画面
- プレイリストの中身（項目・再生方法・fx・別名）の編集は、編集画面で行う。中央の一覧は、いつも絞り込んだ曲の一覧になる。
- メインの画面に重ねて出す（エフェクトの管理画面と同じ形）。「閉じる」と Esc で閉じる。開いている間は、ライブラリの一覧からファイルを足せない（左の欄の行へのドラッグは、編集画面を閉じてから行う）。
- 開き方
  - 左の欄のプレイリストの行の「✎」と、行のダブルクリック。名前の変更は、編集画面の中へ移す。
  - 右の欄のファイルの詳細の「プレイリスト」の欄の「📃 名前」のチップの名前を押したとき。そのファイルの項目の行を選んだ状態で開く。一括操作の欄の「プレイリスト」の「外す」のチップの名前も同じ。
  - 中央の一覧の行のアイコンを押したとき（上の「中央の一覧」）と、再生の欄の曲名を押したとき（上の「再生の欄の曲名を押したとき」）。
- 項目の詳細（別名・中身・曲のリスト）を出す欄は、今回は設けない（今は右の欄に出している）。
- 項目のチェックでできる操作は、項目を外す・fx を付ける・再生方法を変えるだけにする。今の「一括操作」（項目の曲へのタグ付けなど）は外す。
  - 🎲の項目の候補すべてにまとめて操作したいときは、ライブラリの一覧をそのタグで絞り込んで行う（タグの組み合わせの項目の候補は、そのタグでの絞り込みと同じ）。
- プレイリスト上での名前（別名）は、編集画面でだけ直せる（右の欄では直さない）。項目の行ごとに「✎」（別名を付ける）のボタンを置き、押すと名前が入力欄になる。Enter で決め、Esc でやめる。空にして決めると外れる。
- 項目の行のダブルクリックは、今どおりその項目を再生する。
- タグの組み合わせの項目は、編集画面の中のタグの入力欄で加える（今の「選択タグをリストに追加」の代わり）。右の欄の「付けるタグ」と同じ入力欄でタグを1つずつ選んでチップとして並べ、「追加」で、並べたタグの組み合わせの項目を加える。
- 書出は編集画面に置く（今の一番下の行と同じ）。

### 書出
- 抽選し直さず、今中央の一覧に出ている曲（抽選した並びに絞り込みをかけ、見えている順に並べたもの）を書き出す。
- そのプレイリストを選んでいないとき（右の欄のチップなどから編集画面を開いたとき）は、書出を始めるときに、そのプレイリストを選んだ状態にして（抽選して）から、その一覧を書き出す。
- フォルダの分け方は、各行の「項目のたどり方」で今と同じように分ける（順に再生の子はフォルダ、🔀・🎲の子は展開して並べる）。フォルダの中は、一覧の見えている順に番号を付ける。
- 絞り込みで1曲もなくなったフォルダは作らない。同じ曲が2回出れば、2回書き出す。

### 再生の欄のエフェクトの表示
- 別の作業「再生の欄のエフェクトの表示」で行う。

### 「入っている」の意味
- プレイリストで絞り込んだときの一覧：展開した中身（タグの組み合わせ・子・参照の中身まで）。
- 右の欄の「📃」のチップ・一括操作の欄の「プレイリスト」の「外す」：ファイルの項目として直に入れたものだけ（今のまま）。
- 資料にも、この2つを書き分ける。

## 作りの方針
- 抽選した並びは Rust 側の状態として持つ（データベースには入れず、アプリを閉じると消える）。中身は、行の番号・ファイル・項目のたどり方（選んだプレイリストから、どの項目を通って来たか）。
  - 絞り込みの条件には「抽選した並び」を指す印だけを入れる。絞り込み・件数・並べ替えは、SQL で抽選した並び（一時テーブル）とつないで、今の作りのまま1か所で行う。
  - 別名とかけるエフェクトセットは、抽選した並びに写して持たない。表示・再生のときに、項目のたどり方から今の項目を引く（別名・fx を変えたり、エフェクトセットを削除したりしても、ずれない）。
- 抽選し直すかどうかは1か所で判断する。Rust 側が「プレイリストの中身の版」（そのプレイリストと、その中に入っているプレイリストの項目・再生方法から作る値）を返し、データを読み直すたびに比べて、変わっていれば抽選し直す。
- 一覧の行は、ライブラリの一覧もプレイリストの一覧も、同じ「行」の形（行の番号・ファイル・項目のたどり方）で表す。ライブラリの一覧は「項目のない行」。右の欄・鳴っている印・↑↓・Shift でのチェックなどは、この形で1通りに書く。
- 通しの曲数（プレイリストの行の件数）は、展開の処理（`playlists/expand.rs`）に「数えるだけ」の形を持たせて求める。展開の決まりと数え方がずれないようにする。
- 画面テストのため、環境変数で抽選の乱数の種を決められるようにする。
- 画面側の、プレイリストの選択・抽選・抽選し直しは、1つのフックに分ける（App.tsx を大きくしない）。

## 現在の想定（任された点・細部）

### 抽選し直すきっかけ
- 抽選し直す：選んでいるプレイリストか、その中に入っている（子・参照の）プレイリストの、項目の追加・削除・並べ替え・再生方法の変更（子の移動、ドラッグでの追加、タグの統合・削除でタグの組み合わせの項目が変わったとき、データの取り込みを含む）。上の「プレイリストの中身の版」が変わったときにあたる。
- 抽選し直さない：別名の変更、項目の fx の変更、プレイリストの名前の変更、エフェクトセットの中身の変更（どれも表示・再生のときに今の値を引くので、そのまま効く）。
- タグの付け外しでは抽選し直さない（一覧が勝手に変わらないように）。削除したファイル・ライブラリから外したファイルの行は消す。ひも付け直しでファイルが付け替わったときは、抽選し直す。

### そのほか
- プレイリストの選択は、アプリを閉じると覚えていない（ほかの絞り込みの条件と同じ）。
- 選んでいるプレイリストを削除したときと、データの取り込み（置き換え）で消えたときは、選択が外れてライブラリの一覧に戻る。
- 「最後まで再生した」は、順に連続・ランダムで、再生の順番の最後の曲が終わったとき。一曲だけ・ランダムセレクトで1曲鳴らして止まったときは含めない。

## 懸念点
- 性能：プレイリストの行の件数（通しで流したときの曲数）を、データが変わるたびにすべてのプレイリストについて数える。抽選した並びとつないだ絞り込み・件数の計算。数万曲・大きなタグの組み合わせの項目で重くならないか。試作して計測してから、計算の方法を決める。
- 一覧の作りの変更：今の一覧は、右の欄に出す行・鳴らしている行の印・キーボードの↑↓・Shift でのチェック・再生の欄の曲名から移る先などを、すべてファイルの id で見分けている。「行」の形にそろえる直しが広い。
- 再生方法「ランダム」で再生したときと、抽選した🔀の項目の並べ替えが重なる。動きとしては問題ないが、どちらの並べ替えか分かりにくいかもしれない。
- プレイリストを組み立てる作業（絞り込んで探す → 加える → 中身を直す）は、編集画面を閉じたり開いたりするので、今より手数が増える。今回は受け入れ、使ってから見直す。
- 画面テスト（playlists・effects・export・bulk・facets・perf・layout）、資料（プレイリスト・プレイリストの出力・再生・エフェクト・画面の構成・ファイルの一括操作・音声のタグ管理）、README の画像の書き直しが大きい。
