# ロードマップ

ユーザーが離席中のため、判断が必要な所は仮判断で進め、`01-01_仮判断の一覧.md` に記録する。

## 1. 試作と計測（Rust）
- [ ] 展開の処理（`playlists/expand.rs`）で、各曲が通った項目のたどり方（外側から内側の項目 id）を持つようにする
- [ ] 抽選した並びを一時テーブル（`temp.draw_rows`：行の番号・ファイル・たどり方・別名を引く項目・抽選で変わりうる曲か）に入れ、絞り込み（`filter_conditions`）と件数（`facets`）を、そこにつないで行えるようにする
- [ ] 計測用のテスト（`--ignored`）：3万件・大きなタグの組み合わせを含むプレイリストで、抽選・一覧・件数・全プレイリストの通しの曲数の時間を測り、`テスト/試作結果.md` に記録して計算の方法を決める

## 2. Rust 側の本実装
- [ ] 抽選の状態（選んでいるプレイリスト・中身の版）を AppState に持ち、選ぶ・外す・抽選し直す・中身の版を比べて抽選し直す（`refresh`）のコマンドを作る
- [ ] 乱数の種を環境変数（`CYANOMELODY_DRAW_SEED`）で決められるようにする
- [ ] 一覧（`list_files`）：抽選した並びのときは行ごとに返す（行の番号・別名・来た項目・かけるエフェクトセット・抽選で変わりうる曲か）。ファイル名の検索は別名にも当てる。並び順に「プレイリストの順」を加え、「ファイル名順」は出している名前で並べる
- [ ] 件数：抽選した並びのときは行の数で数える
- [ ] プレイリストの行の件数を、通しで流したときの曲数にする（`count_items`）
- [ ] 書出：渡された行（見えている順）から、項目のたどり方でフォルダに分けて書き出す
- [ ] 単体テスト（抽選・たどり方・中身の版・一覧・件数・書出のフォルダ分け）

## 3. 画面側の本実装
- [ ] 一覧の行を「行」の形（行の番号とファイル）にそろえる（右の欄・鳴っている印・↑↓・Shift でのチェック・再生の欄の曲名から移る先）
- [ ] プレイリストの選択のフック（`usePlaylistSelection`）：選ぶ・外す・抽選し直す・データを読み直した後の `refresh`・再生中に抽選し直したときの停止
- [ ] 左の欄のプレイリスト：押すと選ぶ（もう一度で外す。ダブルクリックの2回目は無視）、ダブルクリックと「✎」で編集画面、件数は通しの曲数、0曲はグレーアウト、条件のチップ「📃 名前」
- [ ] 中央の一覧：見出しをプレイリストの名前に、並び順（ライブラリとプレイリストで別々に覚える）、曲名に別名、来た項目のアイコン（説明・押すと編集画面のその行）、一番下の行の単位（曲・ファイル）
- [ ] 再生：プレイリストを選んでいる間は行ごとのエフェクトをかけ、最後まで再生した後の「▶」で抽選し直す
- [ ] 編集画面：重ねる画面にする（閉じる・Esc）、名前の変更、項目の「✎」で別名、タグの入力欄で組み合わせを加える、再生ボタン、書出、項目のチェック（外す・fx・再生方法）。項目の詳細と一括操作を外す
- [ ] 右の欄の「📃」のチップ・一括操作の欄の「外す」のチップの名前と、再生の欄の曲名から、編集画面を開く
