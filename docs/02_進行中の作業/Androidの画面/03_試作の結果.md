# 試作の結果

実施日：2026-11-10。試作のコードは `android-ui-proto` ブランチ（`app/src/MobileProto.tsx`。本実装では作り直す）。
実機（Android 17、画面は CSS で 411×923 ピクセル、dpr 2.625）で確かめた。3つとも、作業概要の作り方のままで作れる。

## 端末の戻る操作
- 画面を開くたびに `history.pushState` で履歴に積み、`popstate` で画面を戻す形で動く。3段積んで、戻る操作を3回すると1つずつ戻った。
- 履歴が一番上のときに戻る操作をすると、アプリが閉じる（ホーム画面に戻る）。Android の決まりどおりで、別の作りは要らない。

## セーフエリア
- `index.html` の viewport に `viewport-fit=cover` を足すと、CSS の `env(safe-area-inset-*)` で大きさが取れる（上 66・下 24・左右 0 ピクセル）。
- 画面の一番上と一番下を、ステータスバー・ナビゲーションバーに隠さずに出せた。

## 長押ししてからのドラッグ・スクロール・下へのスワイプ
- 普通のスクロール（指をすぐに動かす）は、行の上からでも動く。
- 長押ししてからのドラッグは、次の形で動いた（項目を4つ下へ動かせた。その間、一覧はスクロールしない）。
  - 行は `touch-action: pan-y`（縦のスクロールは許す）にしておく。
  - 指を置いて 350ms 動かなければ、ドラッグを始める（8 ピクセルより動いたら、スクロールとみなして長押しをやめる）。
  - ドラッグを始めた後の `touchmove` を `preventDefault` で止める（スクロールにさせない）。React の `onTouchMove` は止められない（passive）ので、要素に直に `addEventListener("touchmove", …, { passive: false })` で登録する。
  - 止めないと、指を動かした時点でブラウザがスクロールとして引き取り、`pointercancel` になる（最初の形ではこうなった）。
  - 長押しで出る端末の選び肢（文字の選択など）を出さないよう、`user-select: none` と `contextmenu` の `preventDefault` をする。
- 下へのスワイプ（全画面の再生を閉じる）：`pointerdown` と `pointerup` の縦の差（120 ピクセルより下）で閉じられた。全画面の側は `touch-action: none`。
- 再生エリア（小）を押して全画面を開く操作も動いた。

## 確かめ方のメモ
- 長押ししてからのドラッグは、`adb shell input draganddrop x1 y1 x2 y2 時間` で試せる（指を置いてしばらく待ってから動かす）。普通のスクロールは `input swipe`。
