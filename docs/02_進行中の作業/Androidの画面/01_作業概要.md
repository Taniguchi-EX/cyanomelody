# Android の画面

状態：実装中（作業概要とロードマップは承認済み。試作は済み）。

## 目的
Android の端末（縦長の狭い画面）で、cyanomelody を使えるようにする。内部の処理（フォルダの登録・スキャン・ハッシュ値・タグ付け・再生）は作業49で Android でも動くようにしたので、この作業では画面を作る。

## 前提（作業49までで分かっていること）
- 今の画面（左・中央・右の3列と、下の再生の欄）は、Android でもそのまま開くが、狭い画面に押し込まれて使えない。
- 画面の上の端が、端末のステータスバー（時刻など）と重なる。
- Android では使えない操作がある（ファイルの削除・エクスプローラーで見せる・ファイルを1つ選んでのひも付け・自動アップデート・フォントの一覧・データの入出力・書き出し）。今はエラーで知らせているだけ。
- 確かめる端末：USB の有線デバッグでつないだ実機（縦 2424 × 横 1080 の画面、Android 17）。

## 範囲
- 画面の遷移：`01-01_画面遷移.md` のとおり。動的エリア（ファイルの一覧・絞り込み・ファイルの詳細・一括操作・プレイリストの編集を切り替える）と、再生エリア（小。押すと全画面の再生）の2つ。
- 各画面のレイアウト：`01-02_画面のレイアウト.md` のとおり。
- セーフエリア（ステータスバー・ナビゲーションバーの分を空ける）。
- 端末の戻る操作（ジェスチャー・戻るボタン）で、開いた順に戻る。
- 指での操作：長押しでチェックを始める（ファイルの一覧）、長押ししてからドラッグで並べ替える（絞り込みの行・編集画面の項目）、下へのスワイプで全画面の再生を閉じる。
- Android で使えない操作を、画面に出さない。

## 作り方（仮判断）
- Windows の画面は変えない。Android のときだけ、別の画面の組み立て（`MobileApp` など）を使う。
- データ・読み直し・操作（今の `App.tsx` の状態と、hooks の操作）は、Windows と Android で共有する。そのため、`App.tsx` の「状態と読み直し」を1つのフックに分け、Windows の画面の組み立てと Android の画面の組み立ての両方から使う。
- 欄の中身の部品（タグの入力、プレイリストの選び肢、ファイルの一覧の行、エフェクトの管理など）は、できるだけ今の部品を使い、狭い画面のための違いは CSS と、部品の小さな切り替えで吸収する。
- 端末の戻る操作は、画面を開くたびにブラウザの履歴に積み、戻る操作で取り出して画面を戻す形にする（Tauri の Android では、WebView に戻れる履歴があるとき、戻る操作は履歴を戻す。最初に試作で確かめる）。

## やらないこと
- Windows の画面の変更。
- データの入出力・同期（「Androidとの同期機能」で行う）。
- 横向きの画面・タブレット向けのレイアウト（まず縦向きのスマートフォン）。
- 配布（リリース版の署名・Release への APK の追加）。

## 確かめ方
- Windows：check.sh all がそのまま通ること（画面は変えない）。
- Android：実機で、画面ごとの操作と遷移・戻る操作・セーフエリアを確かめ、画面の写真を `テスト/` に残す。操作は開発者ツール（Playwright）と adb で行う。
