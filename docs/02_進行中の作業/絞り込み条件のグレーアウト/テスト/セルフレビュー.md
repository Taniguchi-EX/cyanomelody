# セルフレビュー

テストの前に、実装を作業概要と突き合わせ、コードを見直した。

## 作業概要との突き合わせ

作業概要の仕様の項目ごとに確かめ、すべて実装されていた。
- 各項目の「選んだときの件数」
  - タグ：いまの条件（「タグなし」を除く）に合うファイルのうち、そのタグか子孫のタグが付いたもの
  - 出典・ライセンス：同じ欄の条件を除いた条件に合うファイルのうち、それが設定されたもの
  - 「なし」の項目：同じ欄の条件を除いた条件に合うファイルのうち、タグ（出典、ライセンス）がないもの
- 「ほかの条件」に、ファイル名、見つからないファイルだけ、重複しているファイルだけ、同じ音声、チェックしたファイルだけを含める（一覧の読み込みと同じ条件を渡している）
- 件数が0の項目のグレーアウトと、押しても選べないこと。選んでいる項目は0件でも外せる
- 条件がないときも0件の項目はグレーアウトする
- 管理のボタン、開く・たたむの印、並べ替えの取っ手はグレーアウトしない
- 絞り込みの条件やデータが変わったときに求め直す（一覧の読み込みと同時に求める。データを変える処理の後は一覧を読み直すので、件数も求め直される）。ファイル名の入力中は、一覧と同じく少し待つ

## 実装中に変えた点

- 「（タグなし）」「（出典なし）」「（ライセンスなし）」の行にも件数を出すようにした。これまでは件数を出していなかったが、グレーアウトの理由が分かるように、ほかの項目とそろえた。
- 試作の結果、件数はSQLで条件に合うファイルを取り出し、タグの条件と数えるのはメモリの上で行う方法にした（`試作結果.md`を参照）。

## 見つけて直した問題

1. ファイルの一括操作の作業で入れた、チェックしたファイルの内訳を求める処理で、チェックがなくなったときに画面の状態を同期的に書き換えていた（lintの警告）。チェックがないときは一括操作の欄を出さないので、内訳を消す必要はなく、求めないだけにした。
2. 左のタグの一覧のコードで、グレーアウトの判定を加えたときに字下げが崩れていた。直した。

## 確かめて問題がなかった点

- 件数は、単体テストで、いくつかの条件（タグ、親のタグ、タグなし、出典、出典なしとファイル名、チェックしたファイル、タグと出典、タグなしとライセンスなし、存在しないライセンス）について、各項目を実際に選んで絞り込んだ件数と一致することを確かめている。
- 件数をまだ求めていないとき（起動直後）は、これまでどおりの総数を出し、グレーアウトしない。
- 一覧と件数は同時に求めるので、操作のたびの待ち時間は、一覧の読み込みとほぼ変わらない（試作で、件数の計算は3万件で60ms以下）。

## 気づいたが直さなかった点

- 「（タグなし）」は、選ぶとタグの選択が外れるので、タグの条件を外して数える。そのため、タグで絞り込んだ結果が0件でも「（タグなし）」は選べることがある。作業概要どおり。
- 既存の画面テストのうち、0件になる条件を押して0件になることを確かめていたもの（credits.mjsのC13）は、グレーアウトして選べないことを確かめる形に直す。
