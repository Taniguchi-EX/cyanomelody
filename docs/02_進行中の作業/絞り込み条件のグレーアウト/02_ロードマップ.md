# ロードマップ

「タグの階層構造」と「ファイルの一括操作」の作業の後に行う。

## 1. 試作
- [ ] 3万ファイル・数百タグ（階層あり）のデータで、すべての項目の「選んだときの件数」を求める処理を作り、時間を測る（目安：0.2秒以内）
  - 求め方の案：いまの条件から同じ欄の条件を除いたファイルの集合を作り、タグ（子孫を含む）・出典・ライセンスごとに数える
- [ ] 結果を`テスト/試作結果.md`にまとめる。目安を超えるときは求め方を見直す

## 2. 本実装（Rust側）
- [ ] 絞り込みの条件を受け取り、タグ・出典・ライセンスの各項目と「なし」の、選んだときの件数を返す処理
- [ ] 単体テスト（タグはAND・子孫を含む、出典・ライセンスはORで同じ欄の条件を除く、ほかの条件との組み合わせ）

## 3. 本実装（画面）
- [ ] 絞り込みの条件やデータが変わったときに件数を求め直す（ファイル名の入力中は少し待つ）
- [ ] 左の欄の各項目の件数を「選んだときの件数」にし、0件の項目をグレーアウトして選べないようにする（選んでいる項目は外せる）

## 4. セルフレビュー
- [ ] 実装を作業概要と突き合わせ、抜けや食い違いがないか確かめる
- [ ] コードを見直す（不具合、エラーの扱い、既存の機能への影響、既存のコードとの書き方のそろい方）
- [ ] 見つかった問題を直し、内容を`テスト/セルフレビュー.md`に記録する

## 5. テスト
- [ ] テストケースを`テスト/テストケース.md`にまとめる
- [ ] 単体テストを実行する
- [ ] Playwrightで画面のテスト（`e2e/facets.mjs`）を実行し、結果を`テスト/テスト結果.md`にまとめる。3万件で条件を変えたときの速さも測る
- [ ] ほかの画面テストも実行し、壊れていないことを確かめる（件数の表示が変わるため、必要ならテストを直す）

## 6. 仕上げ
- [ ] `01_現在の機能`に反映する（新しく「絞り込み条件のグレーアウト」の機能のフォルダを作るか、「音声のタグ管理」の絞り込みに書き足すかは、反映のときに分量を見て決める）
- [ ] 全体ロードマップにチェックを入れる
- [ ] 作業フォルダを`03_完了した作業`へ移動する
