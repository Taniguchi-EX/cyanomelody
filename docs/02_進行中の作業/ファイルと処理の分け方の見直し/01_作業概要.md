# ファイルと処理の分け方の見直し

状態：完了（2026-11-10）

## 目的
コードのリファクタリング（ユーザーの依頼）。次の2つの観点で見直す。
- ファイルや処理の分け方は正しいか
- 長すぎるファイルは、役割で分けられないか

## 範囲
- 画面：App.tsx（1521行）の操作を、役割ごとのフックに分ける（App は状態・読み直し・画面の組み立てに絞る）。中央の一覧の見出しの行を部品に分ける。api.ts（585行）を呼び出し・型・選び肢・文に、PlaylistEditor.tsx（529行）の項目の行と項目を加える欄を部品に分ける。
- Rust：
  - lib.rs（1154行）の Tauri のコマンドを、役割ごとのファイル（commands/）に分ける（lib.rs は状態と起動だけにする）。
  - transfer.rs（1239行）を、ファイルの形式・書き出し・取り込みに分ける。
  - playlists/mod.rs の項目の操作を items.rs に分ける。
  - 単体テストが本体と同じくらい長いファイル（playlists/mod.rs、tags.rs、files.rs）は、テストを別のファイルに分ける（draw_tests.rs と同じ形）。
- 動きは変えない。

## 確かめ方
型チェック・lint・ビルドを周ごとに、テスト（check.sh all）は最後に1回。
