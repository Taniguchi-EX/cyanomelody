# ロードマップ

各周の観点は、始める前にコードを読んで決めた。周ごとに、単体テスト（`cargo test`）、型の確認とlint（`npx tsc -b`、`npx oxlint src`）、リリースビルドでのすべての画面テスト（`e2e/run.sh`）を行う。

- [ ] 1周目：画面の共通化（木の並べ替え・開閉の状態の記憶）
- [ ] 2周目：データ構造（並べ替えの移す先の型の名前）
- [ ] 3周目：App.tsxの分割（再生・チェックの処理を切り出す）
- [ ] 4周目：Rust側の共通化（idの一覧の渡し方、絶対パスの組み立て、存在の確認）
- [ ] 5周目：コメントの正確性・冗長性
- [ ] 6周目：機能レベルの微修正（入力欄のEnter、Escなど操作の細部）
- [ ] 7周目：問い合わせの回数（プレイリストの展開・表示の速さ）
- [ ] 8周目：型の安全性（データベースの文字列と列挙型の変換）
- [ ] 9周目：CSSの整理
- [ ] 10周目：テストコードの共通化
