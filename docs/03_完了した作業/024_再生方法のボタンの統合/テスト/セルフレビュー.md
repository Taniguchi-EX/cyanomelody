# セルフレビュー

## 仕様との突き合わせ
- 作業概要の範囲（ボタン1つで4つの再生方法を回す、始めるときに従う、再生中に変えたら今の曲の後に効く）をすべて実装した。
- プレイリストは、順に展開した並び（中の項目の再生方法は当てはめたもの）に、画面側で再生方法を当てはめる。今までのプレイリスト自体へのシャッフル・ランダムセレクトと同じ結果になる（展開した並び全体を並べ替える・1つ選ぶ）。

## 見つけて直した問題
- 順に連続で行の「▶」を押したとき、その行より前の曲を再生の順番から外していた（今までは一覧全体を入れて、その行から鳴らしていた。「⏮」で前の行に戻れなくなる）。今までどおり一覧全体を入れる形に戻した（画面テスト P30 で見つかった）。
- 上のように始めた後に再生方法を変えると、始めた行より前の（まだ鳴らしていない）曲を「鳴らした曲」として扱い、ランダムに入れていなかった。始めた位置を覚えておき、それより前の曲は再生の順番から外したうえで、まだ鳴らしていない曲として扱うようにした（同じ曲が2回入らない）。
- エフェクトをかけた音を用意している間や、再生の失敗が届いたときに「別の曲に移ったか」を Player の同一性で見ていた。再生方法を変えると Player が作り直されるので、用意した音が鳴らなくなる・失敗した曲を飛ばさなくなるおそれがあった。鳴らし始めた回数（playSeq）で見るように直した。止めたときも回数を進め、用意中の音を鳴らさない。

## 不具合の確認
- 鳴らせる曲がないとき（元の並びが空）は、今までどおり始めない（呼ぶ側で「再生するファイルがありません」を出す）。
- 1曲だけの並びでランダムにしても、今の曲の後は空になり、終わったら止まる。
- 「⏮」で始めた曲より前に戻った後に再生方法を変えたときは、今の曲から作り直す。

## 既存の機能への影響
- 再生の欄の「▶」の名前を「順に再生」から「再生を始める」に変えた（再生方法で動きが変わるため）。画面テストのボタンの指定も直した。
- プレイリストの項目の再生方法（順に・シャッフル・1曲）のプルダウンは変えていない。
- 性能：3万件の再生の開始は 852ms → 838ms（変わらない）。
