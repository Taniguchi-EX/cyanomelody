# セルフレビュー

## 仕様との食い違い
- なし。消す・まとめるテストの一覧（`見直しの一覧.md`）は、ユーザーに見てもらってから手を入れた。
- 目安の「画面テストを100件前後」に対して、101件になった（手動UIレビューの反映で足したものを含む）。

## 不具合・境界値
- 条件を待つ形にしたところは、待つ条件が来なかったときに長く止まらないよう、3〜5秒で切る。切れたあとは、続く確かめ（`expect`）で失敗として出る（待ちの失敗は握りつぶし、確かめの方で何が違うかを出す）。
- `ui.confirmed` は、確認のダイアログが出た回数が増えるのを待つ。答え（OK・キャンセル）を決めてから呼ぶ。
- `ui.reload` は、一覧の版（`data-list-version`）が1以上になるのを待つ。読み込み直すと版は0から数え直すので、前の画面の値と取り違えない。
- `ui.clearChecks` は、「チェックをすべて外す」を押せないとき（チェックがない）は待たずに戻る。
- 決まった時間だけ待つところは17か所残した。「何も起きない」ことを確かめるところ（ドラッグを落とせない位置、打ち込みだけでは付かない、取っ手では絞り込まない、グレーアウトの行は押しても選ばれない、URLを開いてエラーが出ない）、描画を少し待つところ（50ms）、ハッシュ値の計算のあとの読み直し、性能の計測の中のスクロール。

## 既存の機能への影響
- アプリの中身は変えていない。テストのために足した印（処理の回数 `data-run-count`、一覧の版 `data-list-version`）は、画面には出ない。
- 画面テストはデバッグビルドで流すようになった。普段使うアプリ（リリースビルド）は、作業の最後に1回だけビルドする。

## 書き方
- テストを流す入口を `app/check.sh` にまとめた。どの変更でどの画面テストを流すかは、`開発の手順.md` の対応表に書いた。
- 待ち方の決まり（`waitIdle`・`filtered`・`confirmed`・`waitStatus`・`waitFor`）を `開発の手順.md` に書いた。
