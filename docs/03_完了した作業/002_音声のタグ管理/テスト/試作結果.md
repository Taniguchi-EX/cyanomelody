# 試作結果

確認日：2026-11-02
環境：Windows 11 Home、Rust 1.98.1、Node.js 22.23.4、Tauri 2.12、WebView2 156

## 1. Tauri 2・React・SQLiteの構成

- `npm create vite`（react-ts）で画面を作り、`tauri init`でTauriを加えた。
- SQLiteはrusqlite 0.41の`bundled`機能を使い、SQLite本体をアプリに組み込んだ（別途インストール不要）。
- 開発モード（`npx tauri dev`）とリリースビルド（`npx tauri build --no-bundle`）のどちらでもビルド・起動できた。
- 結果：問題なし

## 2. 3万ファイルのスキャン時間

中身がダミーの`.wav`を3万個（100フォルダ×300個）置いて測った。

- Rustの単体テスト（リリースビルド、`scan_30000_files`）
  - 初回（3万件を追加）：98ms
  - 2回目（変化なし）：93ms
- 画面から登録（リリースビルド、画面テストT16）
  - 登録・スキャン・一覧の読み直しまで：494ms
- 目安（3万ファイルで10秒以内）を大きく下回った。
- 注意：作った直後のファイルで測ったため、OSのキャッシュが効いている。外付けHDDや、PCを起動した直後の初回スキャンはこれより遅くなる見込み。
- 結果：問題なし

## 3. 3万件の一覧表示

- @tanstack/react-virtualで仮想スクロールにし、画面に見えている行（とその前後）だけを描画した。描画した行は45行。
- 一覧を10回に分けて端までスクロールして644ms（1回あたり約50msの待ちを含む）。引っかかりはなかった。
- ファイル名での絞り込み（3万件→100件）：234ms（入力の待ち時間200msを含む）
- 3万件を全選択してタグを付ける：472ms
- 結果：問題なし

## 4. WebView2での再生

ffmpegで作った1秒のチャイムを、Tauriのassetプロトコル経由で`<audio>`要素で再生した。

- MP3（libmp3lame）：再生できた
- WAV（PCM）：再生できた
- FLAC：再生できた
- OGG（Vorbis）：再生できた
- M4A（AAC）：再生できた
- 結果：問題なし。OGGのうちOpusは確かめていない。

## 5. Playwrightでの画面操作

- 環境変数`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`を付けてアプリを起動し、Playwrightの`chromium.connectOverCDP`でつないだ。
- クリック、キー入力、確認ダイアログへの応答、スクリーンショットのすべてができた。
- OSのフォルダ選択ダイアログ（「参照」ボタン）は、Playwrightでは操作できない。
- 結果：問題なし
