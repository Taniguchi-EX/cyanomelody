# セルフレビュー

## 仕様との突き合わせ
- `01-01_画面遷移.md`・`01-02_画面のレイアウト.md` の決めたことは、すべて作った。決めたことと違えたのは次だけ。
  - プレイリストの編集のチェックは、長押しでなく行の右端のチェックボックス（長押しは並べ替えのドラッグに使うため。ユーザーに伝えて了承済み）。
  - ファイルの詳細の「▶ 再生」は、本文の上でなく見出しの行の右端に置いた（狭い画面で、スクロールしても押せるように）。

## 見つけて直したもの
- 重ねて出す画面（設定など）を開いたまま戻る操作をすると、下の画面が戻っていた。重ねて出す画面も履歴に積み、戻る操作で閉じるようにした。
- プレイリストの編集・一括操作の画面を、「開いているのに積まれていない」で積んでいたため、戻る操作の直後（まだ開いている間）に積み直し、履歴がずれていた（1回の戻る操作で2回戻る・戻る操作が効かない・アプリが閉じる）。開いた瞬間だけ積むようにした。
- 一括操作の画面が空になっていた（開いた直後、まだ画面が積まれていない間に「積まれていないので閉じる」が動いていた）。画面から外れた瞬間だけ閉じるようにした。
- 全画面の再生の下へのスワイプが、全画面がスクロールできる作りのため、指の動きがスクロールとして扱われて閉じなかった。pointer でなく touch の知らせで見るようにした（試作は全画面がスクロールしない作りだったので、pointer で動いていた）。
- ファイルの詳細で、ファイルの場所が URI（JSON）のまま出ていた。相対パスを出すようにした。
- プレイリストの編集の、項目を加える欄の説明が Windows のまま（左の欄へのドラッグ）だった。Android の加え方を出すようにした。

## 既存の機能への影響
- Windows の画面は、`App.tsx` の状態と操作を `useAppController` に、欄の中身を `views/` に移しただけ。部品に足した Android 用の振る舞いは、`isAndroid` か、一覧の部品の `touch`（Android の画面だけが渡す）のときだけ効く。
- 並べ替えのドラッグ（`treeDrag.ts`・`useFileDrag.ts`）は、指（pointerType が touch）のときだけ長押しを待つ。マウスの動きは変えていない。
- 画面テスト（check.sh all）はすべて成功した（テスト結果）。

## 気を付けること
- 端末の戻る操作は、ブラウザの履歴（pushState・popstate）で扱っている。画面を積む・外す処理を足すときは、「開いた瞬間だけ積む」「戻る操作で外れたら閉じる」を守る（積み直すと履歴がずれる）。
- 画面テストは Windows だけ。Android の画面は、実機で開発者ツールと adb から確かめた（手順はローカルのスキル）。
