# セルフレビュー

テストの前に、実装を作業概要と突き合わせ、コードを見直した。

## 作業概要との突き合わせ

作業概要の仕様の項目ごとに確かめ、すべて実装されていた。
- 各行の右端のチェックボックス。絞り込みを変えてもチェックは外れない
- 見出しの行の「表示中のファイルをすべてチェック」（一部だけチェックしているときは「－」の表示）、Ctrl+Aでのすべてチェック、Shift+クリックでの範囲のチェック
- チェックしている件数の常時表示（表示中のうちの件数も）と「チェックをすべて外す」
- 「チェックしたファイルだけ」の絞り込み。「絞り込みを解除」で外れ、チェックは残る
- 一括操作の欄（タグを付ける・外す、出典・ライセンスの設定・解除と内訳、ひも付け直す、ライブラリから外す）。操作の前に件数を出して確認し、操作の後もチェックは残る
- ライブラリから消えたファイルはチェックから外れる（チェックしたファイルの内訳を求めるときに、ライブラリにあるものだけに絞る）
- 行のクリックは1件の詳細の表示だけ（Ctrl・Shiftを押していても同じ）。右の欄は1件用。チェックボックスを押しても右の欄は変わらない

## 見つけて直した問題

1. Shift+クリックでの範囲のチェックの起点を、一覧での位置（何行目か）で覚えていたため、絞り込みを変えると別のファイルを起点にしてしまう。
   - 起点をファイルのidで覚え、今の一覧での位置を探すようにした。起点のファイルが今の一覧にないときは、押した行だけをチェックする。

## 実装中に変えた点（画面の確認で見つけたもの）

- 一括操作の欄の「ひも付け直す」「ライブラリから外す」は、押せない状態で常に出すと欄が2段に折り返した。チェックしたファイルに見つからないファイルがあるときだけ出すようにした（作業概要の記述も直した）。

## 確かめて問題がなかった点

- チェックしたファイルのidは、数万件でもSQLの引数の数の上限にかからないよう、JSONの配列1つとして渡している（単体テストで4万件を確認）。
- 一括操作の処理（タグの付け外し、出典・ライセンスの設定、ひも付け直し、ライブラリから外す）は、既存のものをそのまま使っている。ひも付け直し・ライブラリから外すは、見つからない印のないファイルを無視するので、チェックしたすべてのidを渡してよい。
- 右の欄の操作は、表示中の1件だけを対象にしている。

## 気づいたが直さなかった点

- 「チェックしたファイルだけ」を表示しているときにチェックを外すと、その行はすぐに一覧から消える。条件どおりの動きなのでそのままにした。
- チェックを1つ押すたびに、チェックしたファイルの内訳を求め直す。3万件での速さはテストで測る。
