# セルフレビュー

## 仕様との対応
- 「✎」で詳細画面を開く、タグ名・並び順（3種類と昇順・降順）・背景色・文字色：実装済み。
- 並び順は直下の子だけに効く：子の並べ替えは親ごとの一覧の中だけで行い、孫は子の設定で並ぶ（単体テスト child_sort_orders_only_direct_children）。
- 色はライブラリの行と右の欄のチップに付く。親から引き継ぎ、子の色が優先：list_tags で階層の順に引き継ぐ（単体テスト colors_are_inherited_separately_and_child_wins、画面テスト T02）。

## 見つけて直したこと
- 色付きのチップの枠が灰色のままで、背景色と合わずに見えた。背景色があるときは枠も同じ色にした。
- E2Eで、並び順を決めた親の中のドラッグを確かめる手順が、ドラッグで決めた順を変えない操作になっていた。後ろへ落とす操作にした。

## 確かめたこと
- 統合になる名前で保存したとき：統合を確認し、統合したときは並び順と色を保存しない（確認のメッセージに書く）。キャンセルなら詳細画面は残る。
- 詳細画面を開いている間にタグが消えたとき（削除・統合）：開いているタグが一覧になければ、詳細画面を出さない。
- 色の形式：`#rrggbb` 以外はエラー。小文字にそろえて保存する。
- ファイル数順の件数は、ファイル数順を使う親があるときだけ求める（ないときの list_tags 以外の処理を遅くしない）。
- タグの順を使うほかの処理（ファイルの行のタグの順、tag_rank）も、同じ tree_order を通るので並び順が効く。
- 最上位のタグには並び順の設定を持つ親がないので、ドラッグで決めた順のまま（作業概要の「やらないこと」）。

## 残したこと
- ローマ字順は漢字の読みを変換しない（作業概要の「やらないこと」）。
- 名前を変えて保存するとき、並び順と色を先に保存してから名前を変える。名前の変更だけが失敗したとき（制御文字を含むなど）は、並び順と色は保存されたまま、エラーを出して詳細画面が残る。害はないのでこのままにする。
