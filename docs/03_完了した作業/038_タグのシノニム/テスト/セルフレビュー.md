# セルフレビュー

## 確かめたこと
- 名前でタグを探す処理（find_tag）にシノニムを足したので、それを使うところ（付けるタグ名の Enter、ファイルの情報からのタグ付け、名前の変更での統合の判定、インポートの同じ名前の判定）は、まとめてシノニムでも引けるようになった。
- 重なりの確かめは2か所。詳細画面の一覧で加えるときにその場で（画面にあるタグの一覧で）、保存のときに Rust で（データベースで）。保存では、シノニムを先に確かめて保存し、その後で並び順・色・名前を保存する。重なりがあれば何も変えずにエラーを出す。
- 名前とシノニムの入れ替え（名前を自分のシノニムの1つに変え、元の名前をシノニムに加える）ができることを確かめた：シノニムの保存では、これからの名前と同じものを外し、元の名前は自分の名前なので重なりにしない。名前の変更では、自分のシノニムと同じ名前ならそのシノニムを外す。
- 統合では、統合元を消す前に名前とシノニムを読み、消してから統合先のシノニムの最後に加える（もう誰かの名前・シノニムなら加えない）。統合元のシノニムは表の UNIQUE に当たらない。
- 付けるタグ名の候補はブラウザ（WebView2）の datalist なので、候補の option の label にシノニムを入れた。Chromium の候補は value と label の両方で絞り込む。画面テストでは label が入っていることまでを確かめ、候補の一覧そのもの（OS の部品）は確かめられない。
- シノニムの大文字・小文字の区別は、タグの名前と同じく SQLite の COLLATE NOCASE（英字だけ）。画面側の確かめは toLowerCase で、全角の英字なども同じとみなす（画面の方が厳しいだけで、食い違っても保存できないものは出ない）。
- ファイルの情報からのタグ付けの結果は、値ではなく付けたタグの名前を出すようにした（大文字・小文字の違う名前のときも、今のタグの名前が出る。前は値をそのまま出していた）。

## 気づいた問題と対応
- 詳細画面のシノニムの一覧が、無視する値の一覧の見た目（薄い文字・字下げ）のままだった。ふつうの色にし、字下げをやめた。
- 一覧の部品（EditableList）を自動タグ付けのダイアログから自分のファイルに移し、入れる前の確かめ（validate）を足した。自動タグ付けのダイアログの動きは変わらない（画面テスト autotag で確かめた）。
