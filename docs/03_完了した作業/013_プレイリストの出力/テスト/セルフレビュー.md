# セルフレビュー

## 作業概要との突き合わせ

作業概要の仕様の項目ごとに確かめた。下の「見つけて直した問題」を除き、実装されていた。
- 書き出す曲は、プレイリスト全体を再生したときと同じ展開（シャッフル・ランダムセレクトはそのときに決める）
- 選んだフォルダの中にプレイリストの名前のフォルダを作る。同じ名前があれば「 (2)」などを付ける（上書きしない）
- ファイルの項目・タグの組み合わせの曲はそのフォルダに、プレイリストの項目（子・参照とも）はフォルダにして中を書き出す
- 名前の先頭に、フォルダの中での順番（3桁。1000件以上なら桁を増やす）。名前は別名、なければファイル名（拡張子を除く）・プレイリスト名。Windowsで使えない文字は「_」
- エフェクトのかかる曲はWAV（16bit、元の標本化周波数）、かからない曲はそのままコピー
- 裏で書き出し、進み具合（何件中何件）と「中止」、終わったら書き出した件数・書き出せなかった件数と書き出し先を出す

## 見つけて直した問題

1. 見つからないファイルの項目を、書き出す内容を決める段階で除いていたため、「書き出せなかった件数」に数えていなかった（作業概要と食い違い）。書き出す内容に入れておき、書き出すときの失敗として数えるようにした。
2. 画面テストの途中で、テストの実行（`e2e/run.sh`）が、終わるたびに`cyanomelody.exe`をすべて止めていたことに気づいた。ユーザーが普段のアプリを開いていると、それも閉じてしまう。テストのアプリは別の名前の実行ファイルで動かし、それだけを止めるようにした。WebView2の保存領域もテストごとに分け、普段のアプリの画面の状態（欄のたたみ具合など）を消さないようにした。

## 作業概要に書いていなかったが決めたこと

- 「順に再生」のプレイリストの項目は、中の階層をそのままフォルダにする。シャッフル・ランダムセレクトのプレイリストの項目は、並べ替えや選び方が中の階層をまたぐので、展開した曲をそのフォルダに並べる（中のフォルダは作らない）。
- 書き出し先は、フォルダのパスを入れるか「参照」で選ぶ（フォルダの登録と同じ形）。
- 書き出しは同時に1つだけ。書き出し中にもう一つ始めようとするとエラーにする。

## 気づいたが直さなかった点

- 見つからないファイルの項目も順番の数字を使うので、書き出したファイルの番号が飛ぶことがある。
