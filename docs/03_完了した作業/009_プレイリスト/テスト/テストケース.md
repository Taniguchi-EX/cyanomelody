# テストケース

## 単体テスト（Rust）

`playlists.rs`
- 作成（最上位・子）、名前の決まりと一意、存在しない親、名前変更。左の欄の並び・親・項目として入れているプレイリスト・項目の数
- ループの防止：自分自身、子孫・参照先をたどったプレイリストへの追加、ループになる階層の移動、自分自身の前後への移動。同じものを2回参照するのはループではない
- 左の欄での移動（子の最後、子の前・後ろ、最上位、最上位の前・後ろ）。子を親の中で動かしても再生方法を引き継ぐ
- 項目の追加（ファイル、タグの組み合わせ、参照）・並べ替え・外す（子は最上位へ）。ないファイルは無視、空のタグの組み合わせはエラー、ファイルの項目は再生方法を持たない
- ファイルは、指定した順ではなくファイルの一覧の順で加わる
- 削除：子は削除した位置に繰り上がる（親の項目の並び・最上位）、参照の項目は外れる
- 展開：順に（見つからないファイルを除く）、ランダムセレクト、シャッフル、プレイリスト自体の再生方法。項目のファイル数
- 子のプレイリストは親の並びの位置で再生される。空のプレイリスト
- タグの統合・削除で組み合わせが変わる。プレイリストで使われているタグは、使われていないタグの一括削除で消えない
- 見つからないファイルの項目は残り、ライブラリから外す・フォルダの登録解除で項目が外れる

`hashing.rs`
- ひも付け直しで、プレイリストのファイルの項目が新しいファイルに付け替わる

## 画面テスト（Playwright、`app/e2e/playlists.mjs`）

- P01：左の欄でプレイリストを作る（最上位の最後に入る）。同じ名前はエラー
- P02：一括操作の欄から、チェックしたファイルを追加する（件数の確認が出る）
- P03：右の欄から、1件のファイルを追加する。ファイルの一覧の順に並ぶ
- P04：タグの組み合わせを、選んで加える・いまの絞り込みのタグを加える。ファイル数が出る
- P05：再生方法を変える（ランダムセレクトは1件）
- P06：別の階層のプレイリストを参照として加える。自分自身とループになるプレイリストは選べない（理由も出る）
- P07：子のプレイリストを作ると、左の欄に子として出て、親の項目の最後に入る
- P08：項目を取っ手で並べ替える
- P09：左の欄の取っ手で子にできる。ループになる位置には表示が出ず、落としても変わらない
- P10：子の項目を外すと、その子は最上位に移る
- P11：再生の欄に名前・何曲目か・ファイル名が出る。次へ・前へ・一時停止・再開・停止
- P12：1曲終わると次を再生し、最後まで再生したら止まって、そのことを表示する
- P13：再生できないファイルは飛ばして、そのことを表示する
- P14：試聴を始めると、プレイリストの再生は止まる
- P15：名前を変える（同じ名前はエラー）
- P16：削除すると、子は繰り上がり、参照していたプレイリストから外れる。確認のメッセージにそのことが書いてある。開いていた編集画面は閉じる
- P17：3万件が対象のタグの組み合わせを再生し始めるまでの時間
