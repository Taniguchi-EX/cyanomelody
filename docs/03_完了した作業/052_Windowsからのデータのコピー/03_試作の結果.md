# 試作の結果

実施日：2026-11-10。試作のコードは `copy-prototype` ブランチ（一時的なコマンド `app/src-tauri/src/copy_proto.rs`。main には入れていない）。
実機（Android 17）に USB の有線デバッグで入れ、書き出したフォルダの形（`cyanomelody.json` と、サブフォルダ「効果音」（中にさらにサブフォルダ）・「BGM」・「大量」（500件））を adb で端末の `Download` の下に置いて確かめた。

## 確かめたことと結果
- 書き出したフォルダを選べるか：できる（`Picker::pick_dir`。`Download` そのものは選べないが、その下のフォルダは選べる）。
- 選んだフォルダの中の JSON を、名前で引いて読めるか：できる（`AndroidFs::resolve_file_uri(フォルダ, "cyanomelody.json")` と `open_file_readable`）。
- 選んだフォルダの中のサブフォルダを、そのままライブラリのフォルダとして登録できるか：できる。`read_dir` で得たサブフォルダの URI を、今の `library::add_saf_folder` に渡して登録・スキャンできた。画面に出す名前も「Download/…/効果音」と正しく出る。
- アプリを起動し直しても、サブフォルダを読めるか：読める。権限は選んだフォルダ（親）に残り、サブフォルダの URI の確認（`check_persisted_uri_permission`）は親の権限で通る。
- スキャンの速さ：500件のフォルダで約0.5秒（デバッグ版）。
- ハッシュ値の計算：サブフォルダの曲も計算できる（512件、30秒以内。試作の音声ファイルは小さいので、実際の曲ではもっとかかる）。
- JSON のファイルだけを選んで読めるか：できる（`Picker::pick_file(None, &["application/json"], false)`）。

## 分かったこと（本実装で守ること）
- 残る権限は、選んだフォルダ（親）の1つ。サブフォルダを登録しても、権限は増えない。フォルダの登録を外すときに権限を手放す処理を作るなら、同じ親の下に登録が残っていないかを見る（今は手放していないので、問題はない）。
- 2回目以降のコピーで同じ場所に上書きしたときは、サブフォルダの URI が前と同じになるので、「登録済みのフォルダ」として見分けられる（URI の document の部分が同じ）。
- adb で 513件（約1.6MB）を写すのに約13秒かかった。ファイルの数が多いと、USB で写すのに時間がかかる（ユーザーが行う部分）。
