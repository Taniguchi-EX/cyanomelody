# セルフレビュー

## 仕様との突き合わせ
- 作業概要のとおり、リリース年をハッシュ値の計算と一緒に調べて保存し、「その他」に「長さ」と同じ形の「リリース年」の行（「以上」「以下」。その年を含む）を加えた。

## 見つけて直した問題
- WAV の INFO の日付（ICRD）を、symphonia の結果から読めなかった（WAV の INFO は symphonia の結果に出てこない。曲名を直接読んでいるのと同じ理由）。ファイルから直接読むようにした。
- 長さとリリース年を別々に読むと、ファイルを開く回数が増える（Google ドライブの上のファイルでは遅い）。長さを求める処理と同じ1回の読み込みで、年も読むようにした（AudioInfo）。性能テストの続きの計算の時間は変わらない（3,723ms → 3,447ms）。
- 入力欄が空のときに枠を赤くすると、最初から赤くなる。空でなく、4桁の年でないときだけ赤くした（空のときはボタンを押せないだけ）。

- （作業の後に見つけた）年が読めなかったファイルで、WAV でなくても INFO を読むためにファイルを開き直していた。WAV のときだけ開き直すようにした。実際のライブラリの60曲（Google ドライブの上）で測ると、直した後は、長さだけを読むときと時間が変わらない（5回の平均：長さだけ 187ms、長さと年 182ms。ハッシュ値の計算を含めると、前 792ms・後 776ms）。

## 不具合の確認
- 「以上」「以下」はその年を含む（2019年以上と2019年以下で、2019年のファイルだけになる。画面テスト・単体テストで確認）。
- 「06」「0999」「abcd」のような値は年にしない。
- 年を調べていないファイル（この版に上げた後、スキャンするまで）と、年のないファイルは、条件があるときは出さない（長さと同じ）。

## 既存の機能への影響
- ハッシュ値の計算の対象に「リリース年をまだ調べていないファイル」が加わった。この版に上げた後に初めてスキャンしたときは、すべてのファイルを調べ直す（ハッシュ値も計算し直すが、値は変わらない。長さを加えたときと同じ）。
