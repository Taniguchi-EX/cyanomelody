# セルフレビュー

## 仕様との対応
- 長さを調べて保存する：ハッシュ値の計算の裏の処理で一緒に調べる（hashing::analyze）。長さをまだ調べていないファイルも計算待ちにする（pending_files）。
- 情報にない長さはパケットをたどって求める（metadata::duration）。読めないファイルは NULL（duration_done は1にして、何度も調べ直さない）。
- ファイルが変わったら調べ直す：スキャンでサイズか更新日時が変わったら duration・duration_done を消す（単体テスト scan_clears_hash_only_when_file_changed に追加）。
- 「その他」の長さの行、以上・以下（それぞれ1つ、押し直すと置き換え）、チップ、見出しの数：実装済み（画面テスト F11）。
- 長さのないファイルは条件があるときは出さない：SQL の比較で NULL は外れる（単体テスト filter_by_duration）。
- ほかの項目の件数にも効く：絞り込みの条件（filter_conditions）を件数の計算と共通にしているので、そのまま効く。

## 見つけて直したこと
- 「指定フォルダから自動で探す」もハッシュ値の並列計算を使っていて、長さまで調べると無駄になる。並列計算を、ファイルごとの処理を受け取る形にし、探すときはハッシュ値だけを計算するようにした。
- 画面テストの初めの版に、意味のない確認（常に成り立つ式）があった。「その他」の見出しの選んでいる数の確認に書き換えた。

## 確かめたこと
- 入力欄は数字だけを受け付ける（数字以外は消える）。時・分・秒は桁の制限をしない（「90分」も90分として扱う）。
- 「以上」の値が「以下」より大きいときは、0件になる（エラーにはしない）。
- すべての条件を外す「✕」・左の欄の操作での条件の初期化（EMPTY_FILTER）で、長さの条件も外れる。入力欄の値は残る。
- データベースの更新（マイグレーション11）の後、最初の起動でスキャンをすると、今あるファイルすべての長さを調べる（ハッシュ値も計算し直すが、値は同じ）。

## 残したこと
- 長さはスキャンの後の裏の処理で調べるので、アプリの更新の後は、スキャンするまで長さの条件に出ないファイルがある（今の作りでは、ハッシュ値の計算はスキャンの後に始まるため）。
- 性能テストの PF02（続きの計算）は、長さを調べる分だけ遅くなった（下の「テスト結果」）。
