# 曲名の文字化けの修正

## 目的
再生の欄・右の欄に出す曲名（音声ファイルの中のタイトル）が、文字化けすることがあるのを直す。

## 原因
- 曲名は、音声を読むライブラリ（symphonia）で読んでいる。symphonia は文字コードを次のように決め打ちしている。
  - WAV の INFO（INAM）：UTF-8。Shift_JIS で書かれた曲名は「�」に置き換わり、元のバイト列が失われる。
  - MP3 の ID3v2 で文字コードが ISO-8859-1 の項目、ID3v1：ISO-8859-1。Shift_JIS や UTF-8 で書かれた曲名は「ã‚ƒ」のような文字になる（1バイトが1文字になり、元のバイト列は残る）。
- 日本語の曲名を Shift_JIS で書くソフト（Windows の古いソフトや効果音素材など）は多く、そのファイルで化ける。

## 範囲
- WAV：INFO の曲名（INAM）を、symphonia を使わずにファイルから直接バイト列で読み、文字コードを判定して文字にする。
- MP3（ID3v2・ID3v1。拡張子が mp3 のファイルだけ）：symphonia の結果がすべて U+0000〜U+00FF の文字で、0x80 以上の文字を含むときは、元のバイト列に戻して文字コードを判定し直す。
- 文字コードの判定：UTF-8 として正しければ UTF-8。そうでなく Shift_JIS として正しければ Shift_JIS。どちらでもなければ、今までどおり（WAV は UTF-8 として読み、読めない部分は「�」。ID3 は ISO-8859-1）。
  - 英字だけの曲名や、ISO-8859-1 の欧文（「Café」など）は、UTF-8・Shift_JIS として正しくないことがほとんどなので、今までどおりに読む。

## やらないこと
- FLAC・Ogg（Vorbis コメント）、MP4 のタグ：仕様で UTF-8 と決まっており、化けることは少ないため。
- 文字化けを判定して直す（Shift_JIS 以外の文字コード、EUC-JP など）こと。
