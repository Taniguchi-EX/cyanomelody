# セルフレビュー

## 仕様との突き合わせ
- 作業概要の範囲（WAV の INFO を直接読む、MP3 の ISO-8859-1 の項目を読み直す、UTF-8 → Shift_JIS の判定）をすべて実装した。
- 実際のライブラリ（MP3 5225件）から400件を抜き出して先頭のタグを調べたところ、93件が「ISO-8859-1 と書かれた Shift_JIS」だった。そのうちの1件（YOASOBI「たぶん」）で、直す前は「\u{82}½\u{82}Ô\u{82}ñ」、直した後は「たぶん」になることを確かめた（一時的なテストで確認し、テストは消した）。

## 見つけて直した問題
- 読み直しをすべての形式の曲名にかけていた。FLAC・Ogg・M4A の曲名は UTF-8 と決まっているので、「éè」のように欧文の文字だけの曲名を、まれに Shift_JIS の漢字と取り違えるおそれがあった。読み直しは拡張子が mp3 のファイルだけにした。

## 不具合の確認
- WAV の INFO の読み取りは、チャンクの大きさを信じすぎないようにした（INFO の中の項目が LIST の大きさを超えるときは読まない。ファイルの終わりを超える移動は、次の読み取りで止まる）。データのチャンクは読まずに飛ばすので、大きな WAV でも遅くならない。
- 大きさが奇数のチャンクの後の詰め物（1バイト）を飛ばす。テストで奇数の長さの曲名を確かめた。
- INAM がないとき・空のときは、今までどおり symphonia で読む。
- 欧文の ISO-8859-1（「Café au lait」）は今までどおりに読む（テストで確認）。

## 既存の機能への影響
- 曲名を読むのは、再生の欄と右の欄に出すときだけ。UTF-8 で正しく書かれた曲名と、ASCII だけの曲名は、結果が変わらない。
