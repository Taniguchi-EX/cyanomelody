# セルフレビュー

## 仕様との突き合わせ
- 作業概要の範囲（右端の歯車、タブの設定画面、一般タブの新しいタグの既定値、バージョンとライセンスのタブ、ビルドの前に一覧を自動で作る）をすべて実装した。
- 歯車は、途中の指示どおり再生の欄の右端（音量のバーの右）に置いた。

## 見つけて直した問題
- ライセンスのファイルを入れずに配布されているライブラリが19件あった（symphonia の各部品・selectors（MPL-2.0）、alloc-stdlib（BSD-3-Clause）、webview2-com（MIT））。表示の条件を満たせないので、ライセンスの種類の標準の文章を使うようにした。MPL-2.0 の文章は、同じライセンスの別のライブラリ（cssparser）に入っているものを写した。MIT・BSD の著作権の行には、そのライブラリの作者を入れる（作者がなければ「The <名前> authors」）。
- 設定画面の部品は、読み込みの useEffect で onError を使う。App の showError は描画のたびに作り直される関数なので、そのまま渡すと読み込みを繰り返す。設定画面には、毎回同じ関数（useCallback）を渡すようにした。
- タグの詳細画面と設定画面で使う並び順の選び肢・既定の色を、コンポーネントのファイルから tagSettings.ts に移した（コンポーネントのファイルが部品以外を出すと、lint の警告になる）。
- check.sh の型チェックは、ライセンスの一覧（ビルドの前に作るもの）を読むので、型チェックの前に一覧を作るようにした（新しく取ってきたリポジトリで型チェックが失敗しないように）。

## 不具合の確認
- 既定値を決めていないときは、今までと同じ（引き継ぐ・色なし）。既定値が今までと同じなら、タグを作るときに余分な書き込みをしない。
- 形式の違う色は保存しない（単体テストで確認）。
- ライセンスの一覧は約675KB。このタブを開いたときに別のファイルとして読むので、起動は重くならない。ライセンスの文章は、開いたライブラリの分だけ画面に出す（すべてを出すと重いため）。
- 一覧を作るときの依存のたどり方は、Windows 向けの通常の依存だけ（ビルドの道具・開発用・ほかの OS 向けは除く）。

## 既存の機能への影響
- 再生の欄の右端に歯車が加わった。並び順の画面テスト（P21 の「⏮ ▶ ⏭ 再生方法 ■」）は中央のボタンだけを見るので、影響はない。
- 画面テストの設定画面（S02）が、1回目にだけ途中のクリックで止まった（30秒の待ちで失敗）。その後3回続けて成功し、全体のテストでも成功した。再び起きたら、止まった操作を調べる。
