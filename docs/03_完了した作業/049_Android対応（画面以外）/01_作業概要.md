# Android対応（画面以外）

状態：完了（2026-11-10）。試作は終えた（結果は `03_試作の結果.md`）。

## 目的
Android の端末でも、ライブラリのフォルダを登録してタグで整理し、プレイリストで再生できるようにする。
画面は大きく作り直すことになるので、別の作業（「Android の画面」）に分け、この作業では画面以外（ビルド・ファイルの扱い・内部処理）を先に片付ける。後の作業「Androidとの同期機能」の前提になる。

## 範囲
### 1. ビルドの土台を main に入れる
- 試作のブランチ（`android-prototype`）から、試作専用でないものを main に入れる：デスクトップ専用のもの（ごみ箱・自動アップデート）の切り分け、`package.json` の `tauri` のスクリプト、Android のプロジェクト（`src-tauri/gen/android`）、Docker のビルド環境、`source::FileSource`。
- Docker のビルド環境は `app/android/` に置き、開発の手順に書く。
- 16 KB のページサイズに合わせる（起動のたびの警告をなくす）。
- 試作の画面（`AndroidProto.tsx`）と試作のコマンド（`android_proto.rs`）は main に入れない（同じことを本実装のコマンドで行う）。

### 2. ライブラリのフォルダとファイルを、パスと SAF の URI の両方で持てるようにする
- フォルダの登録：Android では、SAF のフォルダを選ぶ画面で選び、権限を残す（`persist_uri_permission`）。
- データベース（仮判断）
  - `library_folders` に、場所の種類（`path`：Windows のパス、`saf`：SAF のフォルダ）を加える。SAF のフォルダは、`path` に FsUri の JSON を入れる。
  - `audio_files` に、ファイルの URI（SAF のファイルだけ。FsUri の JSON）を加える。スキャンのときに読む（ファイルごとに URI を作り直すと、数千件で遅いため）。相対パス（`rel_path`）は今と同じく持つ（並び順・検索・表示・プレイリストの書き出しの名前に使う）。
- 「ファイルの場所」を1つの型（パスか、SAF の URI か）にまとめ、ファイルを読む所（ハッシュ値と長さ、曲名、ジャケット、ファイルの情報からのタグ付け、エフェクトをかけた音）は、その型から `FileSource` を作って読む。
- スキャン：SAF のフォルダは、プラグインでフォルダの中をたどる（大きさ・更新日時も、たどったときの情報を使う）。見つからない印・戻ってきたときの扱いは、Windows と同じ。
- 再生：画面に渡すファイルの場所を、SAF なら `android-fs-content` のプロトコルの URL にする（画面の側で、場所の種類で `convertFileSrc` の使い方を分ける）。エフェクトをかけた音とジャケットは、アプリのデータ領域の普通のファイルなので、今と同じ。
- 権限がなくなったフォルダ（端末の設定で取り消した、フォルダを消した）は、スキャンで「フォルダがない」のエラーと同じに扱う。

### 3. Android で使えない操作の扱い
- ファイルの削除（ごみ箱）：Android では使えないことをエラーで知らせる（画面で隠すのは「Android の画面」の作業）。
- エクスプローラーで見せる（`revealItemInDir`）・フォントの一覧・自動アップデート：Android では何もしない・空にする。
- リンク切れのファイルのひも付け直し・フォルダから探す：SAF のフォルダを選ぶ形にする（Windows のファイル・フォルダを選ぶダイアログの代わり）。

## やらないこと（この作業では）
- 画面（1列にする・セーフエリア・Android で使えない操作を隠す）。別の作業「Android の画面」で行う。
- SAF への書き込み：プレイリストの出力・ファイルの書き出し・メタデータの書き出し・データのエクスポート。取り込み（インポート）も含め、データの入出力は「Androidとの同期機能」で決める。
- 配布（Google Play・リリース版の署名・GitHub の Release への APK の追加）。
- Windows 版の動きは変えない。

## 確かめ方
- Windows：今の単体テストと画面テスト（check.sh all）がそのまま通ること。場所の型・スキャンの単体テストを足す。
- Android：実機（USB の有線デバッグ）で、フォルダの登録・スキャン・ハッシュ値の計算・タグ付け・プレイリストの再生・エフェクトをかけた再生・ジャケット・起動し直した後の読み取り・リンク切れの扱いを確かめる。画面は今のもの（狭い）を開発者ツールから操作する。

## 前提・未決事項

- データの入出力を同期の作業に回すこと（上の「やらないこと」）。
