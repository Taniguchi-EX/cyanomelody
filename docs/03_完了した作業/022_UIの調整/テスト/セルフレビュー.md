# セルフレビュー

## 仕様との突き合わせ
- 作業概要の1〜5をすべて実装した。食い違いはない。
- 再生の欄から管理画面を開いたときの試聴の曲は、開いたときに鳴らしていた曲に決まる（開いた後に曲が変わっても変えない）。プレイリストの項目から開いたときと同じ考え方。この点を「01_現在の機能」にも書いた。

## 見つけて直した問題
- 一覧の行・項目の行へのスクロールで、lint の警告（依存の不足）を抑止のコメントで消していた。抑止をやめて、依存をすべて書く形に直した（スクロールし終えたら要求を null に戻すので、何度も走ることはない）。
- 単体テスト child_sort_orders_only_direct_children が、新しい「引き継ぐ」に合わず失敗した。孫の親（子のタグ）を「ドラッグで決めた順」にしてから確かめるように直した。引き継ぎは child_sort_inherits_from_ancestors で別に確かめる。

## 不具合の確認
- 境界・空のとき
  - 長さの入力欄が空・形の違う文字・0秒のときは、「以上」「以下」を押せない。分・秒が60以上のときは足し合わせる。
  - 何も鳴らしていないとき、曲名の欄は押せない（role を付けない）。
  - 再生していたプレイリストが削除されていたら、ライブラリの一覧で探す。項目が外されていて行が見つからないときは、スクロールしないだけ。
- 同時に操作したとき
  - プレイリストを開き直す間（読み終える前）は、前のプレイリストの行には飛ばない。読み終えてから、その項目の行までスクロールする。
- タグの並び順の引き継ぎで、親子が輪になっているデータ（本来はない）でも止まるよう、たどる数をタグの数までにした。

## 既存の機能への影響
- 今あるタグのうち並び順を決めていないタグは「親の設定を引き継ぐ」になる。親が並び順を決めていなければ、並びは変わらない。親が並び順を決めているときは、孫もその順に並ぶようになる。
- ファイルの一覧は、並び順を選んでいなければ今と同じ（パス順）。件数（facets）の計算には並び順を使わない。
- 再生の欄のエフェクトセットのプルダウンに選び肢が増えたので、既存の画面テスト（E12）の選び肢の確認を直した。

## 書き方
- 管理画面を開く選び肢（NEW_FX・EDIT_FX）は、プレイリストの詳細画面と同じ名前と動きにそろえた。
- 並び順の選び肢は、再生方法（PLAY_MODES）と同じく api.ts に一覧として置いた。
