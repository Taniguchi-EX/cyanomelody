# テスト結果

実施日：2026-11-11

## Windows
- check.sh all：単体テスト・型チェック・lint と、画面テストは、設定画面の S06 を除いてすべて成功した。
  - S06（「スマホへコピー…」でスマホを探す）は、テストの PC に「ファイル転送」でつないだスマホへ、別にデータを移している最中で、探すのに30秒より長くかかって失敗した。今回の変更はこの処理に触れていない。この処理に影響はないと見て、流し直しは行わないことにした（ユーザーの判断）。

## Android（実機、デバッグ版）
いずれも Pixel 10（Android 17）で確かめた。状態は `dumpsys media_session`・`dumpsys notification` と、画面（WebView）の中の表示で見た。

- ロック中の連続再生（ファイルの一覧）：d_3s の再生中にロックし、次の曲へ進んだ。試作では、画面を消したまま33分、止まらずに鳴り続けた（`03_試作の結果.md`）。
- ロック画面：曲の名前（再生の欄と同じ。拡張子なし）・「ファイルの一覧 11/26」・前へ・一時停止・次へ・進み具合のバーが出た（`写真/ロック画面.png`）。
- ロック画面のボタンを指と同じく押した：一時停止・再生・次へ・前へが効いた。バーを押すと、その位置（136.8秒）へ移り、ロック画面の位置もそれに合った。
- メディアボタン（`cmd media_session dispatch`）：一時停止・再生・次へ・前へ・停止が効いた。停止で通知と MediaSession が消えた。
- 「次へ」で最後の曲を越えたとき、と、ロック中に最後の曲が鳴り終わったとき：再生が終わり、通知と MediaSession が消えた。
- ほかのアプリ（Chrome）が鳴り始めたとき：一時停止し、画面の「再開」のボタンと通知の「一時停止」が合っていた。Chrome を止めても閉じても、自動では再開しなかった。
- イヤホンを外したとき（Bluetooth を切った。ユーザーが操作）：一時停止し、画面と通知が合っていた。
- エフェクト（速さ 1.5 倍）をかけた曲：イヤホンで、速い音で鳴った（ユーザーが確かめた）。エフェクトの音を作っている間は、通知が一時停止の表示になり、鳴り始めると再生中に戻った。ロック中の最後の曲の試験も、エフェクトをかけたまま行った。
- 最近使ったアプリの一覧から払って閉じたとき：プロセスが終わり、通知と MediaSession が消えた。
- 画面がロックされたまま（裏から）再生を始めようとしたとき（開発者ツールで、ふつうは起きない操作）：Android の決まりでサービスを始められず、アプリは落ちずに、通知なしのままになった。
