# セルフレビュー

## 仕様と照らし合わせて
- 裏でも鳴らし続ける：通知を出している間（鳴らしている・一時停止している）は、`MainActivity.onPause` で WebView を起こし直す。通知を消したとき、画面が見えていなければ WebView を止める（`MediaBridge.pauseWebViewIfHidden`）。
- ロック画面と通知：曲の名前は再生の欄と同じ決め方（`playingName`。PlayerBar と共通にした）。2行目はプレイリストの名前か「ファイルの一覧」と何曲目か。ボタンは前へ・再生/一時停止・次へ。バーを動かすと `seek`。
- 「■」・最後まで鳴らし終えたとき：Player が null になるので、`CyanoMedia.stop` で通知を消す。
- 割り込み：ほかのアプリの音は Chromium が止めるので、audio 要素の `pause` で一時停止に合わせる。割り込みの後に外から鳴らされたら、Android では止め直す（自動では再開しない）。イヤホンを抜いたときは、サービスが `ACTION_AUDIO_BECOMING_NOISY` を受け取り、`pause` を送る。
- 払って閉じたとき：`onTaskRemoved` で止める。
- エフェクトの管理画面の試聴は、通知の対象にしない（短い1曲で、Player を使わないため）。仕様の文書に書く。

## 見つけて直したこと
- 外から鳴らされたときに止め直す処理が、Windows でも効いていた。Windows ではキーボードのメディアキーなど使う人の操作なので、再開として状態を合わせるようにした（止め直すのは Android だけ）。
- 試作では、位置が動くたびではなく状態が変わったときだけ知らせていたが、位置を動かしたとき（`seeked`）にも知らせるようにした（ロック画面のバーがずれないように）。
- 試作の通知のアイコンはアプリのアイコンで、灰色の四角になっていた。白一色の音符の絵（`ic_stat_playback.xml`）にした。
- 裏から（Android 12 から）サービスを始められないときに、アプリが落ちないようにした（例外を受けて、通知なしで画面が見えている間だけ鳴らす）。

## 確かめたこと
- 自分から止めたとき（一時停止・エフェクトの用意・停止・曲の終わり）は、`pause` のイベントで状態を書き換えない（一時停止は状態を先に変える。エフェクトの用意中は `preparing`。停止は Player が null。曲の終わりは `ended`）。
- 再開（`togglePause`・`playAt`）は、状態を先に「再生中」にしてから `play()` するので、`play` のイベントで止め直さない。
- Windows では `window.CyanoMedia` がないので、useMediaSession は何もしない。
- 試聴を始めると Player が null になるので、通知は消える。
