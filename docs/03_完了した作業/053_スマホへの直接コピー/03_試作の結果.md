# 試作の結果

実施日：2026-11-11。試作は、リポジトリの外の小さな Rust のプログラムで行った（winmtp 0.3 と windows 0.52）。
実機（Pixel 10、Android 17）を USB でつなぎ、USB の使い方を「ファイル転送」（MTP）にして確かめた（adb で `svc usb setFunctions mtp`。adb のデバッグと同時に使える）。

## 確かめたことと結果
- Windows のアプリから MTP の端末を見つけられるか：できる（Windows Portable Devices の API。端末の名前「Pixel 10」、ストレージ「内部共有ストレージ」）。
- フォルダを作る・ファイルを書く・読む・上書きする・消す・中の一覧（名前・大きさ・更新日時）を見る：すべてできる。日本語の名前も使える。
- 書いたファイルを端末のファイルとして読めるか：読める（adb で中身を確認）。Android のアプリ（SAF）でフォルダを登録してスキャンし、ハッシュ値も計算できた。
- 速さ
  - 大きいファイル：100MB を約3秒（約33MB/s）。
  - 小さいファイル：1件あたり約0.14秒（500件で約70秒）。Android の MTP の、ファイル1つごとの手間による。
  - フォルダの中の一覧：1件あたり約12ms（500件で約6秒）。
  - 500件のフォルダを消す：約10秒。
- 端末の音楽の一覧（MediaStore）：MTP で `Music` の下に書いた曲は、すべて端末の音楽の一覧に載る（ほかの音楽アプリに、効果音が曲として並ぶ）。フォルダに `.nomedia` を先に置くと、載らない。`.nomedia` があっても、MTP からも、Android のアプリ（SAF）からも見えて読める。
- Android でフォルダを選ぶ画面の初期位置：プラグインの `Picker::resolve_public_storage_initial_location(None, PublicAudioDir::Music, "cyanomelody", true)` で `Music/cyanomelody` を指定でき、なければ作れる（説明で確認。実機は本実装で確かめる）。

## 分かったこと（本実装で守ること）
- winmtp の `push_file`（`create_write_stream`）は、書くたびに同じ名前のファイルがないか、そのフォルダの中を全部読み直す（1件 0.3 秒、件数が増えるほど遅くなる）。本実装では、先に一覧を読んでおき、書くときは確認なしで `IPortableDeviceContent::CreateObjectWithPropertiesAndData` を直接呼ぶ（親の id・大きさ・名前を渡して、ストリームに書いて Commit）。上書きは、自分で消してから書く。
- winmtp は windows 0.52 に依存している。本実装では、使う所が少ない（端末の一覧・開く・子の一覧と大きさ・フォルダを作る・書く・読む・消す）ので、winmtp を使い続けるか、新しい windows クレートで直接書くかを決める。
- 1件ごとの手間が大きいので、2回目以降は差分だけ写す（作業概要のとおり）ことが効く。初めて写すときは、曲の数×約0.15秒＋大きさ÷約30MB/s かかる（例：2,000曲・10GB で約10分）。進み具合を出し、やめられるようにする。
- フォルダの中の一覧も遅いので、差分は、前に書いた `cyanomelody.json` を主に使い、端末の一覧は必要なフォルダだけ読む。
- `Music/cyanomelody` に `.nomedia` を置く（ほかの音楽アプリに並ばないように）。
- USB の使い方が「充電のみ」のときは、Windows から端末が見えない。端末が見つからないときは、スマホで「ファイル転送」を選ぶよう画面で案内する。

## 本実装に向けて
- 作業概要の流れのまま進められる。`.nomedia` を置くことを足す。
