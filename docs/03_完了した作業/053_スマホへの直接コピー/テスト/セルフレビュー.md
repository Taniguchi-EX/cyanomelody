# セルフレビュー

## 作り
- Windows（`phone.rs`・`commands/phone.rs`）：Windows Portable Devices を winmtp で使う。端末の一覧・調べる（フォルダの中を全部読む、前のデータを読む）・写すの3つのコマンド。調べた結果（PhonePlan）は AppState に持ち、写すときに使う（2回調べない）。
  - ファイルを書くときは winmtp の push_file を使わず、確認なしで `CreateObjectWithPropertiesAndData` を呼ぶ（push_file は書くたびにフォルダの中を読み直すので、件数が増えるほど遅い。試作の結果）。同じ場所に前のファイルがあれば、先に消す。
  - 端末とのやりとり（COM）は、調べるときはコマンドのスレッド、写すときは裏の仕事のスレッドで、それぞれ端末を開き直す（COM のものをスレッドをまたいで持たない）。持ち越すのは、id の文字列とパスだけ。
  - データの JSON は、曲を写し終えてから最後に書く。中止したとき・続けられなくなったときは書かない。
- 差分の決め方（`transfer/package.rs` の diff）は端末に依存しない関数にし、単体テストを書いた。
- 進み具合と中止：今の書き出しの仕組み（`export_job`）を、1件ずつ進める仕事を受け取れる形（spawn_steps）に広げ、プレイリストの出力と「スマホへコピー」で共有した。進み具合に phone（写し先をエクスプローラーで見せない）と error（続けられなくなったとき）を足した。
- Android（`commands/copy.rs`）：cyanomelody 用のフォルダの場所と、前に取り込んだデータの日時を、設定（データベース）に覚える。アプリを開いたときに、データの日時を比べて知らせる。取り込みの中身は作業52のまま。
- 作業52の「音声ファイルも入れる」の書き出し（Windows）と「フォルダを選ぶ…」（Android）は外した。「ファイルを選ぶ…」（JSON だけ）は残した。

## 気になる点と判断
- 調べてから写すまでの間に、ライブラリやスマホの中が変わると、計画とずれる。写す前にもう一度確かめはしない（ずれても、次に写すときの差分で直る）。
- 写している途中で中止すると、スマホには新しい曲の一部と、前のデータが残る。Android で取り込むと前のデータのままになり、新しい曲はタグなどが付かない（次に写し終えれば直る）。
- 曲を消すのは、前に写したデータではなく、スマホの中の一覧で決める（cyanomelody 用のフォルダの中で、今のライブラリにないものはすべて消す。作業概要で決めたとおり）。
- winmtp は windows 0.52 に依存していて、Windows 向けのビルドに古い windows クレートが加わる。使う所は phone.rs に閉じている。

## Windows の画面への影響
- 設定画面の「データ」：「音声ファイルも入れる」のチェックがなくなり、「スマホへコピー」の欄が増えた。
- 一番下の行の書き出しの進み具合：スマホへのコピーのときは「スマホへ写しています」になり、写し先は押せない文字で出す。プレイリストの出力などは今までどおり。
