# Android 版の配布

状態：作業概要の確認済み（2026-11-11）。試作から始める。

## 目的
Android 版を、Windows 版と同じく GitHub の Releases で配る。v1.3.0（スマホへの直接コピー）は、Android 版を配れるようになってから、Windows 版と一緒に公開する（一度作った v1.3.0 のタグと下書きは消した）。

## 今の状態
- Android 版は、開発用の Docker の中でデバッグ版（`dev.cyanomelody.app.debug`）だけをビルドしている。デバッグ用の鍵で署名していて、配る形（リリース版）はまだない。
- 公開の仕組み（GitHub Actions の `release.yml`）は、版のタグを押すと Windows のインストーラーと自動アップデートの情報を作り、Release の下書きに付ける。

## 範囲（仮判断）
- リリース版の APK を作る
  - アプリの名前（applicationId）は `dev.cyanomelody.app`（デバッグ版は `.debug` が付くので、同じ端末に並べて入れられる）。
  - 64ビットの ARM（arm64-v8a）だけ。今のスマホのほとんどはこれ。Android 7.0 以上（今の設定の minSdk 24）。
  - 版の番号は、Windows と同じ（tauri.conf.json の version。Android の versionCode もそこから決まる）。
- 公開用の署名の鍵を新しく作る
  - Android は、同じ鍵で署名した APK でないと、上書きで更新できない。鍵を無くすと、使っている人はアンインストールして入れ直す（データが消える）しかなくなるので、自動アップデートの鍵と同じく、手元（リポジトリの外、名前に `.sec` を付ける）と、ユーザーが別の場所にバックアップする。
  - GitHub のリポジトリのシークレットに登録し、GitHub Actions で署名する。
- GitHub Actions に Android のビルドを足す
  - 版のタグを押すと、Windows と並んで Android の APK もビルドし、同じ Release の下書きに付ける（`cyanomelody_1.3.0_android-arm64.apk` など）。
- 入れ方を README に書く
  - スマホで Release のページから APK をダウンロードし、「この提供元のアプリを許可」してから入れる。Play プロテクトの警告が出たときの進め方。
  - スマホへの直接コピー（Windows の「スマホへコピー」と、Android の取り込み）の使い方。
- 自動アップデート（ユーザーの回答：新しい版の知らせを付け、できれば Windows と同じく自動アップデートにする）
  - アプリを開いたときに、GitHub の最新の Release の版を見る。新しければ、Windows と同じく「はい／いいえ／このバージョンをスキップ」のダイアログを出す。
  - 「はい」：アプリの中で APK をダウンロードし、Android のインストールの画面を出す。Android では、アプリが黙って自分を入れ替えることはできない（Google Play を使わないため）ので、最後の「更新」はユーザーが押す。初めてのときだけ、cyanomelody に「この提供元のアプリを許可」する画面も出る。上書きで更新するので、データは残る。
  - 入れる APK が本物かは、Android が署名の鍵で確かめる（違う鍵の APK は、上書きで入れられない）。
  - 試作で、アプリの中からインストールの画面を出せるか（権限 REQUEST_INSTALL_PACKAGES と、ダウンロードしたファイルの渡し方）を確かめる。できなければ、Release のページを開く形に戻す。

## やらないこと
- Google Play での配布。
- 32ビットの ARM・x86 の端末向け。
- ユーザーの確認なしでの更新（Android の決まりでできない）。

## 決めたこと（ユーザーの回答）
- 新しい版の知らせを付け、できれば Windows と同じく自動アップデートにする（上のとおり）。
- 公開用の署名の鍵のバックアップは、自動アップデートの鍵と同じ場所。
