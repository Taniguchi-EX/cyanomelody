# 仮決め事項の確認

## 概要

開発者が席を外している間に、開発者の決定が必要な点を仮決めして作業を進めた。その一覧で、あとでまとめて確認してもらう。確認が済んだ項目は、決定に合わせて仕様と実装を直し、このファイルに結果を書く。

## 仮決めした項目

### 技術選定（2026-10-27）

1. 画面のフレームワーク：React ＋ TypeScript ＋ Vite
   - 理由：利用者の多さと情報の多さ。開発PCに React のプロジェクト（`Documents/ReactProject`）があり、使い慣れていると見込んだ
   - ほかの案：Svelte（軽い）、素の TypeScript
2. プレイリストと設定の保存先：マイドライブ直下にアプリが `cyanomelody` フォルダを作り、JSON で保存する
   - 理由：開発者からも見えて、手で確認や退避ができる。`drive.file` の権限で読み書きできる
   - ほかの案：アプリ専用の見えない領域（appDataFolder）。誤って消す心配はないが、中身を手で見られない
3. デスクトップのリフレッシュトークンの保存先：OS の資格情報の保管庫（Windows の資格情報マネージャー、Ubuntu の Secret Service）
   - ほかの案：アプリのデータ領域のファイル（手軽だが、ほかのアプリから読める）
4. Android のログイン：Google Identity Services の AuthorizationClient を Kotlin から呼ぶ
   - 実機での確認は後でまとめて行う
5. 曲のキャッシュの最大容量の既定値：2GB
6. アプリの ID：`dev.cyanomelody.app`
   - 本番用の Android の署名鍵を新しく作り、この ID とその鍵で Android 用の OAuth クライアントを作り直す必要がある（開発者の作業）
7. 本番用の Android の署名鍵の保管：リポジトリの `secrets/`（Git の管理外）に置き、開発者が別の場所にバックアップする
8. MP3 のシークの改善（ビットレートから位置を見積もる）を MVP に含める
   - 理由：本物の Google Drive では、改善しないとシークに数秒〜十数秒かかるため
9. Google Cloud の公開ステータス：「テスト中」のまま進める
   - 「テスト中」では、ログインが7日で切れる見込み。「本番環境」に切り替えるには、ブランディングの設定を済ませて「アプリを公開」を押す必要があり、外部に関わる操作のため、開発者の判断を待つ
   - 2026-11-04 以降に、7日で切れるかを確かめる

### 再生エンジン（2026-10-27）

10. 「前の曲」の動き：再生位置が 3 秒より後なら今の曲の頭に戻り、3 秒以内なら前の曲に移る
    - 理由：多くの音楽再生アプリと同じ動き
    - ほかの案：常に前の曲に移る
11. 一時停止の間は、出力先（スピーカーへの出力）を閉じる
    - 理由：Android で電池を使わないため。再開のときに一瞬の遅れが出る

### プレイリストと設定の同期（2026-10-27）

12. プレイリストを削除したときは、Drive のゴミ箱に移す（完全には消さない）
    - 理由：誤って消しても、Drive のゴミ箱から戻せる。Drive のゴミ箱は 30 日で自動的に空になる
    - ほかの案：すぐに完全に消す

### 画面（2026-10-27）

13. 画面の構成：上に「プレイリスト」と「設定」のタブ、下に常に再生バー。曲の追加は、プレイリストの画面から「曲を追加」で開く
14. Android の「この端末のフォルダ」は、フォルダを選ぶ画面ではなく、パスを入力する（例：`/storage/emulated/0/Music`）
    - 理由：Android のフォルダを選ぶ画面は、Rust から読めない形式（`content://`）を返すため。試作では、音楽ファイルを読む権限があればパスで読めることを確かめた
15. Drive の指定フォルダは、自動操作の確認で `music/cyanomelody_test` に設定した。本番で使うフォルダ（例：`music`）に変えてよいか確認したい

### Androidの連携（2026-10-27）

16. Kotlin と Rust のつなぎ方：計画の「Tauri のプラグイン」ではなく、試作で動いた「JNI での直接のつなぎ」にした。Kotlin のファイルは Android 向けのプロジェクト（`app/src-tauri/gen/android`）に直接置く
    - 理由：プラグインの仕組みでは、Kotlin から Rust を呼ぶ向き（通知からの操作）の扱いが難しい
    - 注意：`tauri android init` で Android 向けのプロジェクトを作り直すと消えるため、作り直さない
