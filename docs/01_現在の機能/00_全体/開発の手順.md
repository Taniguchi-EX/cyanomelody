# 開発の手順

## 構成

- `app/`：アプリ本体
  - `src/`：画面（React、TypeScript、Vite）
  - `src-tauri/`：内部処理（Rust、Tauri 2）
  - `e2e/`：画面テストのスクリプトとテストデータの作成スクリプト

## 必要なもの

- Rust（stable、MSVC）とVisual Studio Build Tools
- Node.js
- WebView2ランタイム（Windows 11には入っている）
- ffmpeg（テスト用の音源やデータを作るときだけ）

## よく使うコマンド

`app/`で実行する。

- 依存関係のインストール：`npm install`
- 開発モードで起動：`npx tauri dev`
- 実行ファイルのビルド：`npx tauri build --no-bundle`
- インストーラのビルド：`npx tauri build`
- 単体テスト：`src-tauri`で`cargo test`
  - ハッシュ値の単体テストは`src-tauri/tests/fixtures`の音源を使う。作り直すときは`src-tauri`で`bash tests/make-fixtures.sh`（ffmpegが必要）
  - 計測用のテスト（3万ファイルのスキャン、ハッシュ値の計算の速さ、絞り込みの件数の計算の速さ、プレイリストの表示・展開の速さ、エフェクトの処理の速さ）は`cargo test --release -- --ignored --nocapture`で実行する

## 実行ファイルの場所

`app/src-tauri/target/`の下にできる。`target/`はgitの管理外で、ビルドし直すと上書きされる。

- リリース版：`app/src-tauri/target/release/cyanomelody.exe`
  - `npx tauri build --no-bundle`と`npx tauri build`で作られる。画面テストはこれを使う。
  - これ1つで起動できる（WebView2ランタイムが必要）。
- 開発版：`app/src-tauri/target/debug/cyanomelody.exe`
  - `npx tauri dev`で作られる。画面を開発サーバ（Vite）から読むため、単独では起動しても画面が出ない。
- インストーラ：`npx tauri build`で作られる。名前の数字はバージョン（`src-tauri/tauri.conf.json`の`version`）。
  - `app/src-tauri/target/release/bundle/nsis/cyanomelody_0.1.0_x64-setup.exe`
  - `app/src-tauri/target/release/bundle/msi/cyanomelody_0.1.0_x64_en-US.msi`

## 環境変数

- `CYANOMELODY_DATA_DIR`：データ（SQLite）の置き場所を変える。テストで普段のデータと分けるときに使う。

## 画面テスト

`app/e2e/`にPlaywrightのスクリプトがある。起動したアプリのWebView2にリモートデバッグでつないで操作する。

- `tag-management.mjs`：音声のタグ管理
- `tag-admin.mjs`：タグ自体の管理
- `hash-features.mjs`：ハッシュ値を使った機能
- `credits.mjs`：出典とライセンスの管理
- `tag-tree.mjs`：タグの階層構造
- `bulk.mjs`：ファイルの一括操作
- `facets.mjs`：絞り込み条件のグレーアウト
- `playlists.mjs`：プレイリスト
- `effects.mjs`：エフェクト
- `helpers.mjs`：共通部分

手順
1. テストデータを作る：`bash e2e/make-testdata.sh <テストデータのフォルダ>`
2. リリースビルドを作る：`npx tauri build --no-bundle`
3. まとめて実行する：`bash e2e/run.sh <テストデータのフォルダ> <作業用フォルダ> [スクリプト名...]`
   - スクリプト名を省くと、すべて実行する。
   - テストごとに、空のデータでアプリを起動し直す（データは`<作業用フォルダ>/<スクリプト名>/appdata`）。
   - スクリーンショットと結果（`results.json`）は`<作業用フォルダ>/<スクリプト名>/`に保存する。

確認のダイアログは、Tauriのダイアログのプラグインが`window.confirm`をOSのダイアログ（非同期）に置き換えたもので、テストから操作できない。そのため`helpers.mjs`で、メッセージを記録して決めた答えを返すものに置き換える（`ui.setConfirmReply`で答えを、`ui.lastConfirm`で最後のメッセージを扱う）。画面を読み込み直すときは`ui.reload`を使う（置き換えをやり直すため）。

画面の状態（左の欄のたたみ具合など）はWebView2の保存領域（localStorage）に残り、`CYANOMELODY_DATA_DIR`を変えても消えない。そのため、画面テストは起動のたびにlocalStorageを消してから始める（`helpers.mjs`）。

テストはテストデータのファイルを一時的に移動・名前変更する。途中で止めた場合は、`formats/`のファイルがそろっているか確かめる（`make-testdata.sh`で作り直せる）。
