# アップデート

新しい版を GitHub の Releases で公開すると、配布済みのアプリが起動したときにそれを見つけ、確かめてからアップデートする。

## 新しい版を探す
- 起動したときに1回、GitHub の最新の Release にある更新の情報（`latest.json`）を読み、今の版より新しい版があるか調べる（Tauri の updater プラグイン）。
- 調べられなかったとき（オフラインなど）は、何も出さない。
- 開発用のビルド（画面テストで使うデバッグビルド）では調べない。ただし環境変数 CYANOMELODY_FAKE_UPDATE に版があれば、その版が見つかったことにする（画面テストでダイアログを出すため。run.sh が update.mjs のときだけ 9.9.9 を渡す）。

## 確かめるダイアログ
- 新しい版が見つかったら、アプリの中のダイアログで「新たなバージョンが公開されました。アプリをアップデートしますか？」と、その下に今の版と見つかった版を出す（「現在：1.1.2」「最新：1.1.6」の2行）。
  - 版の番号は、その版の GitHub の Release のページ（リリースノート。`https://github.com/Taniguchi-EX/cyanomelody/releases/tag/v1.1.6` など）へのリンクで、押すとブラウザで開く。
- はい：ダウンロードしてインストールし、アプリを再起動する。ダウンロードしている間は、そのことを出してボタンを押せなくする。失敗したら、ダイアログを閉じてエラーを下の行に出す。
- いいえ（Esc でも）：何もしない。次に起動したときに、また出す。
- このバージョンをスキップ：その版では、もう出さない（スキップした版は画面の設定として覚えておく）。もっと新しい版が見つかったら、また出す。

## インストール
- インストーラは、画面を出さずに進む形（passive）で動き、終わるとアプリを起動し直す。
- 更新ファイルは署名を確かめ、アプリに書いてある公開鍵と合わなければ入れない（「開発の手順」の「自動アップデートの署名の鍵」）。
