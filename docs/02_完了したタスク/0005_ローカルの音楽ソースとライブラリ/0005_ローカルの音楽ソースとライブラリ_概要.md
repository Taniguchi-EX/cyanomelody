# ローカルの音楽ソースとライブラリ

## 概要

音楽ソースの共通の窓口と、ローカルのフォルダの曲の読み込み、曲の一覧のキャッシュを作る。

詳しい仕様は `00_現在の仕様/機能仕様.md` と `00_現在の仕様/技術仕様.md`、順番は `00_現在の仕様/開発ロードマップ.md` を参照。

## 結果

中核のクレートに次のモジュールを作った（`app/crates/core/src/`）。

- `source/mod.rs`：音楽ソースの共通の窓口 `MusicSource`（曲の一覧 `list`、タグ `read_tags`、曲を開く `open`）。複数のスレッドから同時に呼べるようにした（タグの並行読み込みのため）
  - 曲を見分ける値 `key`：ローカルは指定フォルダからの相対パス（`/` 区切り）、Drive はファイル ID
  - 対応する拡張子は `mp3`、`wav`、`m4a`（大文字小文字を区別しない）
- `source/local.rs`：ローカルの音楽ソース `LocalSource`。指定フォルダとサブフォルダを探す。指定フォルダの外を指すパス（`..` など）は開かない
- `source/tags.rs`：lofty でタグ（曲名、アーティスト、アルバム）を読む。音声の長さは読まない（Drive での通信を減らすため）。ローカルと Drive で共通に使う
- `library.rs`：ライブラリ `Library`。曲の一覧とタグを SQLite に保存する
  - 手動更新 `refresh`：新しい曲と、大きさや更新日時が変わった曲だけ、タグを並行して読む（既定 8 件）。前回タグを読めなかった曲も読み直す。見つからなくなった曲には `missing` の印を付け、戻ってきたら外す。一覧を取れないとき（フォルダがない、通信できない）は、ライブラリを変えずにエラーを返す
  - タグに曲名がなければ、ファイル名（拡張子を除く）を曲名にする
  - フォルダをたどる画面のための `browse`（直下のサブフォルダと曲）、フォルダ単位で追加するための `songs_under`（サブフォルダの中も含む）
- `device.rs`：端末 ID。初回に 32 桁の 16 進数を発行してデータ領域に保存し、以降はそれを使う。ファイルが壊れていれば発行し直す
- ライブラリ：lofty 0.25、rusqlite 0.41（SQLite を同梱してビルドする `bundled`）

### レビュー

- 差分を読み直し、仕様（指定フォルダとサブフォルダ、手動更新、見つからない曲の印、タグがないときのファイル名、端末 ID）との対応を確かめた
- 書いている途中で、手動更新の「変わらなかった曲」を探す処理が二重ループで、曲数が多いと遅くなる点に気づき、集合での照合に直した。フォルダの一覧の重複の除き方も簡単にした

### テスト

- 単体テストは中核全体で 36 件、すべて通った。追加は、ローカルの音楽ソース 4 件（日本語の名前とサブフォルダ、タグあり・なし、指定フォルダの外を開かない、フォルダがない）、ライブラリ 5 件（追加、消えた曲の印と復帰、一覧を取れないときに変えない、フォルダをたどる、進み具合の通知と開き直し）、端末 ID 2 件、共通の窓口 2 件
- Docker で Android 向けにビルドし、SQLite（C のコード）を含めて NDK でコンパイルできることを確かめた
