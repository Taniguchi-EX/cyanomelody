# 技術スタック

試作の結果をもとに決めた、本番のアプリで使う技術。「（仮決め）」が付いたものは、開発者の確認待ちの仮の決定で、`02_完了したタスク/0012_仮決め事項の確認/` で確認した（すべて了承済み）。

## 構成

- 1つのアプリの中で、画面、アプリの中核、音楽ソース、保存、再生とOS連携の層に分ける。サーバは立てない（`アーキテクチャ方針.md`）
- Tauri 2（Rustの中核 ＋ Web技術の画面）。Windows、Ubuntu、Androidを1つのコードベースで作る
- Androidだけに必要な処理（バックグラウンド再生、通知とロック画面の操作、音声フォーカス、権限の要求、Googleのログイン）は、KotlinのTauriプラグインとして作る

## 言語とフレームワーク

- Rust：2024エディション、最新の安定版
- 画面：TypeScript ＋ React ＋ Vite（仮決め）
- Android：Kotlin（Tauriプラグイン）。追加のライブラリなしで、Android標準のMediaSession、フォアグラウンドサービス、AudioFocusRequestを使う
- Androidの対応バージョン：最低、対象ともにAPI 37（Android 17）。NDK 30

## 主なライブラリ

- 音声のデコード：Symphonia 0.5（`mp3`、`aac`、`isomp4`、`wav`、`pcm` の機能を有効にする）
- 音声の出力：cpal 0.16（WindowsはWASAPI、UbuntuはALSA経由でPipeWire、AndroidはAAudio）
- サンプルレートの変換：rubato（Windowsなど、出力先と曲のサンプルレートが違う場合）
- タグの読み込み：lofty 0.22
- HTTP：ureq 2（接続を使い回す共有のエージェントを使う）
- 端末に持つデータ：SQLite（rusqlite、`bundled`）。曲の一覧とタグ情報のキャッシュ、曲のキャッシュの索引を入れる
- JSON：serde、serde_json

## Google Drive

- 権限：`drive.readonly`（指定フォルダの曲を読む）と `drive.file`（アプリが作るプレイリストと設定のファイルを読み書きする）
- 曲の識別：DriveのファイルID
- 曲の読み込み：`files.get` の `alt=media` をRange指定で部分取得する。1回の通信に約1秒かかるため、続けて読むときはまとめて取得する大きさを倍々に増やす（最大4MB）
- MP3のシーク：ビットレートや可変ビットレートの目次（Xingヘッダ）から位置を見積もり、そこから読み始める（Symphoniaの標準のシークは先頭からたどるため遅い）
- タグの読み込み：手動更新の際に、8件ずつ並行して読み、結果を端末のSQLiteに保存する
- プレイリストと設定の保存先：開発者のマイドライブ直下に、アプリが `cyanomelody` フォルダを作り、その中にJSONで保存する（仮決め）
  - `settings.json`：Driveの指定フォルダ、端末ごとのローカルの指定フォルダ（端末IDごとに分ける）
  - `playlists/<プレイリストID>.json`：プレイリスト1つにつき1ファイル（名前、お気に入りかどうか、曲の並び）
- ログイン
  - Windows、Ubuntu：ブラウザで同意し、ループバック（`127.0.0.1`）で認可コードを受け取る。PKCE付き。リフレッシュトークンはOSの資格情報の保管庫に保存する（keyringクレート）（仮決め）
  - Android：Googleのログインの仕組み（Google Identity ServicesのAuthorizationClient）をKotlinから呼び、アクセストークンをRustに渡す（仮決め。実機での確認は後でまとめて行う）

## 端末に持つデータ

- 端末ID：初回起動時にランダムなIDを発行し、アプリのデータ領域に保存する
- 曲のキャッシュ：アプリのキャッシュ領域に保存する。最大容量の既定値は2GB（仮決め）。最後に再生されてから最も時間がたった曲から削除する

## 開発とビルド

- Windows版：開発PCで直接ビルドする
- Android版、Ubuntu版：Dockerのビルド環境（`prototypes/android_env/` を元にする）でビルドする
- Androidの署名鍵：本番用の鍵を新しく作り、`secrets/` に保存する。なくすと上書きインストールができなくなるため、開発者がバックアップする（仮決め）
- アプリのID：`dev.cyanomelody.app`（仮決め）。Android用のOAuthクライアントは、このIDと本番用の署名鍵で作り直す必要がある
- テスト：中核はRustの単体テスト（`cargo test`）、静的な検査（`cargo clippy`）、画面は型の検査（`tsc`）

## 未確認のまま実装で確かめる項目

技術選定の判断には影響しないため、実装の各タスクで確かめる。

- Ubuntuでの音の出力と画面の表示（B-1、F-1、G-2）
- 曲のキャッシュ（E-1）
- Androidでのログイン（C-1）、ログインが7日で切れないか（C-2）
- 一時的に音声フォーカスを失ったときの動き（A-6）
- WindowsとUbuntuでの日本語のファイル名（D-2）
