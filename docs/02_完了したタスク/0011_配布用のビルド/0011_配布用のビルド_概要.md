## 結果

| 対象 | できたもの | 大きさ |
|---|---|---|
| Windows | NSIS のインストーラ `cyanomelody_0.1.0_x64-setup.exe`、MSI `cyanomelody_0.1.0_x64_en-US.msi` | 3.8MB、5.1MB |
| Ubuntu | `cyanomelody_0.1.0_amd64.deb`（依存：`libasound2t64 \| libasound2`、`libwebkit2gtk-4.1-0`、`libgtk-3-0`） | 6.2MB |
| Android | `cyanomelody-0.1.0-release.apk`（本番用の鍵で署名、arm64） | 13MB |

- `app/scripts/build-release.sh`：Ubuntu と Android のリリース版を Docker でビルドする。手順は `app/README.md` の「配布用のビルド」
- Android の本番用の署名鍵を作った：`secrets/android_release.sec.jks`（RSA 4096、有効期限 100 年）、パスワードは `secrets/android_signing.sec.properties`。どちらも Git の管理外。SHA-1 は `25:55:AB:54:B3:23:6C:31:16:6A:63:1B:04:BF:18:1A:CB:93:CC:BB`
- Android のビルドの設定：環境変数 `CYANOMELODY_ANDROID_SIGNING` で署名の設定ファイルを渡したときだけ、リリース版を署名する。リリース版はコードを縮める処理（R8）が有効なため、Rust から名前で呼ぶ `RustBridge` を残す設定を `proguard-rules.pro` に足した
- Ubuntu のパッケージの依存に、音の出力で使う ALSA を足した

### レビュー

- 署名鍵と OAuth クライアントがリポジトリに入らないこと（`secrets/` が Git の管理外）を確かめた
- Ubuntu で、再生バーの記号（⏮ ⏭）がフォントになく四角で表示された。記号を SVG のアイコンに置き換えた（`app/src/components/Icon.tsx`）
- 残した課題
  - リリース版の Android は署名鍵が違うため、Google Cloud に、`dev.cyanomelody.app` とリリース版の SHA-1 の Android の OAuth クライアントも必要（デバッグ版とは別）
  - 署名鍵は、開発者が別の場所にもバックアップする必要がある

### テスト

- 3 つとも、ビルドが成功した
- Android のリリース版の署名を `apksigner` で確かめ、作った鍵の SHA-1 と一致した
- Ubuntu のパッケージを、Docker の Ubuntu 24.04 に入れてインストールでき、仮想の画面（Xvfb）でアプリが起動して画面が表示された（日本語、アイコンとも正しく表示）。仮想の画面では、WebKitGTK の描画の方式を切り替える設定（`WEBKIT_DISABLE_DMABUF_RENDERER=1`）と D-Bus のセッションが必要だった。実機の Ubuntu での起動、音の出力、資格情報の保存は、`実機での総合テスト` で確かめる
- Windows のインストーラでのインストールは、`実機での総合テスト` で確かめる
