# プレイリストと設定の同期

## 概要

プレイリストと設定を Google Drive 上の JSON に保存し、全端末で共有する。

詳しい仕様は `00_現在の仕様/機能仕様.md` と `00_現在の仕様/技術仕様.md`、順番は `00_現在の仕様/開発ロードマップ.md` を参照。

## 結果

- `app/crates/core/src/drive/client.rs` に書き込みの操作を足した：フォルダの作成、ファイルの作成（multipart）、中身の置き換え、中身の取得、ゴミ箱への移動、名前でのファイルの検索。呼び出しは `send` にまとめ、401 でのやり直しを共通にした
- `app/crates/core/src/sync.rs`
  - データの形：`Playlist`（ID、名前、お気に入り、曲の並び、保存日時）、`PlaylistItem`（ソース、曲を見分ける値、追加したときの曲名とアーティスト、ローカルの曲なら追加した端末の ID）、`Settings`（Drive の指定フォルダ、端末 ID ごとのローカルの指定フォルダ）。JSON の形式の版 `version` を持ち、項目が欠けた古い形式も、知らない項目がある新しい形式も読める
  - 置き場所：マイドライブ直下の `cyanomelody/`（`settings.json`）と `cyanomelody/playlists/<プレイリストID>.json`。フォルダがなければ作る
  - `SyncStore`：一覧（8 件ずつ並行して読み、お気に入りを先、あとは名前の順）、取得、作成、編集（最新を読み直してから当てて保存。同時の編集は後勝ち）、削除（Drive のゴミ箱に移す）、設定の読み書き（同じく読み直してから保存）
  - 通信できないときは `SyncError::Offline` を返す。画面はこれを受けて、オフラインの間は編集できないようにする
  - グレーアウトの判定 `PlaylistItem::is_available`：ローカルの曲は追加した端末で、前回の手動更新で見つかったもの。Drive の曲は前回の手動更新で見つかったもの
- `examples/sync.rs`：本物の Drive で確かめる確認用のプログラム

### レビュー

- 差分を読み直し、仕様（端末間の同期、読み直してからの編集、後勝ち、お気に入りの共有、端末ごとのローカルの指定フォルダ、ほかの端末のローカルの曲のグレーアウト）との対応を確かめた
- プレイリストの削除を「Drive のゴミ箱に移す」にした（誤って消しても Drive 側で戻せる）。仕様にないため、仮決めとして `仮決め事項の確認` に追加した
- 本物の Drive では、1 回の操作に 1〜4 秒かかる。画面では保存中であることを表示する（`画面` のタスク）

### テスト

- 単体テストは中核全体で 68 件、すべて通った。追加は、Drive への書き込み 1 件、プレイリストと設定 7 件（フォルダの作成とお気に入り順の一覧、端末間の共有と読み直しと後勝ち、ゴミ箱への移動、設定の共有と端末ごとの値、古い形式と新しい形式の読み込み、通信できないとき、グレーアウトの判定）
- 本物の Drive で、確認用のプログラムを実行した。作成 4.3 秒（初回のフォルダの作成を含む）、編集 3.2 秒、別の接続からの読み込み 2.0 秒、一覧 1.0 秒。最後にテスト用のプレイリストをゴミ箱に移した
  - 開発者のマイドライブに `cyanomelody/playlists/` フォルダができた（アプリが使う場所なので残した）。テスト用のプレイリストは Drive のゴミ箱にある
- Docker で Android 向けにビルドできることを確かめた
