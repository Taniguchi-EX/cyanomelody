## 結果

アプリ（`app/src-tauri/src/`）:

- `core.rs`：中核の部品をまとめた `AppCore`。端末 ID、ライブラリ、曲のキャッシュ、再生エンジン、プレイリストと設定の同期を持つ
  - 再生エンジンとの間では、曲を見分ける値の頭に `drive:` か `local:` を付け、どちらの音楽ソースから開くかを見分ける
  - 設定（Drive で共有）を読んだら、Drive とローカルの音楽ソースを差し替える。ローカルは、この端末の ID の指定フォルダを使う
  - 端末だけで持つ設定（キャッシュの最大容量、アプリ内の音量）は、データ領域の `local.json` に保存する
  - 画面に返すエラーには種類（`offline`、`login`、`not_found`、`error`）を付ける
- `lib.rs`：画面から呼ぶコマンド 27 個と、画面に知らせるイベント（`player`：曲の切り替え・状態の変化・再生できない曲・最後まで再生、`library-progress`：手動更新の進み具合）。通信を伴うコマンドは別のスレッドで動かし、画面を止めない
- フォルダを選ぶダイアログのプラグイン（`tauri-plugin-dialog`）を追加した

画面（`app/src/`、React ＋ TypeScript）:

- 上に「プレイリスト」と「設定」のタブ、下に常に再生バーを出す
- プレイリストの一覧：お気に入りが上（★）。作成、Drive からの読み直し
- プレイリストの中身：最初から再生、ここから再生、曲の追加、上下の並べ替え、プレイリストから外す、名前の変更、お気に入り、削除（確認してから Drive のゴミ箱に移す）。この端末で再生できない曲はグレーアウトし、ローカルの曲には印を付ける
- 曲の追加：Google Drive と「この端末」を切り替え、指定フォルダをたどって、曲ごと、またはフォルダごと（サブフォルダの中も含む）追加する
- 再生バー：曲名とアーティスト（押すとそのプレイリストを開く）、シークバー、シャッフル、前の曲、再生・一時停止、次の曲、リピート、音量（Windows と Ubuntu だけ。Android は OS の音量）
- 設定：ログインとログアウト、Drive の指定フォルダ（Drive のフォルダをたどって選ぶ）、この端末のフォルダ（Windows と Ubuntu はフォルダを選ぶ画面、Android はパスを入力）、手動更新とその進み具合と結果、キャッシュの使用量と最大容量
- オフラインになったら上に知らせを出し、プレイリストの編集を押せなくする。保存中は上に「〜中…」を出し、編集のボタンを押せなくする
- 画面の自動操作のスクリプト `app/e2e/windows.mjs`（`npm run e2e`）

### レビュー

- 差分を読み直し、機能仕様の画面に関わる項目（お気に入りの優先表示、フォルダ単位・ファイル単位の追加、グレーアウト、オフライン時に編集できない、Android は OS の音量）との対応を確かめた
- 状態を参照する箇所に `unsafe` を使っていたのを、`Arc` で共有する形に直した
- 画面の自動操作で見つかった点を直した
  - Drive のフォルダを選ぶ画面で、サブフォルダを読み込む前に「このフォルダにする」を押せてしまい、親のフォルダが保存された。読み込み中は押せないようにした
  - プレイリストを開いた状態で「プレイリスト」のタブを押しても一覧に戻らなかった。一覧に戻るようにした
- 残した課題
  - 開発者の Drive の `music`（5,696 曲）を指定フォルダにすると、初回の手動更新でタグを読むのに約 30 分かかる見込み（8 件ずつ並行、1 曲 1〜6 秒）。2 回目からは変わった曲だけを読む。必要なら並行の数を増やす
  - 一覧から戻る直前に保存中だった変更は、一覧の曲数にすぐには反映されないことがある（保存が終われば、次の読み直しで反映される）

### テスト

- 型の検査（`tsc`）と静的な検査が通った
- Windows で、画面の自動操作（WebView2 のリモートデバッグ経由で Playwright から操作）を行い、すべての段階が通った。画面のエラーはなかった
  - ログイン状態の表示、Drive の指定フォルダの選択（`music/cyanomelody_test`）、手動更新（3 曲、約 5 秒）、プレイリストの作成と曲の追加、再生（最初の音まで約 2 秒）・次の曲・一時停止（止めている間は位置が進まない）、お気に入り（一覧で上に★付き）、名前の変更、並べ替え、曲の削除（3 曲 → 2 曲）、プレイリストの削除
  - ログインは、ブラウザでの同意の代わりに、試作で得たリフレッシュトークンを資格情報マネージャーに入れて行った。アプリの「ブラウザでログイン」の流れそのものは、実機での総合テストで確かめる
  - この端末のフォルダを選ぶ画面（OS のダイアログ）は自動操作できないため、実機での総合テストで確かめる
- Docker で Android 向けにビルドできることを確かめた
